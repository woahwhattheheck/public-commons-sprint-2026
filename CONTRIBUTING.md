# Contributing to Public Commons Sprint Assets

Thank you for helping maintain and extend these public goods.

## Principles
- Keep assets factual, sourced from public/open materials, and free of personal data.
- Prefer permissive licenses (MIT, Apache-2.0, CC-BY-4.0, CC0).
- Mark any domain-specific or high-stakes content with "Needs expert review".
- Include verification notes and known limitations.
- Write for underserved users: plain language, offline-friendly where possible, accessibility considered.

## How to contribute
1. Open an issue describing the improvement or new asset.
2. Fork, make changes on a branch, open a pull request.
3. For new prompts/templates: include a short test case or example usage.
4. For code: include basic tests or runnable examples if feasible.
5. Update the relevant README and LICENSE notes.

## Priority areas post-sprint
- Translations / localization of OER and glossaries (with native-speaker review)
- Additional datasheets for public datasets
- More offline-friendly formats
- Evaluation results and community feedback incorporation
- Maintenance of existing modules

## Code of Conduct
Be respectful. Focus on the work. No harassment, spam, or off-topic political advocacy.

Questions? Open an issue.
