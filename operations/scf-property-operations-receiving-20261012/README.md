# Complete Property Operations receiving

This entry operates the existing installed Property Operations application, SDK and merchant interface, receives all original records/files and proves a cold restore with the unchanged Socrata CLI. It uses the original Applications manager and a single native workspace owner at a time.

## Inputs and original identities

Run Node 24 or later on Linux with Python 3 and GNU tar/flock available. Use a complete maintained READY runtime containing the `property-operations-interfaces` contribution. The receiving program must be run from that runtime's `package/source` tree.

The input JSON names:

- The original runtime installation and its existing or new Applications workspace.
- The existing Socrata/Property workspace, its original `createdAt` and optionally its exact initial `workspace.json` hash.
- The complete retained HPD edition, its reviewed source-column mapping, exact expected row count and operator note.
- The existing paid customer ZIP with complete byte count, SHA-256, customer, acquisition and snapshot identities.
- One private receiving output directory, outside the source runtime and original native workspace.
- Optionally the existing Playwright module and Chromium executable for the original browser receiving.

Use `receiving-input.example.json` as a field template. Its illustrative paths and column names must be replaced with the actual selected values before execution.

~~~sh
node /absolute/runtime/package/source/operations/scf-property-operations-receiving-20261012/run-receiving.mjs \
  /absolute/private/property-receiving-input.json
~~~

The entry keeps its original `receiving-operation.json` and Linux receiving lease outside the native workspace. That journal contains exact private startup and request information; keep it private and retain it alongside the operation if execution is interrupted.

## Executed workflow

The entry verifies the complete original installed manifest and source registration. It retains the original completed customer ZIP, saves one reviewed application, allows the original manager to adopt the same source, and starts the original workspace.

The attached workflow saves the HPD baseline from the already retained full capture and imports the original paid delivery ZIP as source evidence through its declared host alias. It prepares and saves the exact native request envelopes before invoking them. Neither action requests data from a property vendor or buys anything.

It reads every native property collection to its terminal page, compares full SDK and MCP record results, receives every retained property file, and reads the full selected dataset query through its native cursors. It then creates one original package export, binds the complete merchant receiving manifest, receives every declared file and verifies the files offline after closing the merchant listener and borrower.

The manager performs normal Stop. The entry records the original result, removed connection announcement, process/listener closure and a successful original CLI lease open/close. It starts the same saved application again, repeats the attached read-only receiving against the original IDs, and stops it normally a second time. Full original workspace JSON is compared across both managed lifetimes.

The complete saved portable package is restored with the original CLI into the receiver's own cold directory. Every member is compared against its declared byte/hash identity. A cold re-export is verified against the original logical workspace and all complete source bytes.

When browser inputs are selected, each successful application lifetime also opens the original UI, receives all eight workspace sections and four Property workflow views, downloads the largest existing native export member through its normal browser button, and checks desktop 1440×1000 and mobile 390×844 views. The selected Playwright module may expose Chromium through an ES module namespace or its CommonJS default export. Screenshots stay under the operation's private `private/browser-inspection/` directory for local inspection. `Browser_Receiving.json` and the complete downloaded native member remain in the customer directory. It allows only native reads, and closes both browser context and process.

## Continuation and uncertain outcomes

Resume by running the same command with the same input and output directory. Keep all original IDs and journal files.

- Prepared Property writes retain the exact action, key, workspace, revision and input digest. A saved `DONE` operation is reused. An issued or changed operation remains explicit.
- The source package export has no native request key. The entry retains the pre-export inventory and resolves one newly saved export after a lost response. An ambiguous or missing original outcome remains pending instead of starting another export.
- Managed Start/Stop/recovery uses the original Applications request ID and its native operation history. A ended or interrupted attempt is preserved; a new listener is allowed only after the original closure is established.
- Merchant receiving retains its original endpoint, complete manifest, native export and per-file checkpoints.
- An interrupted import is resumed only while the cold workspace remains empty. A populated receiver must equal the selected original logical workspace.
- Completed product output is frozen before archive publication. Packaging continuation reads only the frozen customer roster and original staged archive identity.

Do not remove a native workspace lock, change a source selection to make a stale request pass, or infer a missing provider response from a local process exit. The original engines expose the relevant recovery states.

## Complete output

`customer/Property_Operations_Operation.json` is the complete result report. The customer directory includes the original paid ZIP and identity, all native Property record/file receiving, full query pages, source and merchant manifests, complete package exports, original application histories and closure receipts, the exact cold receiver and re-export, operating instructions, the actual browser receiving reports and complete native browser downloads. Private inspection screenshots are excluded.

`customer/MANIFEST.json` declares every final customer member. `Property_Operations_Complete_Delivery.tar.gz` contains that complete directory. Keep the private receiving journal separately for exact operation continuation.

The report records actual execution. A prepared source carrier or available browser executable alone is not a completed receiving run. The entry makes no property-vendor request, source recapture or new customer payment.
