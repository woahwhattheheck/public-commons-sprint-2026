Original describeRuntimeLock, adopt-existing, and fresh-process source/import inspection validate that installed result.

The receiving pass opens its six catalogue tabs at 1280 and 390 pixels, closes the host normally, and opens the same saved identities in a fresh process. It does not contact a catalogue provider or acquire a customer source. Browser screenshots are not package deliverables.

The final ZIP contains the complete original source TGZ, original source manifest, exact runtime inputs and original locks, the two approved customer documents, operating instructions and actual installed-app result. The existing full upload workflow runs before the temporary owner exits. Unknown or failed uploads are retained and are not automatically retried.

## Remaining source in the admitted context

Optional configuration `source_feed` selects the unchanged, published `source-feed.py` by its exact path and Git blob. This mode requires the one original launch to own its allocated PTY. After the native callback acquires that launch, the caller retains the terminal device, session, native process identity, and foreground process group, then performs the unchanged foreground handoff. The native command keeps its original `stdin=DEVNULL` contract.

Only after admission does the driver inventory the already-persistent incoming bytes read-only and derive the missing Git blobs from the exact selected metadata. It opens and verifies the bound terminal once, then invokes the same source-feed implementation on that descriptor. Send only the requested missing source batches, wait for each actual acknowledgement, and finish that feed once. Its complete manifest is retained in the original result. The driver adds that temporary incoming directory to the original receiver's repeated `--incoming` arguments and continues build, installation, app receiving, and durable file saving within the same context.

A changed parent, process start identity, session, terminal device, or foreground group fails into this operation's retained result. It does not select a replacement terminal or create a second native job. The terminal mode handling remains the original source-feed implementation's responsibility. An interrupted source feed preserves every original persistent input and the remote source bytes; no source refetch or customer acquisition is implied.

A complete current incoming set can supply the original Git receiver without a historical archive or Git donor. Configure `git_donors: []` and omit `archive_donor` in that case. If an original verified archive is explicitly selected, its unchanged optional receiver arguments remain available.

## Original installed leaf receiving

A leaf may select `installedDonor` instead of `cacheRoot`. The binding includes the canonical original package directory, complete per-file hashes and modes, the original installed lock path/hash/entry, and the exact name/version. The driver verifies that complete observed tree before source receiving, copies it with the same guarded receiving routine, verifies the copied inventory and original lock again, and then uses the existing bin-link, composed-lock, adopt-existing and fresh inspection APIs. The original selected registry lock is preserved separately. Receiving an installed tree does not independently verify the registry archive SRI; the result explicitly records `archiveIntegrityVerified: false` and the original installed-file provenance. This path neither reconstructs a registry archive nor changes the selected package version.

## Supplied terminal ownership

The caller accepts the original Linux PTY slave in either its controlling or explicitly noncontrolling mode. The latter requires `isatty` and the actual `tcgetpgrp` ENOTTY outcome; it does not create a session or acquire a controlling terminal. Both modes require `/dev/pts/<number>`, exact fd-to-path device/inode identity, and the same accepted supervisor/session/group on handoff. The admitted reader opens that slave once with O_NOCTTY/O_NOFOLLOW, verifies the same identity and control mode, and gives that descriptor to the unchanged source receiver. A PTY master or multiplexer path is never reopened. Only the controlling mode uses the existing guarded foreground-group transfer.
