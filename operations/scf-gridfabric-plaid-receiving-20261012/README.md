# Complete GridFabric Plaid native receiving

This entrypoint operates the original GridFabric domain through its actual Node SQLite store, authenticated HTTP console, CLI and portable archive. It receives the complete retained 31-day portfolio, preserves every input and outcome, closes the original owner, restores a distinct receiving directory, and compares all original logical records and file identities before producing the complete customer bundle.

Operation: **GRIDFABRIC-PLAID-OPERATIONS-20261012-1FB3**.

The input is explicitly **TokenJunkieLabs-authored functional data**. Public Plaid examples and the historical HTTP 200 / status OK / code 452 response remain separately identified source evidence. The functional operation makes no external management or device requests. It does not claim a vendor deployment, provider acceptance or a completed selected Starforge installation.

## Source and runtime

Use the complete repository-shaped source declaration in [source-manifest.json](source-manifest.json). The declaration binds the application, original lease helper, full functional generator, receiving code, configuration, contracts, documentation and product registration by exact bytes, SHA-256 and Git blob. Relative paths must remain intact.

The direct native application needs:

| Requirement | Purpose |
| --- | --- |
| Linux and Node 22.13 or newer with `node:sqlite` | Original SQLite transactions, HTTP owner and CLI |
| Original Linux `flock` | One workspace owner and a separate single receiving journal |
| GNU `mv` with `--no-clobber --no-target-directory` | Publish a verified portable restore or customer archive without replacing another destination |
| GNU `tar` | Package and independently list the complete customer bundle |
| Adequate private disk and memory for the full inputs, native DB, full original/cold output copies and archives | Preserve complete rows and files through cold receiving |

The application and native receiver use Node built-ins and the original lease helper. They need no npm package, external DNS or provider credentials for this functional portfolio. Browser automation uses only caller-selected, already available Playwright and Chromium.

The largest original input is 17,662,029 bytes. The largest expected report is 5,329,484 bytes. The server accepts complete source bodies up to 256 MiB by default; portable receiving supports 4 GiB of decoded records. File chunks and verification use bounded reads. The original domain may load a whole source or report while calculating it, so a worker still needs sufficient memory for the actual portfolio.

```json

  "sourceRoot": "/retained/gridfabric/source",
  "outputDirectory": "/private/gridfabric-native-receiving",
  "sourceCommit": "FULL_JOINED_SOURCE_COMMIT"

```

Run:


The default Node executable is the one running this command. An optional absolute `nodeExecutable` can select the host's existing compatible Node. The runner validates all declared source before importing the original owner.

That generator verifies and reuses identical existing files. The runner then verifies every generated member against the committed [functional input manifest](functional-input-manifest.json), including the full receiving envelope. It copies all 42 exact inputs into customer custody.

If the host already has the complete retained input portfolio, set `inputFile` to its absolute `gridfabric-functional-input.json`. All referenced files must be present beneath its retained directory. The receiving envelope must retain its original 89,750 bytes and SHA-256 `697b0be311d2b8a0f0d191fc46b4a81b364dc0f53dba1526bc37c5cf723a04e6`; each member is also independently checked. ## Add actual browser receiving

Add the following object only when the existing host can run Chromium:

```json
{
  "browser": {
    "playwrightPackage": "/host/node_modules/playwright/index.mjs",
    "executablePath": "/host/chromium/chrome-headless-shell"
  }
}
```

The browser uses the original private connection. It verifies every navigation section, original record details, first and final source/report row pages, and a complete original file download. It saves desktop and mobile screenshots, full browser observations and the actual download identity.

The browser phase is read-only. Its route guard refuses mutation requests, and final assertions require the original workspace ID and revision to remain unchanged. The original browser closes before the first owner closes. A new browser is then used for the distinct cold receiver and also closes completely. If browser configuration is absent, the report explicitly records `NOT_REQUESTED`; the full native HTTP/CLI operation still runs.

## Complete operating sequence

The full original input has 51 steps, 53 exact assertions and seven complete expected-output comparisons:

1. Initialize or reopen the same original CLI workspace under its existing lease, and start its authenticated loopback HTTP listener.
2. Import the 71,424-row mixed original energy, power and status source, the 96-row sparse correction, and separately retained schema, registration, event and public response evidence. Original raw files and every normalized row remain addressable.
3. Review instance configuration and explicit JSON-pointer event/target bindings. Save and activate source mappings, prepare full baseline reports, then activate the explicitly selected corrected source precedence.
4. Serve the original registration, report query, event, interval, end, distribution and empty-heartbeat callback bytes through the actual original callback routes. Intentional duplicate deliveries remain original additional delivery records with the same saved callback response.
5. Check every declared assertion and compare all seven complete expected files structurally or byte-for-byte according to their declared representation. Each full power, energy and status report contains 23,808 outputs.
6. Page every original public collection and the original host file/dispatch collections to the exact declared end. Download every retained original file with its full length and SHA-256, and retain all rows and outcomes.
7. Export the original complete portable workspace with a saved request UUID. Run optional actual browser receiving. Stop the original owner, await its closed output streams, verify its private connection was removed, and prove lease release through the unchanged original CLI.
8. Inspect and restore the same portable archive into a distinct private directory. Open that receiver, page and download its entire contents, and compare all original logical records and file identities with the original workspace. Run the optional cold browser.
9. Close the cold owner, export again through the CLI, and compare original record hashes and the full immutable file declarations. Preserve the same logical workspace ID and revision.
10. Freeze the successful product report and its full member roster. Build, sync, verify, and publish the complete customer archive. Only then record terminal completion.

The published original domain calculation produced 71,520 source rows and 71,528 report rows. Those earlier source calculations are separate evidence. The native receiving report records the rows, revisions, callbacks, intents, closure receipts and comparisons actually observed on its own original Node/SQLite execution.

Management and device dispatch entrypoints are intentionally not invoked by this functional envelope. Callback handling may queue native device intents, but the final host dispatch collection must remain empty. Public historical response evidence stays an import, without a synthetic dispatch receipt.

## Exact recovery

Keep the same source, input, output directory and private configuration when continuing:

```sh
node /retained/gridfabric/source/operations/scf-gridfabric-plaid-receiving-20261012/run-receiving.mjs \
  /private/gridfabric-receiving.json
```

The runner saves an action's original UUID, payload and expected revision before sending. After uncertainty, it first reads that native operation. Only the exact native operation-not-found response plus the unchanged original workspace/revision permits the same saved request to proceed. A changed body, different workspace or unrelated revision is a concrete stop for review.

Callbacks use the original source identity and retained callback delivery history. A resumed step looks for its one newly committed original delivery before any POST. A found delivery supplies the original saved response. Multiple new deliveries or a changed revision without a matching delivery require review. The runner never invents a callback UUID or repeats a possibly completed delivery blindly.

Every prior owner record remains in the journal. A normal stop records its actual exit, complete logs and removed connection file. An interrupted historical owner is reconciled only when the original CLI actually acquires and releases the same logical workspace lease; stale PIDs alone provide no closure proof. A retained live lease prevents a new owner.

The product outcome is frozen before customer packaging. If packaging fails, continuing uses the saved successful result. It does not repeat the source imports, callbacks, correction or cold operation. Before publication, the archive journal saves the exact complete byte length and SHA-256; an existing identical prepared archive is reused. A differing destination is preserved and rejected.

A terminal `COMPLETE` continuation verifies the frozen final report and bundle before returning. That path executes before application imports or owner creation. Native stdout/stderr buffers are received through the child's `close` event so final JSON and archive listings are complete.
