This command operates the original published PRS examples through the installed ClinicalTrials batch interface. It uses the existing Python owner, the real browser UI, the original authenticated MCP reader and the ordinary installed CLI. It writes a complete customer package and closes its owned processes.

## Existing runtime

Use Python with the original PRS `lxml` dependency, Node22 or later, the existing Linux `flock` command, and an already installed Playwright/Chromium pair. Supply the actual executable and package paths explicitly. The source/MCP closure uses Node builtins.

Run against an existing pinned checkout or complete installed package's repository-shaped `source/` directory. Keep the working/output directories on the worker's persistent private volume.

```sh
python3 operations/scf-clinicaltrials-batch-receiving-20261012/run-receiving.py \
  --source-root /path/to/pinned/repository-source \
  --out /path/to/new/private/disclosure-receiving \
  --node /path/to/node \
  --browser-executable /path/to/chrome-headless-shell \
  --playwright-package /path/to/node_modules/playwright/package.json
```

The source checkout containing this command includes the original MCP callback unchanged. Its manifest may also be supplied when the callback is invoked independently by an existing console owner.

## Actual operating sequence

1. Use the original CLI to create the private ClinicalTrials workspace.
2. Open one authenticated original Python console.
3. Receive the three XML files and four client references through the browser manifest/file forms.
4. Prepare and apply reviewed legacy-occurrence decisions, inspect the original upload composition, select its candidate with its context and retain dispositions for all four references.
5. Export the original batch, receive five useful browser downloads and inspect desktop/mobile layout and same-session reopen.
6. Borrow that same owner through the original MCP handler. Read every batch entry and receive/reopen every declared export file. Detach and reattach while preserving the owner revision and all document/review identities.
7. Close the original owner. Use the ordinary CLI to restore the portable workspace into a fresh customer directory and export that same batch.
8. Reopen the customer owner and verify the original client references, selected documents, histories and review decisions.

All source findings remain represented by their actual original results. A blocking source or composition finding leads the operating example to follow-up rather than an incompatible ready disposition.

`Customer_Operation.json` records the actual phase, selected IDs and result. `Disclosure_Workspace.zip` is the portable reviewed workspace. `Original_Workspace_Backup.zip` preserves the closed native owner and its original action journal. If an operating step fails, retain that same work directory, report and original-workspace backup. Continue its current batch and saved actions through the original console or CLI. The runner reports a nonzero exit and the original error; its stored phase identifies the point to resume. It creates a new workspace only when explicitly invoked with a new working directory.

Return the completed package, report and images to the existing ClaritiDox batch thread with their actual sizes and hashes. The sole company-form contact remains with Actions1FB3 after reviewing the customer result.
