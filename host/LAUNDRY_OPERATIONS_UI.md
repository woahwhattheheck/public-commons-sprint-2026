# Laundry workbench — interface and portable use

The complete editor carries the prepared public service catalogue and actual operating record together. It starts with no real customers, orders, cycles, trips, invoices, payments or complaints. Published examples in the vendor's downloadable tracker stay source material and are not imported as customers.

## Daily interface

Use Catalogue for reviewed service prices and operating settings. Customer records contain actual contact details. Intake preserves the collection or shop request, original item/bag references, quantities and care observations. Assessment distinguishes source guide prices from an actual reviewed price. Quotes retain selected delivery, domestic minimum and campaign decisions before customer approval.

Collection and return requests are not confirmed appointments. Staff enter the actual agreed time and confirmation reference. Record actual work in shop machines or with a specialist partner. Machine capacity and unit labels are operator-entered; standard/large/extra-large source loads do not imply kilograms.

Driver routes preserve the chosen stop order and actual handoffs. The editor does not provide GPS optimisation or send messages. Mark an order ready from actual completion, then record its return or shop collection. Issue the reviewed invoice and record actual external card, transfer or other payment references. Complaints, remedial work, credits and reversals remain linked to the original order.

The October duvet offer and optional first-order promotion remain separate source observations. Choose an actual eligible charge base and reviewed minimum ordering. Never silently combine the campaigns or apply a marketing opt-in to someone who has not given it. Public dry-cleaning/alteration prices are starting guides until assessment establishes a reviewed amount.

## Source and records

Every form records the named operator and the engine retains history. Source changes, actual operation edits and billing corrections use the maintained actions rather than replacing the original record. The source panel preserves current and older payment/lead-time observations separately and shows their actual URLs.

Save the complete record regularly. The full preparation ZIP includes engine exports, original source, history, received file rows, this working editor, both guides and the full editable JavaScript source. Working_Record.json is the canonical data input for CLI and source receiving. The optional working-session save additionally retains unfinished form inputs and current selection.

Open is source-aware and generation guarded. If a newer file is chosen while an earlier read is pending, only the newer file can apply. Edits made while opening a file are retained; the interface asks you to choose the file again before replacing those edits. External Page state uses the same original source and invalidates a pending older file read.

## Original CSV intake

Choose a complete original CSV, select the intended entity, map actual headers to neutral fields and preview every row. Preserve the original text, including quoted commas and line breaks. The receiving action retains original rows and selected row decisions. Existing IDs are reviewed through the original register instead of silent replacement.

The published twelve-column order tracker is a useful neutral export. It is not a documented one-click Wash Junkie import API. Actual native onboarding uses a confirmed vendor template and a saved mapping.

## Installed operation

In the original repository:

```sh
node host/laundry_operations_cli.mjs create --source examples/laundry-operations/easy-laundry-source.json --out /tmp/laundry-record.json
node host/laundry_operations_cli.mjs inspect --record /tmp/laundry-record.json
node host/laundry_operations_cli.mjs build --record /tmp/laundry-record.json --out /tmp/laundry-complete-package
```

The output path must be a new directory. Existing files are preserved. To operate an existing record, prepare a complete operation JSON with type, input, actor and at, then:

```sh
node host/laundry_operations_cli.mjs apply --record /tmp/laundry-record.json --operation /tmp/laundry-operation.json --out /tmp/laundry-successor.json
```

Quote, order and import-preview commands return the actual engine result without changing the record. build writes every export, the offline editor, both guides, source modules, member hashes and the complete ZIP.

From the extracted portable package, run the same CLI inside source/. The builder resolves the domain guide from LAUNDRY_OPERATIONS.md if the repository docs/ path is absent. All source dependencies are included; no package install or network request is required by the offline editor.
