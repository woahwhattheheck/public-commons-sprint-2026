# Register migration operator

## Open the maintained workspace

Start the original Migration Workbench server against the selected private workspace. Use the Register migration section in its existing navigation. File migration, case/document migration, grants, financial reporting and the complete original handover remain available in the same application.

Enter the actual operator name in the masthead. Accepted changes are immutable editions in the existing SQLite workspace. Every operation retains its original request identity, selected revision and actor. The interface uses a neutral industrial layout and the existing full source intake and receiving flow.

## Retain the original inventories

In Sources, retain the entire original file and select inventory_csv or inventory_jsonl. Declare the real scope, identity namespace, capture time and coverage. CSV intake uses its existing minimal canonical mapping; the subsequent register mapping reads the full retained raw original fields. The source row and its original bytes remain available from every projected occurrence.

Use a separate source record for each actual independent target observation. A loader's response and a target's independently observed population have distinct meanings. The original capture context travels into the register dataset and every comparison.

## Map a typed register

Source mappings creates an immutable dataset from one exact source ID. Supply a title, register name, actual system label, source or target side, and a mapping review note. These are operator-selected names and original source mappings.

Add each canonical field with Add mapped field. Enable the selected field, choose its exact CSV heading or RFC6901 JSON pointer, then specify text, decimal, date, datetime, boolean or JSON. Mark required values explicitly. Original values, missing/null/empty distinctions, interpretation issues and explicit conversions stay visible alongside the normalized value.

Identity order selects the logical key. Key fields must be text. Assign distinct positive positions; their ascending order becomes the retained key definition. Preserve source identifier formatting exactly. The tool exposes duplicate logical identities with all original occurrences.

Exact value maps accepts a full JSON object keyed by field and original text. It records explicit conversions without changing the retained source. Preview mapped population reads every original occurrence through complete pagination. Its paging keeps the exact configuration selected when the preview started.

Save complete mapped register creates its immutable dataset edition. An earlier dataset ID records the predecessor. Open original dataset browses the complete retained rows, interpretation findings, original source references and full mapping.

## Define the destination plan

Destination plans selects the full set of original source dataset IDs, an explicit timestamp cutoff, the permitted capture age and a review note.

Target destinations is an ordinary row editor: select each register's exact expected target system. Compared fields lists the mapped nonkey fields to check; leaving it blank selects every mapped nonkey field.

Relationship rules records a rule ID, source register, ordered source fields, referenced register, corresponding ordered referenced fields, required flag and one/many cardinality. The domain evaluates the selected original and independent target populations. Complete coverage and usable identities determine whether a missing reference can be concluded.

Exact unit and group controls records the register, one or more exact decimal measures, explicit text unit fields and optional group fields. Each measure is summed separately for each selected unit/group. Every original signed amount remains exact; the tool performs no implicit currency conversion. Invalid values, unusable identities, partial coverage and stale observations remain attached to the control result.

The full plan preserves every selected dataset and policy. Save a later plan edition to change the mapping, cutoff, destination or control selection while retaining earlier reviews.

## Reconcile and compare

Rehearsals selects one frozen plan and all actual independent target dataset IDs. The complete result includes record comparisons, relationship findings and exact grouped controls. Findings retain MATCH, DIFFERENT, UNKNOWN, AMBIGUOUS, MISSING or UNEXPECTED with their full supporting checks.

Open complete rehearsal can filter by register, finding kind, status and original identity. Every list is paged against its declared complete count. Inspect sources and complete checks opens the full retained result and its original source row links.

Compare whole rehearsals selects the exact earlier and later IDs and retains both complete original items for each transition. Changed source membership, identities or values remain explicit. Source removal by itself is not a destination deletion instruction.

## Review findings and record cutover

Record decision opens a form bound to the exact rehearsal and finding. Supply a title, disposition, reason and supporting original row IDs. Rework, waiting for evidence, accepted variance and withdrawal remain separate recorded choices. Preparing a successor decision carries the original finding and current predecessor ID into a new draft.

Cutover review selects one or more complete rehearsals in the same source scope/identity namespace, an actual acceptance owner and a recorded decision. Select any current accepted-variance review IDs explicitly. The complete unresolved population, full review basis and original actor remain in the resulting edition. Use the note for actual cutover/recovery instructions and operational continuation.

## Working files and original-request recovery

The register module keeps a complete working file in IndexedDB, scoped to the exact original workspace. It contains unfinished forms, typed mapping rows, target/rule/control editors, selections, original unanswered requests and preserved stopped attempts. The journal compares its previous saved revision so another tab's edits are not silently overwritten.

Form submission captures every selected field and dynamic row before asynchronous persistence or transport. The original request is retained before the existing mutation route runs. A lost return is recovered by inspecting the original operation, retrying the same body/ID, or continuing the same interrupted operation. The original workspace state is refreshed before subsequent revision checks.

Download current working file exports the complete local draft/history. Restore validates its schema and exact workspace, preserves unresolved original requests and merges prior stopped-attempt history. Complete original source bytes and accepted records travel in the ordinary workspace handover.

## Full exports and receiving

Every opened register entity supplies complete NDJSON and CSV downloads. Each begins with the selected full original descriptor, workspace identity/revision and entity identity. Datasets then include every original projected row; plans and rehearsals include every full finding. Reviews and cutovers retain their full original basis. The final CSV column carries the complete original record JSON, including exact decimal values and typed raw values; the display columns escape formula-like text.

The standard complete delivery also contains register-review.html, the five complete register catalogues and full CSV/NDJSON for every retained edition. The HTML joins readable counts and policies with each complete original descriptor and its full row exports. The original SQLite, original file objects, application and all previous workflow results remain in the same package.

Use the maintained Migration Workbench portable receiver to receive into a separate directory, reopen the same workspace and continue its original records. Keep the full register source module, mounted browser module and guide in the portable source roster.

## Source integration

The mounted module is public/migration-registers.js. The existing migration-app.js supplies its ordinary UI helpers, transport, request journal, selected revision and navigation. migration_server.py advertises the additive register read operations and static script. migration_reports.py streams iter_register_export and write_register_reports using the existing workspace mutex, paginated original readers and immutable PublishedText writer.

The domain and native store integration are in migration_registers.py and migration_workspace.py. The register browser does not create an independent business store. Its local working file contains unfinished operator work while accepted records remain in the maintained native workspace.
