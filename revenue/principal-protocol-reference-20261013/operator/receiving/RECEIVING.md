# Principal complete operator receiving

This course exercises the actual selected source imports, operator commands and complete independent customer continuation. It uses the installed Node/SQLite workspace and, only when selected in the original input, the existing Stellar CLI simulation/read path. It never dispatches plan.execute, deploys a contract or supplies invented network/account/case data.

## Original input

Create one complete JSON file with these exact keys:

- schema: principal.receiving-input.v1
- operationId: the original receiving operation ID
- producerDirectory: absolute original producer workspace
- customerDirectory: separate new independent recipient directory
- returnDirectory: separate new independent return directory
- producerCommands: nonempty array of complete original command envelopes
- customerCommands: nonempty array of complete customer continuation envelopes

Every envelope is {requestId,expectedRevision,method,args}. Allowed methods are source.import, config.save, plan.prepare, plan.simulate, observation.capture and note.save. At least one producer command must import a complete actual original file. Preserve the real name/type/base64/byte count/SHA-256, selected action and actual configuration. All supplied commands execute exactly in their selected order and expected revisions. Customer revisions continue the exported producer's original revision. Choose distinct original request IDs for genuinely new customer work.

A purely local course can import and annotate actual source without a deployed network. This proves only those selected local operations and portable custody. Actual CLI observations require the selected RPC network, an installed configured signer identity and the original deployed reference contracts. Keep these two results accurately distinguished in the receiving report.

```sh
node operator/cli.mjs course --input /ABS/original-principal-course.json --out /ABS/owned-principal-receiving
```

The output directory belongs to this operation. Reuse that same directory and same input on continuation. The input is frozen before work. Each stage stores a complete accepted result and its full artifact index; after interruption the original result is verified and adopted. Failed transport/native results retain the original request and attempt; the course does not create replacement IDs.

## Complete ten-phase course

1. Retain the exact supplied input and operation identity.
2. Apply original producer commands through the real workspace journal, retaining every full request and accepted response.
3. Export the complete native workspace, original files, source roster and request history.
4. Receive that exact packet into the independent customer directory, retaining the first acceptance and every exact later observation separately.
5. Apply the selected new customer edits using the original inherited revision and full request history.
6. Replay the original producer request and verify that later customer state is unchanged.
7. Export the customer's complete return.
8. Receive that exact return into the independent return directory.
9. Replay all selected original producer/customer requests and verify unchanged returned history.
10. Reopen the final workspace cold and verify source prefix, complete packet, original requests and all file identities.

The first completion and later COMPLETE adoption share the same complete proof: all ten ordered phase files, every full artifact hash, both portable envelopes/source rosters, immutable history prefix, original request bodies/results and actual customer/return workspace identities. Owner closure precedes the complete result. No parallel database/server or extra child is created by this course.

## Browser commissioning with the same actual workspace

After the CLI owner closes, start the actual operator server with its original token file and workspace, then operate the full UI at wide and narrow widths. Retain complete original screenshots and downloaded files with the same programme. Perform these real actions:

- Open every supplied original source attachment, including its actual file contents rather than only a filename or file list.
- Inspect the full selected configuration, action ABI and runtime pins. Confirm all i128/u64 fields preserve exact decimal strings.
- Open actual issuance observations and their original network/manager binding. Inspect entry sample, settlement sample, backing, budgets, shortfall and original native streams. Keep USDC accounting units distinct from underlying-token amounts.
- Prepare the selected original read/simulation operation through the real forms. Inspect the exact saved argv and request before any explicit invocation. Funded execution is not part of this receiving course.
- Enter unfinished fields, retain a full source file, save the complete browser working copy, inspect it, and restore it. Verify all original file bytes and prior views. Imported unresolved requests must remain explicit recovery items.
- Inspect a request after a deliberately interrupted browser response using the original request lookup. Preserve the exact request and accepted receipt; never substitute another transaction.
- Export the complete native workspace and browser working copy, reopen both through their intended receiving paths, and inspect the original source files and later edits.
- Navigate away and back, change active manager/network, and verify that an old issue shortcut cannot silently target the new manager with the same numeric issue ID.
- Inspect every supplied attachment and all rendered panels at the actual wide and narrow layouts. Retain full downloaded native files, browser files, HTML/page evidence and actual process closure receipts.

The operator guide and owner policy remain part of the source roster. A source review or a local JSON parse is not a rendered product result. An unrun course must remain labelled unrun; no current provider payment, deployment or funded invocation is implied by this package.

The original input phase retains the actual Node, SQLite, platform and architecture versions. Linux Node 22.16 or later is required. If interruption occurs after the final cold-state file was published, the same course adopts that exact original observation and separately checks that the current recipient head preserves it; later legitimate edits do not replace the original observation.

Before the first workspace mutation, the course reads every executing source member and its manifest, verifies all full byte identities, and freezes the complete source in executing-application.json. Every resume re-reads that same complete installed roster before adopting or issuing work. The initial phase and final receipt bind this exact source digest; changing code under the same API cannot continue an earlier course silently.
