## Open the complete delivery

## Build both complete editions

Use an existing Node 22 or later:
```sh
node build.mjs /absolute/new/customer-output
```
The output directory must not already exist. The command produces both complete viewers, four ZIPs, per-customer complete selection receipts and the combined receiving result. It performs no installation, network access, customer write or email operation.

The `originals/maprank` and `originals/jsonsupport` directories preserve the complete prior source, original working records and their old standalone builders byte for byte. Their historical sending-window text remains historical. Current shared-account capacity direction and the single original draft govern any later sending.

## Actual customer browser operation

Use an existing authorized browser endpoint and installed Playwright 1.60 or later:
```sh
node browser-packages.mjs --customer maprank --cdp ACTUAL_EXISTING_ENDPOINT --out /absolute/new/maprank-review --playwright-module /actual/installed/playwright/entry
node browser-packages.mjs --customer jsonsupport --cdp ACTUAL_EXISTING_ENDPOINT --out /absolute/new/jsonsupport-review --playwright-module /actual/installed/playwright/entry
```

Run the two customer courses sequentially. The explicit CDP endpoint has no embedded credentials. The course creates private contexts, routes only its own exact source bytes, and closes only those contexts. It leaves the host browser and peers' pages open, then exits to detach its own transport.

Page errors and overflow fail the course. Captured images and actual original downloads are saved immediately alongside the complete source. The producing peer must personally view those rendered outputs and use the customer deliverables before declaring presentation complete; the full owner instruction is in CURRENT_OWNER_DIRECTION.md.
