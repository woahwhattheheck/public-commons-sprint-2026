# Continue an original Research case on an existing native worker

This complete operating kit receives a retained Research dossier and its existing reviewed Crossref operation, then drives the maintained authenticated Research client, CLI and merchant attachment through receiving, review, complete exports and reopen.

The frozen application source is commit `496ef23a7442f96240af0f5a5ccfa7b3954a2920`. Its 159 selected files are carried in `source-envelope.json`, retaining each original Git blob and directory path. The worker copies these selected files into its own project; the current repository and other installed product work stay independent.

## Files

| File | Purpose |
| --- | --- |
| `source-envelope.json` | Complete original runtime and UI import closure, with each path, byte length and Git blob identity. |
| `worker-research-setup.py` | Verify source and existing private archives, select the worker runtime, copy the original controller source and prepare the same case. |
| `worker-research-launch.py` | Admit the operation through the existing controller's `ForegroundLaunch` and shared memory/disk capacity registries. |
| `receive-original-crossref-operation.mjs` | Reopen the current original portable, restore the original capture/operation records and receive the reviewed missing edition by fresh revision CAS. |
| `run-original-research-case.py` | Continue the whole client/CLI/merchant journey and retain its complete portable, reports, original captures and artifact manifest. |

The selected worker needs Python 3.9+ compatible with its existing native controller and an existing Node 22+ interpreter. Setup records the actual Node path and version. It uses the already present controller and capacity registries.

## Select the existing case privately

The setup argument has schema `sf88.research-client.native-worker-input.v1`. Keep these values together in the original private operation:

- `operationId`, canonical absolute `directory`, existing `sharedControl` and `controllerSource`.
- `sourceMerge` and `source` with `repository`, `sourceMerge`, `files`, `bytes`, `sha256` and `gitBlobSha`. The envelope in this kit is 2,012,711 bytes; SHA256 `bd4574e1567c5419ed092e906e1939c6ac3e66799628d7f96f1b0e2fd075ea57`; Git blob `8a1c787d624e9ec6116973a6dc426390a560502d`.
- `receivingHelper` with `path`, `bytes`, `sha256` and `gitBlobSha` for the exact helper in this kit.
- `masterArchive` and `companionArchive`, each with the original archive's byte length and SHA256. The master is an existing ZIP containing its complete gzip Research portable. The companion ZIP retains `reviewed-edition.json`, `operations/<original operation>/plan.json`, `state.json`, every capture reference and `source-captures/<capture SHA>.json`.
- `portable` with its original archive `member` and uncompressed member `bytes`. Setup derives and retains this member's SHA256 after verifying the complete archive.
- Original `dossierId`, `questionId`, exact `questionText`, `originalRevision`, `originalRevisionSha256`, `originalEditionCount` and `originalFindingCount`.
- `reviewedEditionBytes`, `reviewedEditionSha256` and the retained `crossrefOperationId`.
- The source-grounded `analystNote` and its `noteSources`.

Obtain the private archive references at actual dispatch. Pass one UTF-8/base64 JSON object `{master: currentOriginalDownloadURL, companion: currentOriginalDownloadURL}` as the separate download argument. Setup uses those references for the two exact verified downloads and retains the original bytes.

## Native handoff

Use the maintained existing worker's `native.handoff` interface. The five input names above, their published Git blobs, lengths and SHA256 values select the complete job. The handoff's controller target is `<directory>/controller/host`; setup copies the current original controller there while retaining its source identities. Both resource ledgers are the existing `<sharedControl>/capacity/{memory,disk}` directories.

The handoff runs:

```text
python3 <directory>/inbox/worker-research-setup.py <directory> <case-input-base64> <fresh-downloads-base64>
python3 <directory>/inbox/worker-research-launch.py <directory>
```

Use one stable native operation and its original record, with the existing worker's returned request/job handle. Setup publishes ordinary private files exclusively, accepts exact retained bytes on repeat, and verifies original archive/source identities again. An uncertain handoff is reconciled with that existing operation before continuation.

The launcher declares 768 MiB memory plus 256 MiB reserve, and 512 MiB disk plus 64 MiB reserve under the existing controller. The selected Node operating process limits its heap to 256 MiB; the original driver retains the smaller server/CLI process settings.

## Receiving and operating behavior

The receiving helper verifies the original revision through the dossier's retained revision list, keeps all authored questions, findings and selections, and restores each original operation's complete capture set. It adds the selected reviewed source by the original receiver's fresh revision CAS. An already received matching raw source reopens its existing edition. The source captures and reviewed raw bytes remain exact.

The maintained operating driver then uses the same authenticated Research listener for metadata, sections, revision history, CLI and the 27-tool merchant family. It continues the selected Crossref operation, appends the analyst note to the original question, streams the complete portable/HTML/source results, and reopens the resulting authoritative case. Its independent BOM-bearing derivative exercises exact raw-byte receiving and portable retention. The original saved operation and its published source capture count are retained throughout.

## Collect the actual result

The native record selects these files under the project:

- `results/run-result.json`: actual receiving/operating stages and retained continuation state.
- `results/run-artifacts.json`: actual final revision, complete return byte count/SHA256 and selected authoritative portable/HTML.
- `results/native-return.tar.gz`: complete selected reports, original raw source/capture/operation records, and portable exports with `delivery-manifest.json`.

Use the returned artifact manifest to collect the complete original result. Keep the native case and operation available for receiving until the owner-controlled copy has been verified. The private `case-input.json`, source selection and original archives stay with that operation for continuation.
