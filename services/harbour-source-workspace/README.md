# Harbour Source Workspace

A complete editable source, operating-evidence, financial-basis and supplier-return workspace. Open Harbour_Source_Workspace.html directly in a current browser. This is a migration and evidence tool; the responsible authority and supplier retain actual harbour operations, billing and production loading.

## Complete working flow

1. **Workspace & delivery**: create the original workspace or open a complete engine/recovery JSON. Name the operator before changing retained source. Every operation keeps its original identity and actor.
2. **Original files & CSV**: retain all original bytes, source URL and representation. Receive actual UTF-8 CSV as source, target or reference. Choose one of nineteen neutral roles; these are not asserted vendor tables. Native workbook, SQL, PDF and other files remain full supporting originals.
3. **Role mapping**: select exact zero-based header occurrences and all opaque compound-key parts. Extra fields, constants and references are explicit. Unknown columns, missing positions and repeated witnesses stay in complete source.
4. **Source scope**: select full mappings/files, declare every role included/not-supplied/not-applicable with reason, and record policy/history/evidence coverage. Source and target/reference sides remain distinct. External endpoints need exact retained declarations; they do not create a local record or target key.
5. **Records & relationships**: inspect original versus effective cells and complete relationship/document/access/history evidence. Correct a cell only with its original current value and attributed reason. A later correction stales the old selection without rewriting earlier files or reports.
6. **Operating evidence**: save an immutable profile from actual selected policy originals and mapping fields. Date formats, code meanings, conditional completeness, dimensions, contact evidence and recorded waiting-date decisions are explicit. Inspect every resulting finding. No automatic deadline, eligibility, vessel suitability, mooring allocation or permit action exists.
7. **Financial basis**: declare actual amount/account/currency/period/type fields, sign multipliers, cross-namespace/period rules and source completeness. Blank remains absent. Exact selected totals never imply a complete debtor balance. Per-record residuals need all required coverage and valid linked data. The application does not calculate charges from public tariffs or move money.
8. **Findings & review**: inspect the structural report and separate operating/finance assessments. An accepted review retains the exact current profiles; it does not grant an operational, financial or supplier approval. Download complete JSON and readable reports.
9. **Supplier templates**: retain real original template/dictionary/route files or label an authored example. Map every selected source, every destination column and every relationship explicitly. A changed native ID needs an original supplied crosswalk. Actual API/write capability is not inferred.
10. **Prepared output & returns**: freeze target CSV bytes only against the current reviewed selection. Receive actual complete returned files linked to that preparation. Inspect missing/extra/conflicting records, changed cells and available native outcomes. Previous editions remain exact.
11. **History & recovery**: preserve full operations, independent copy identity and every unfinished form. Export complete working JSON, a self-contained working HTML, or the whole source-and-data ZIP. Reopen on a separate browser/copy and verify the complete history and original files.

## Operating profile binding guide

The form retains the complete editable JSON array. Its initial skeleton uses actual selected mapping IDs with empty checks; it does not guess date/code semantics. Every binding contains mappingId, dateFields, codeMeanings, requiredByType, dateOrders, dimensions, localContacts and waitingDecisions. The included API.md gives the exact field names. A declared field must exist in that mapping. Date comparisons require the same explicitly declared format. The policy source files must belong to the selected scope. Missing checks stay undeclared rather than passing by default.

## Financial profile binding guide

Each financial binding selects actual charges/payments/allocations mapping fields and declares entry-type sign multipliers. Namespace and period triples are exact source permissions to compare; they are not conversion rules. Coverage identifies exact namespace/account/currency/period plus original files and all four completeness flags. Selected-only totals and unconfirmed residuals remain visibly separate. Review the source basis with the actual finance owner before relying on a control.

## Persistence, original bytes and exit

Browser persistence uses a transactional revision compare-and-swap. Competing completed edits create independently retained branches. Unfinished forms are kept per tab, and conflicting incoming writing remains a recoverable lineage. A stale form retains its original basis until explicitly reviewed. Download raw unfinished values if a complete working-file limit is exceeded; the current writing is not deleted.

The product supports at most32MiB per selected file/CSV,100,000 rows and512 columns per CSV,256 files,128 sources,10,000 operations and128MiB complete portable JSON. These are validation ceilings, not measured browser throughput. Complete evidence, history, reports, row witnesses and unfinished writing count toward portable size. Actual commissioned populations require measurement.

Whole delivery includes all originals, mappings, profiles, corrections, reviews, contract/template editions, frozen outputs, actual returned files, complete journal and all runnable source. Source permissions are retained declarations; an offline file must still be handled under its owner's access policy. This version does not enforce a supplier's tenant ACL.

## Maintained build and native receiving

Run `node build.mjs --out ABS_NEW_DIRECTORY` for the complete blank application and source ZIP. Add `--workspace ABS_COMPLETE_JSON` and optionally the original `--copy-id` to build an editable saved edition. Full output is published atomically/create-only; existing differing bytes are not overwritten. CLI commands and the complete original-request/replay contract are in CORE_OPERATING.md.

BROWSER_OPERATING.md gives the existing-browser course. Source checks and parsed scripts are not actual rendering. The producer must personally view the exact outgoing app, full reports, each attachment and applicable PDF pages after operating the key controls and independently reopening the complete edition.
