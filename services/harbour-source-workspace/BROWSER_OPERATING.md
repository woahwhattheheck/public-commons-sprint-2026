# Original Harbour browser receiving course

Use the existing equipped native browser/controller. The module exports:

```js
await runHarbourReceiving({
 page, context, outputDirectory: ABS_ORIGINAL_OPERATION,
 applicationPath: ABS_EXACT_HARBOUR_HTML,
 fixturePath: ABS_AUTHORED_COMPLETE_ENGINE_WORKSPACE,
 attachmentPaths: [ABS_EXACT_HARBOUR_HTML, ABS_WORKSHARE_HTML, ABS_PUBLIC_REFERENCE_JSON, ABS_PRACTICAL_GUIDE_HTML],
 renderBinaryAttachment
});
```

Import runHarbourReceiving from run_browser_receiving.mjs. All paths are absolute. The caller supplies and owns page/context and the existing browser. The callback creates isolated child contexts for independent received copies and closes only those; it does not create or close the caller's browser.

The fixture must be the exact workspace returned by the maintained buildReceivingFixture() in receiving-fixture.mjs. Export it with the original engine. It contains explicitly authored harbour records, policy sources, both profiles, supplied-example targets and full return. The first source is parties with its editable label at column1, so the actual successor course changes that one label and leaves every original prepared/returned byte intact. It is separate from the public council reference and never asserted to be live customer data.

The callback freezes the actual application, full authored fixture and every outgoing attachment before dispatch. An unchanged retry resumes the original operation and retained output bytes. It validates the executing complete source against the actual embedded application source. No new filename or run directory should replace an interrupted original request.

## Complete actual course

- Open every exact outgoing HTML through the real browser; read full documents at1440 and390 and their print view. Open the reference JSON through the actual application, inspect all source/profile/return/history sections and export its complete handover. Preserve source qualifiers and exact records.
- Replay every maintained authored operation through actual controls: complete file/CSV import, mapping, scope, operating and financial profiles, correction/review, actual target preparation and full returned files.
- Inspect all19-role source relationships, original/effective cells, source-bound profile findings, complete prepared CSV and actual comparison. Capture desktop/narrow views.
- Correct one authored original party label, save a successor scope and both successor profiles, retain a new review/contract/preparation, and compare the earlier actual return. Exactly one differing label remains visible; old target bytes are unchanged.
- Open every full report including original and successor returned-data reports, all applicable original PDFs, and actual outgoing attachments.
- Save unfinished supplier notes, export complete working JSON/HTML/ZIP, compare every ZIP member against the original complete file selection, and reopen in a separate browser. Keep full source history, original files, profile editions and unfinished writing.
- Exercise two tabs against the same original revision and retain both complete diverged branches after the competing edit.

For an original PDF or any other binary attachment, the equipped caller must supply renderBinaryAttachment({page,file,outputDirectory,prefix,widths}) returning actual screens[] and outputs[]. It must open usable ZIP contents and every applicable PDF page; byte verification alone is not viewing. The callback fails instead of silently counting a binary file as inspected without this adapter.

The result is controls/exports completion with exact input/output identities and screenshots. The producing worker must personally LOOK at the returned pixels and all attachment pages before reporting the selected outgoing edition ready. Preserve that observation in the same original operation; no external send is implied.
