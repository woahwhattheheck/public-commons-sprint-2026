# Receive the complete portfolio target desk

This receiving workflow opens the actual operator server and the original MPXJ 16.10.0 source engine. It uses one selected original project file, retains its source edition, corrects an actual task's native NAME field, prepares and reviews the file target, writes Project XML with the original MSPDIWriter, receives those exact bytes through the original reader, records every observed difference, and completes the handover and portable restore.

The browser runs at desktop and mobile widths. It discards one real local intake HTTP reply after the server returns it, then recovers that same saved request. The accepted source edition, target plan, native export, capture, comparison, acceptance, report and original action IDs stay in the same workspace.

## Continue the same operation

From the service directory, with actual absolute paths:

~~~bash
python3 operator/native/receive.py \
  --workspace /absolute/portfolio-receiving/workspace \
  --source /absolute/mpxj/assignment-assignments-project2019-mspdi.xml \
  --output /absolute/portfolio-receiving/output \
  --operation-id portfolio-target-receiving-001 \
  --node /absolute/existing/node \
  --playwright /absolute/existing/playwright/index.mjs \
  --chromium /absolute/existing/chrome-headless-shell
~~~

Keep the same operation ID, workspace and output directory when continuing an existing run.

The Python callable receive(..., native=existing_native) can join an already running original NativeMPXJ instance. It reuses that instance for both original and restored workspaces. The browser temporary directory stays within the same process's private /dev. Source, request progress, outputs and restore records remain at the selected durable output path.

If an original local action failed and its source has been corrected, the same command with --resume-failed invokes that action's existing resume path. Its original ID, input digest, failure history and retained native calls remain. A completed stage reopens its saved result and verifies its existing artifact bytes.

A source finding with requires_decision:true uses the original source review's exact finding SHA and decision shape. Supply a reviewed JSON file with --review-decisions when the selected source requires it. The actual source-review-findings.json is retained when source review requires further handling.

## What the operation retains

- operation.json binds the operation ID, selected workspace, source hash, reviewer and original decision input.
- native-runtime.json and source-selection.json identify the actual native runtime and the source used by the receiver.
- original/browser-progress.json records each exact local request before the browser sends it, plus accepted acknowledgement and artifact identities.
- original/browser-result.json joins source correction, native file export, capture, comparison, acceptance and ten original local actions.
- portfolio-migration-handover.html presents readable counts, accepted differences, identities and native transaction tables.
- portfolio-migration-handover.json preserves the full original deployment and comparison.
- The original portable ZIP retains source files, native exports, source and target editions, request/reply objects and acceptance.
- restore-intent.json and restore-receipt.json bind that same ZIP to its one receiving destination.
- restored-browser/browser-result.json verifies the same accepted project and exact handover bytes on the newly opened original workspace.
- result.json contains the full completed operation and artifact hashes.

The coordinator copies the selected fixture into its own input directory, then moves only that private copy aside before cold receiving. The exact copied bytes remain retained. The original upstream fixture is unchanged. The restored application reads its source and exports from the portable workspace.

Private browser entry files are temporary and owner-readable. Browser storage and operation control files remain private intermediates. Deliver the named source/report/ZIP artifacts and final result through the original customer operation.
