# Commission an existing imported plan

This addition completes existing-plan adoption and correction inside the maintained Project Portfolio target operator. It uses the original PortfolioWorkspace editions, target request and object stores, typed native planner, complete MsPlannerReader capture, native OperationSet continuation, acceptance and portable receiving. B9D2 remains the product and installed-source owner. The original Sensei commercial conversation remains with 2D58.

The code is an additive implementation, with exact source and integration guards delivered alongside it. Its local source-contract exercise is separate from the original installed native programme. That exercise uses explicitly authored records and makes no provider call. Installed native receiving is complete only when the existing owner records its actual result.

## Install into the existing product

Use the original complete A+B source and its maintained installation instructions. Copy the two new Python modules and machine-readable contract under portfolio_target, this guide under operator, and the source exercise under examples. Apply the exact guarded changes in COMMISSIONING_INTEGRATION.json to portfolio_target/workspace.py and portfolio_target/adjustments.py. Those are the only shared Python files this addition changes.

The manifest names the exact original full preimages and composed full postimages. Check all selected files before replacing anything. A differing owner revision needs a deliberate source merge; do not restore the old workspace or overwrite unrelated edits. B9D2 keeps the shared UI and final installed-source composition. The existing CLI discovers the added actions from workspace.ACTIONS; no new launcher or service is required.

This addition introduces no Python, Java or provider dependency. Actual native capture still uses the already selected MPXJ MsPlannerReader and the original Java/runtime closure. Credentials stay in the existing private target configuration and bearer-file route outside the portable workspace.

## What adoption means

Adoption records an existing native project and its evidence. It does not create a project, bucket, task, team, assignment or dependency. It does not mark a fictitious creation transaction complete. A successful adoption ends at CAPTURED after the original native reader and additional complete project-team pages have returned.

Select the original source edition, the actual supported project_operations profile and the existing project GUID. Upload the original import report, export, screenshot or operator statement through the normal upload action. Keep the returned upload descriptor unchanged. Classify each evidence item as native_receipt, original_export, original_screenshot or operator_statement. A screenshot and an operator statement remain those forms of evidence; neither is relabeled as an authenticated native receipt.

The adopt_existing arguments also retain optional original import settings, time, project URL and a label. Retain every import-exception row with its source evidence hash, original coordinate and full original value. These facts describe the supplied import context. The later capture is a separate, dated native observation.

The original request ID and complete argument hash are saved before the first provider read. Continue the same saved request after a connection or process interruption. While that capture remains in progress, a different capture request is rejected even if it names the current deployment revision. The original request retains its complete reader pages, project-team continuation and native edition. A changed source, profile, project or evidence selection is a new explicit adoption or rebind request; it does not replace the unfinished capture.

## Inspect complete native identity

The capture pins the actual WhoAmI user and organization, public profile and native CSDL. It retains every original reader page and the original MPXJ edition. Additional project-team pages are necessary because the original reader materializes bookable resources used by assignments, while native resource selection for this product uses project-team rows.

The inventory has four native families:

| Family | Operator choice |
| --- | --- |
| Tasks | Original source task key to actual msdyn_projecttask GUID |
| Resources | Original source resource key to actual msdyn_projectteam GUID |
| Assignments | Original source assignment key to actual msdyn_resourceassignment GUID |
| Dependencies | Original source dependency key to actual msdyn_projecttaskdependency GUID |

Each native row retains its complete body, GUID, entity, body hash and project-membership evidence. Each task also retains whether a bucket lookup was actually returned and its value. Multiple buckets remain multiple buckets. No single bucket is selected by inference.

Names and candidate GUID matches help inspection; they do not silently bind rows. Explicit mappings must select rows in the pinned source edition and captured project, and two original rows cannot silently share one selected native row. Partial mappings are allowed with exact retained findings.

The original identity reader still resolves resources through project-team → assignment → bookable-resource → reader row. An unassigned resource may have a real native project-team identity but no reader counterpart. That distinction remains an unresolved comparison finding, with the original resource and raw native team still retained. Source assignment/dependency relationships are checked separately from the selected native row identity.

Complete sequential reads do not establish a point-in-time snapshot across pages. The original pages, times, request URLs and hashes remain available for review.

## Prepare and record the adoption review

Call prepare_adoption_review with the exact deployment revision, explicit row_ids, selected mappings and exception_decisions. It produces a local proposal without changing the deployment. Inspect its full plan, intended_observed comparison, import-exception review and required_finding_ids.

Task mappings reuse the existing typed converter. Defaults are NAME → msdyn_subject as text, START → msdyn_scheduledstart as UTC and FINISH → msdyn_scheduledend as UTC. An absent source field is not invented. A local date needs the actual source time zone; ambiguous dates require the explicit original fold decision. Optional conversion rules may select exact native choices, booleans, integers and representable numbers. Identity, hierarchy, bucket and calculated fields are excluded from this correction route.

For every original exception, record exactly one authored disposition and a note:

| Disposition | Meaning |
| --- | --- |
| retained_difference | The original difference remains explicitly accepted for this scope |
| needs_correction | A subsequent correction is still required |
| manual_followup | The issue needs work outside the selected automated task fields |
| observed_resolved | Selected retained evidence supports the operator's resolution decision |

An observed_resolved decision requires at least one selected retained evidence hash. The full original exception is preserved beside the authored decision.

Call review_adoption with the returned proposal_sha256, exact current deployment revision, reviewer, note and all required finding IDs. The service verifies the proposal's deployment snapshot and inventory before saving the review. Earlier adoption plans, reviews and capture selections stay in history. A fresh recapture of an adopted project requires a fresh review of that exact capture.

## Source, intended and observed values

The intended-observed artifact records these separately for every mapped task field:

- The original typed source value and source field.
- The explicit conversion rule and intended native value.
- The actual native task GUID, property presence, observed value and native body hash.
- A status of equal, different, unmapped or unobserved.

Boolean values are distinct from numbers. Dates are compared as equivalent instants only for an explicitly selected UTC conversion. A missing native property is unobserved; it is not interpreted as null or zero.

This comparison is the correction basis. The ordinary original Portfolio comparison is also retained, including all source families, definitions and reader identity findings. A correction's transformed native field value does not replace the original source model.

## Correct an import while the source is unchanged

An imported task can be wrong even when the source file is right. Select prepare_observed_correction on the reviewed adoption or a previously captured correction, passing the current commissioning_comparison_sha256 as basis_sha256. The source edition may remain exactly the same. Optionally select another actual retained source edition, explicit conversion changes or individual source_key/target_field pairs.

The service saves a new child preparation and the complete selected parent snapshot before native reads. It then retains each first complete actual task GET. The prepared operations compare intended values with these current native values. They do not depend on an old-source-versus-new-source difference.

If a task already has the intended value, no update is prepared. If it has the wrong value, the plan contains a PssUpdateV1 operation for that same native GUID and only the selected fields. There are no immediate creation calls, no new bucket and no substituted row identities. Unmapped tasks and absent native properties remain explicit review items.

The task identity set must remain stable. Hierarchy, assignment endpoints and dependency structure cannot be smuggled into a task-field correction. Resources, assignments, dependencies, calendars and other omitted source fields remain available in the complete retained source and findings.

Use the existing review action for the new PREPARED correction. Review every finding and the complete payload/before values. Use the existing continue action with the saved review hash. The original implementation owns each OperationSet, row receipt, status, detail, pause and uncertain-outcome recovery. A lost native reply is reconciled through that same original operation; this addition does not replay an uncertain write automatically.

Before queueing and again before execution, the added verifier reads the actual task, checks its project and native GUID, and compares the listed before values using the same explicit typed rules. A changed value stops that correction. The ETag is retained as observation evidence; the scheduling action does not provide an atomic conditional ETag parameter. Separate OperationSets are separate native transactions.

The legacy prepare_adjustment path explicitly rejects an imported-plan deployment. It directs the operator to prepare_observed_correction so the unchanged-source case cannot silently produce an empty plan.

## Capture and accept the result

After the original correction actually completes, use capture_target on that deployment. It reuses the same complete native reader, identity and project-team routes and retains a new exact intended-observed comparison. The old adoption and previous captures remain unchanged.

Acceptance uses the existing accept action, with its original comparison_sha256, reviewer, note and readable exceptions. Add the current commissioning_comparison_sha256, exactly every non-equal intended-observed field ID in accepted_commissioning_fields, and exactly every current commissioning_identity_findings ID in accepted_identity_findings.

These lists acknowledge the selected result; they do not discard evidence or claim all differences were automatically repaired. The original exception decisions, native row observations and source remain inspectable. Original same-request acceptance replay returns its saved result.

## Handover, receive and principal rebind

After acceptance, commissioning_handover emits the existing handover plus imported-plan-commissioning.html and imported-plan-commissioning.json. The additional files contain full original import context, reviewed identities and exceptions, source/intended/observed values, native correction calls/sets and principal-rebind evidence. Ancestors are read from the exact saved parent snapshots selected by those operations, so later parent edits cannot rewrite a previous handover's lineage.

Use the original archive action for the complete portable workspace. Its existing export retains all referenced operator objects and source/native editions. Use the normal receive command on a selected new destination and reopen that complete workspace. The receiving process retains original request IDs, byte hashes, reviews and editable history. No target credentials are exported or inferred.

For another authenticated principal, use rebind_imported_target with the exact parent deployment revision, separately selected private profile, reviewer and note. It creates a new adoption entry, retains the original target identity and parent snapshot, checks the same actual organization/project, and takes a fresh complete capture. Review the new identity/exception proposal before any correction. Old jobs and their credentials or target identities are never rewritten.

## Exact CLI entry

Run the commands through the existing operator environment and current source. Each arguments file contains the exact fields in portfolio_target/commissioning_contract.json.

```sh
python3 -m portfolio_target.cli --workspace /private/portfolio --profiles /private/target-profiles.json action adopt_existing --request-id ORIGINAL_64_HEX_REQUEST --arguments-file /private/adoption.json
python3 -m portfolio_target.cli --workspace /private/portfolio --profiles /private/target-profiles.json request ORIGINAL_64_HEX_REQUEST --resume
python3 -m portfolio_target.cli --workspace /private/portfolio deployment ORIGINAL_DEPLOYMENT_ID
python3 -m portfolio_target.cli --workspace /private/portfolio action commissioning_handover --arguments-file /private/handover.json
python3 -m portfolio_target.cli receive /private/complete.portfolio.zip --destination /private/received-portfolio
```

The uppercase tokens identify values selected by the operator; replace them with the actual retained IDs. Preserve a command's original request ID on continuation. Use the existing artifact command to copy a selected immutable object by its full SHA-256.
