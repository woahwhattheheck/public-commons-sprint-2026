# Audit Source Workspace

A complete offline workspace for retaining audit records and evidence, declaring original mappings and scope, reviewing structural findings, preparing supplier-approved CSV files and comparing actual returned data. The twelve neutral roles are a migration model: universe, plans, engagements, controls, tests, findings, actions, documents, principals, access_rules, history and relations. They are not a supplier's native schema.

Open Audit_Source_Workspace.html in a current browser with IndexedDB available. The complete reusable application starts empty. All work stays in the selected browser copy until you deliberately download or move a complete working file. Keep confidential source records in an appropriately controlled environment; retained permission declarations do not create local authorization.

## Whole operating flow

1. **Workspace & delivery** — create a named workspace or open a complete working JSON. Enter the named operator above the section. A new operation retains that attribution, its actual time and the original revision.
2. **Original files & CSV** — retain complete original evidence, dictionaries, workbooks, SQL extracts and response files. If document records declare a file binding ID, supply that exact ID when retaining the file. Mark original, authored transcription or authored example explicitly. Receive actual UTF-8 CSV separately, selecting its source/target/reference side and neutral role.
3. **Role mapping** — select the original CSV and its exact namespace. Select every opaque key column. Map reserved or additional fields by numeric original occurrence, or an intentional exact constant. Declare relationship keys and their purposes explicitly. Duplicate headings and unmapped columns remain in the original.
4. **Source scope** — select one mapping edition per intended original source, complete supporting files, every role's included/not-supplied/not-applicable declaration, and actual permission/history/evidence basis. All selected mappings share a side. A source-declared basis needs its retained original file. Save the complete population and cutoff statement.
5. **Records & relationships** — inspect every original row through the 50-row controls. Exact compound keys keep namespace, role and original key parts separate. Missing positions and present empty strings are distinguished. Correct a source cell with an exact expected value and attributed reason. If several trailing cells are missing, append only the next missing position, one attributed correction at a time. Earlier scopes keep their original row edition.
6. **Findings & review** — choose an exact frozen scope and inspect errors, warnings, source witnesses, document bytes and relationship continuity. Open a finding's original row. Save an accepted or needs-work review. Accepted is a structural preparation decision, not an audit opinion, vendor acceptance or confirmation of effective permission enforcement.
7. **Supplier templates** — retain the supplier's complete actual route, dictionary, CSV template and any key crosswalk first. Select exact file IDs and source mapping IDs. The advanced JSON editors preserve ordered duplicate headers and explicit selector types. Every destination column needs a source selector or deliberate constant. Every actual source relationship needs an explicit target-key binding. Inspect the complete target assessment before preparing it. An authored teaching contract must be marked authored-example.
8. **Prepared output & returns** — select the accepted current source review and actual target contract, then freeze the whole output. Download each complete frozen CSV. Later source edits preserve these original files. The supplier performs the sanctioned load. Retain actual returned CSV files and map every expected column to the returned occurrence, or null for an unreported non-key column. Omitted tables, duplicates, missing rows, unexpected rows, changed cells and unconfirmed positions stay visible. Keep the actual submission reference and interpretation.
9. **History & recovery** — inspect every original operation and source edition. Recover another tab's unfinished forms into an independent copy. Download the complete working JSON, working HTML and whole ZIP before transferring or retiring a browser copy.

## Source and identity rules

CSV decoding is strict UTF-8. Original BOM, quoting, complete row order, duplicate headings and every original byte remain in retained files. Corrections create attributed editions. Identity uses the exact namespace, neutral role and ordered opaque key parts; no display-name merge or first/last-wins duplicate policy is applied. Conflicting rows include differences in unmapped original columns.

Workbook, ODF, SQL, PDF and binary evidence inputs remain whole original files. This product does not claim a native workbook parser or a supplier write API. Obtain the actual sanctioned receiving contract before selecting a target mapping.

Source ACL and history rows retain explicit relationships and evidence. Undocumented effect, inheritance, roles, outcomes or native version meanings remain unconfirmed. Original audit opinions are retained as source text without generating new assurance conclusions.

## Saved work, concurrent tabs and complete exit

Each browser copy has one revision and original journal. Each page has its own unfinished form records. An IndexedDB transaction compares the original head, saves the complete next workspace and clears only the submitted unchanged form atomically. A competing saved revision preserves the proposed complete branch separately instead of overwriting the current copy.

A stale unfinished form keeps its original head until the operator uses **Keep these values against current revision**. Saved HTML carries those unfinished values. On reopen they fill only missing current-tab draft slots; newer local writing remains. A different or diverged received branch is kept independently. Receiving a newer descendant requires an explicit choice and another original-head comparison.

**Download complete working JSON** includes the entire workspace, copy identity, current selection and unfinished values. **Download working HTML** includes the same record plus all executable source. **Download whole ZIP** adds every complete original byte, full history, selected source reports, prepared CSVs, returned comparisons, the usable application and its full source tree. Raw unfinished-value download remains available when an oversized working envelope cannot be exported.

The complete recovery limit is 128 MiB of UTF-8 JSON, including drafts; the engine's 128 MiB workspace ceiling is a maximum, not an extra allowance. Each original file/CSV is limited to 32 MiB; selected work also has explicit row, column, file, source and operation limits in API.md. Browser storage quota may be smaller. Preserve a downloaded complete copy.

## Build and command-line use

Use Node with support for the maintained ES modules. No runtime package install or network service is needed for the application or builder.

~~~sh
node build.mjs --out /absolute/new/audit-delivery
node build.mjs --out /absolute/new/audit-working-delivery --workspace /absolute/Working_Recovery.json --copy-id original-browser-copy
~~~

The builder publishes a complete directory, BUILD.json and a sibling .zip file. Existing output paths are adopted only when every originally selected member and complete byte identity agrees. Use a distinct destination for a changed source edition. Inside an exported ZIP, the runnable source is under source/audit-migration-workspace; the shared original browser receiving helper is beside it under source/migration-receiving.

The original CLI owns init, apply, inspect, rows, analyze, assess-target, report, handover and receive. See API.md and CORE_OPERATING.md for exact flags, operation replay, kernel lease and original input custody. It uses the same engine and full working envelope; there is no parallel application store.
