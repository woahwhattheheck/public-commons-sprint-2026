# Complete VIP manager receiving workflow

Run the original application through one retained HTTP and CLI case using Node.js 24. The supplied provider serves the product's generated development records through the native-shaped read routes. No external HubSpot account is required for this receiving workflow.

From the product directory:

```sh
node workspace/receiving/operate.mjs /private/vip-receiving
```

Choose a private directory outside the source repository. Keep that same directory and selected source checkout if a process or host stops. Running the identical command reopens the committed stages and original operation identities. Do not edit the product source while this case is running: the driver binds each selected application file by SHA-256.

The complete workflow retains an original paginated capture, interrupts its child after a saved page, resumes the same capture, and runs the original triage engine. It creates a continuous schedule, advances the explicit engineering clock, preserves the daily and weekly boundaries, reviews a frozen digest, and checks that a later capture with a backdated source time cannot enter an earlier window. A provider refusal produces the retained failure/status digest. The same case covers explicit pause, London daylight-saving fold/gap boundaries, complete workspace export, receiving a paused historical schedule, provider/configuration rebinding, a fresh received capture, and reopening exact digest bytes through independent original CLI processes.

The child service in `receiving/server-child.mjs` calls the product's actual `startServer` entry with its development provider and explicit clock. All capture, triage, schedule, digest, review, export, receiving and CLI operations use the original application. The operating program makes read requests to its selected provider and verifies that it made no provider writes.

## Retained output

`progress.json` contains the selected source files, original project and received-project identities, per-phase completion, request IDs and native provider events. `operation.json` is written only after the complete workflow returns PASS. The same directory holds the frozen digest, portable project export and independent CLI readbacks selected by that progress record. The program's output lists the exact completed stages.

Calendar advancement is deliberate engineering-clock control. The records are generated development inputs, and the source and analysis availability timestamps remain part of the actual application outcome. Use the product's [operator guide](README.md) to configure a permitted live HubSpot account and run its ongoing capture and manager reports.

## Receiving on another host

Use the same source commit and an available Node.js 24 Linux host. Give the new host one explicit case directory and return its actual source pin, `operation.json`, retained output hashes and host identity to the existing product owner. Continue any previously started case from its own saved state.

This entry uses portable source-relative defaults. After path selection, its operating body is identical to the original prepared full-case program; the service child is the same source.
