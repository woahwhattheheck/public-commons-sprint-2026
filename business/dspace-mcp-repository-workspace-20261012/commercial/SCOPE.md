# DSpace repository implementation workshare

Prepared for 4Science by TokenJunkie Labs  
12 October 2026

## Proposed engagement

**$6,400 fixed price; ten business days.** Configure, receive, and hand over one institution's complete repository operating workflow using 4Science's original DSpace MCP implementation and the retained operator workspace.

The engagement covers one existing DSpace 7+ REST service, two agreed collections, up to 500 existing item records, one configured draft-submission family, and up to 20 supplied original files of at most 20 MiB each. The institution chooses its metadata changes and reviewer. We deliver the configured source intake, full-value review, named execution workflow, native return reconciliation, two correction cycles, and complete staff receiving.

This is an implementation workshare that 4Science can incorporate into its client delivery. 4Science retains the client relationship, institutional coordination, and its own commercial terms.

## Delivery

### Repository and source intake

We connect the institution's existing staff profile, confirm its repository UUIDs and collection configuration, and retain its agreed source cohort. The intake carries original item metadata, source response identities, native collection ownership, and files. We configure the institution's environment references and current submission section names.

The intake includes a field disposition agreed with the repository reviewer: preserve, review, amend, or defer with a documented reason. Original values, language, authority, confidence, ordered membership, and related-entity identities remain available throughout the review.

### Staff review and operations

We configure the industrial browser workspace for the agreed cohort. Staff can inspect full records and linked entities, retain selections, preview exact field changes, and record named decisions. Ordinary metadata and generated relationship values are distinguished using native DSpace semantics.

The reviewed operation uses the original MCP tools. Metadata changes recheck the original touched fields, collection moves use the original entity-type check, and file uploads retain the full pre-dispatch inventory plus original received bytes. The implementation includes the selected native draft workflow with its actual section paths; administrative archival is an explicitly distinct action.

Each execution retains the repository and user, reviewed plan, original native responses, and created object identity. Restart receiving reconciles the original action before completing the remaining undispatched steps. Reviewed reversals restore touched metadata or collection ownership while preserving unrelated staff edits.

### Correction and receiving

Two complete correction cycles are included against the agreed cohort and operations. We join the staff's corrected source or field decisions, repeat the affected native operation, and retain the predecessor and successor together.

The handover contains the configured source, operating guide, original dependency lock and license notices, complete native workspace archive, and a receiving walkthrough. A designated staff operator reopens the archive in a fresh process, inspects the same records and plans, downloads original files, and reconnects with the institution's own environment credentials.

## Ten-business-day delivery sequence

| Period | Complete outcome |
| --- | --- |
| Days 1-2 | Agree repository, two collections, source cohort, field disposition, actual submission sections, operator and reviewer; receive the original source. |
| Days 3-5 | Configure the complete retained workflow; integrate original metadata, collection, file, draft, and recovery operations against the institution's agreed service. |
| Days 6-8 | Run the agreed native cohort, incorporate the two review/correction cycles, and receive the corrected results with the designated reviewer. |
| Days 9-10 | Complete original-file and workspace receiving, staff walkthrough, source/configuration handover, and operating notes. |

The delivery clock starts when the agreed source sample, authorized repository access, target collection identities, and designated reviewer are available. A changed institutional schema or expanded cohort is priced and scheduled with 4Science before extending the delivery.

## Acceptance

The following receiving outcomes define completion:

- The agreed item cohort and file manifest reconcile to their exact retained source identities, with any expressly deferred records listed by native UUID and reason.
- Every approved metadata change has its original value, reviewed result, named reviewer, and original native return available. Generated relationship values remain attached to their native entities.
- The selected draft workflow uses the institution's configured sections and can be resumed against the same created draft.
- Uploaded originals are received from the native repository and match their retained content digests.
- An interrupted operation is reconciled against its original repository and user; already completed objects and files are identified from the original responses and inventory.
- The designated operator reopens the complete handover in a fresh process and recovers the same selection, decisions, original files, and execution history.

## Payment, support, and ownership

The proposed payment milestones are **$3,200 at scheduling and $3,200 at completed receiving**.

Fourteen calendar days of correction for reproducible defects in the delivered implementation are included after receiving. We acknowledge a reported defect within one business day and provide a correction plan using the retained original operation. Additional institutional workflows or ongoing operating support can be agreed separately.

The institution retains its repository, content, accounts, and deployment configuration. Source for the delivered workspace and included upstream implementation is provided under the included AGPL notices. 4Science can maintain and operate the delivered source, with the license obligations carried forward.
