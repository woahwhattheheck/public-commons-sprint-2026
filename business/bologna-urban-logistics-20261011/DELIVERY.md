# Bologna delivery workspace

The application joins the retained loading-bay baseline to a source-linked
assessment and D1–D5 delivery workflow. Open the original workspace with:

    python3 workspace/server.py serve --state /private/bologna-assessment --port 0

Use the printed local address. Existing workspaces open with their original
source, observations, decisions, survey responses and publications. The delivery
screens use that same saved assessment and revision.

## Operating sequence

| Section | Work retained | Useful outcome |
| --- | --- | --- |
| Source baseline | The original municipal source and 21 priority-street points | Inspect the four streets, dated space counts, source digest and actual point positions |
| Evidence review | Original observation decisions, analytical assumptions and a delivery source register | Connect subsequent records to exact municipal material, interview notes and methodological references |
| Method and tools | URBANE Radar and CERT Cityqore compatibility, value, guidance and the agreed analytical method | Retain the inception approach and its municipal agreement |
| Scenario assessment | Bilingual scenario definitions, exact five-criterion reviews and a separately recorded municipal selection | A source-linked D2 comparison and selected scenario set |
| Street frameworks | Bilingual operating measures for all four streets, source references and municipal validation | Retained D3 street-by-street implementation tables |
| 2030 roadmap | Phased measures, derogation criteria, conceptual incentives, ownership and governance | A pilot-to-ZTL transition and replication framework |
| Stakeholder input | Survey plan and Italian instrument, supplied interview findings, original response entry and up to two Italian presentation sets | Source-linked municipal engagement material and analysis |
| Learning and reports | English authored pages, original supplied CESF template and section-bound answers | Learning note, factsheet and template-based final report |
| Export and publication | Working exports and immutable retained assessment editions | Complete deliverable ZIP and separate report downloads |

Each save updates the displayed revision. A reviewed record keeps its named
reviewer and selected source references. Source dates remain attached to the
observations and records that use them.

## Source baseline and evidence

The baseline page displays the original June 2022 municipal observations. The
geographic panel plots the retained WGS84 coordinates with a north indicator and
separate street tones. The street filter shows the underlying source rows, civic
numbers, recorded spaces, category, layout and coordinates.

The original dated Via Lame / Via delle Lame observation review remains in
**Evidence review**. Record the relationship and its supporting evidence in the
original decision form.

The delivery source register supplies reusable references for every new delivery
record. Add a stable source ID, title, original HTTP(S) URL or retained
page/record locator, source date, use conditions and interpretation. IDs accept
letters, numbers, dots, underscores and hyphens. Original RfP, loading-bay and
Tram Bologna references remain retained originals; add a new dated source when
later material becomes available. Added references can be revised in place.

## Inception method

In **Method and tools**, assess both of the municipal tools named by the RfP:

- URBANE Impact Assessment Radar;
- CERT Cityqore digital twin.

For each, select the actual decision and describe data compatibility, added
value and municipal operating guidance in English and Italian. Record the
agreed analytical method, municipal agreement reference, source references and
reviewer. The available decisions distinguish use, use with limits, lack of
suitability and current unavailability.

## Scenario comparison and City selection

The D2 table uses the five named assessment criteria: traffic, emissions,
public space, operator acceptance and market readiness.

Select a retained scenario to author its definition, delivery organisation,
vehicle types, infrastructure concepts, innovations and comparable European
practice. Each criterion has a qualitative rating and bilingual reasoning.
Select the actual source references used and retain the review status.

The municipal selection is a separate record. Select one or more retained
scenarios and record either a proposal or an actual municipal decision. A
recorded decision includes its date, record or minutes reference, and the person
recording it. The selection remains visible independently of the analyst's
individual scenario ratings.

## Street plans, roadmap and governance

The four-street overview reports the source totals, linked scenarios, review
status and municipal validation. Select a street and record:

- access rules and loading/unloading time windows;
- vehicle criteria and dedicated delivery spaces;
- conceptual micro-hub, locker and delivery-area references;
- integration with tram works and pedestrian use.

Each measure has separate English and Italian fields. Retain source references,
reviewer and the actual municipal validation date, reference and recorder when
available. Native street-plan records from the earlier application remain
visible in the original-plan panel.

The roadmap adds retained milestones for 2026–2030. Each milestone names its
scope, scenario set, measure, temporary derogation criteria, conceptual
incentives, responsible role, sources and review status. Choose **Edit
milestone** to update the original saved record, or **Add another** to create a
separate milestone. The same page retains the original native roadmap.

The governance editor covers replication, enforcement, roles, 2027 SUMP,
Parking Plan, tram and charging-plan alignment, and monitoring. These records
travel into the framework export with the street plans and milestones.

## Stakeholder inputs

The Italian survey-plan editor retains audience, municipal coordinator,
distribution plan, one coordinated reminder plan and the municipal reference.
The recorded reminder date refers to the completed single round. Add Italian
questions with free-text, single-choice or whole-number answers. Single-choice
questions require two or more distinct options, entered one per line.

The original supplied-response form remains in the same section. It records
a non-identifying respondent ID, language, role, deliveries per week, reported
constraint, analyst note and supplied consent. The response count remains tied
to those actual records and the RfP's 30–50 target.

Municipality-supplied interview analysis records its source title, bilingual
findings and implications, relevant streets and scenarios, source references
and reviewer. The summary form complements the maintained original interview
intake and coding tools.

Up to two Italian public-meeting material sets can be retained. Each set
includes its title, audience, Italian body, source references and municipal
meeting reference. Select an existing set to revise it.

## Authored documents and the original CESF template

The learning editor supports up to ten authored English pages. The factsheet
supports up to two. Add each page's heading, complete text and cited source
references. A page accepts up to 4,800 characters. Pages can be revised or
removed before saving the complete document.

Download the document and inspect its actual print preview before treating the
physical page count as final. The export supplies page structure, but long
headings, paragraphs or source lists can affect pagination in the chosen
printer or PDF renderer. Keep the learning note within the stated maximum and
the factsheet within one or two physical pages.

For D5, retain the template actually supplied by NZC. Paste its original text or
load a UTF-8 text file, enter the received date and source URL, and map its
original section IDs and headings. Each heading must occur in the retained
template. Saving retains the original text and its digest. Complete the English
responses against those original section IDs and select each answer's sources.

The template's supplied text and the authored answers remain separate. Existing
history and retained publications preserve earlier versions when the template
or answers are revised.

## Saved work, drafts and concurrent edits

Entered form drafts remain available while switching sections or refreshing
saved work in the same browser tab. This includes added or removed survey
questions, document pages and template-section mappings. **Restore saved
fields** discards that form's entered draft and shows its retained version.

Use a form's save button to retain the work across closing and reopening the
browser. Unsaved form drafts are held in the current tab.

When another operator has advanced the workspace, a stale save preserves the
entered draft and refreshes the current saved revision. Review the draft against
that revision and save again. Successful saves show the new revision in the
header and a message in the workspace. Network or validation errors leave the
entered content available.

New milestones, interview summaries and meeting sets retain a stable record ID
while the form is being saved or retried. Editing an existing record continues
that same record.

## Working downloads and immutable publications

**Export and publication** offers the current complete ZIP, bilingual
assessment, street framework and roadmap, learning note, factsheet and CESF
report. Coverage is calculated from the retained content and helps locate
unfinished sections; working drafts remain exportable.

**Freeze current revision** creates an immutable assessment publication.
Publication download links include the exact retained publication ID, so later
workspace edits do not change that edition's report or package.

The existing command line also exports a retained edition:

    python3 workspace/server.py export \
      --state /private/bologna-assessment \
      --out /private/bologna-delivery \
      --publication RETAINED_PUBLICATION_ID

The original backup and create-only restore commands preserve the joined
assessment:

    python3 workspace/server.py backup \
      --state /private/bologna-assessment \
      --out /private/bologna-backup.zip

    python3 workspace/server.py restore \
      --archive /private/bologna-backup.zip \
      --state /private/bologna-restored

Open the restored directory through the same server command. Original source,
decisions, native street/roadmap records, delivery history and retained
publications reopen together.

## Source and integration

The original workspace model remains the revision, locking, publication and
backup authority. The additive delivery model provides source-linked authoring
and retained history. The browser uses the same state and action endpoints, and
the exporter resolves either the current saved assessment or the requested
frozen publication.

Source files for this interface are
`workspace/public/{index.html,app.js,delivery.js,style.css}`. The retained
backend and export integration is in the original server/model with
`workspace/delivery.py` and `workspace/delivery_export.py`.

The original source register includes NetZeroCities RfP SGA3-MCCC-029,
sections 3.4 and 3.11, and the retained municipal and Tram Bologna references.
Source material and municipality-supplied operational records stay in the
assessment's original data location.
