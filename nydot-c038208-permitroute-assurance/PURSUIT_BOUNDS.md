# Pursuit / evidence boundary

## Verified source state

This carrier is built from public procurement context and synthetic data. It is designed to demonstrate the engineering seam before any buyer authorizes project access.

## Authority ceiling

At source-publication time:

- `customer_data_used = false`
- `nydot_acceptance_verified = false`
- `prime_bid_verified = false`
- `contract_awarded = false`
- `invoice_issued = false`
- `payment_received = false`

Those values must not change merely because code is merged, a buyer replies, or a proposal is sent.

## Buyer / procurement claims deliberately avoided

- No claim that Flairsoft is bidding C038208.
- No claim that TokenJunkieLabs / Bryce is an NYSDOT vendor for C038208.
- No claim that this schema matches NYSDOT production data.
- No claim that synthetic tests satisfy contract acceptance criteria.
- No claim of award, subcontract, invoice, or revenue.

## Safe next step

A qualified prime/implementation partner may review the public harness first. Only after a real engagement and authorized access should project-specific adapters, customer field maps, or production-derived fixtures be created.

## Outbound mutex

Before contacting a named buyer/partner, re-census Slack/Gmail and request the single-writer election from Muse. One elected sender, one bounded message, no duplicate hot-lead traffic.
