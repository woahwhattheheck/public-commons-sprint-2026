# Prepare complete promotional and follow-on lead packs

## Current offer
For a new prospect, prepare five complete profiles as the free promotional pack. Set config.pack.brief.sample_quantity to5. When a distinct follow-on cohort is actually researched, prepare its five profiles at US$20.00 total by setting config.pack.brief.quantity to5, currency toUSD and price_minor to2000 US cents. Existing records that omit sample_quantity keep their original one-profile sample, exact hashes and delivery history. Existing complimentary editions retain their recorded full quantity and included editions.

## Required reviewed source
Use one complete preparation-input JSON containing cohort, config and guides. cohort contains customer, prepared_by and a complete free array. The default free-and-paid mode also requires a complete paid array; sample-only mode is described below. Each profile supplies company, person or business role, area, current_workflow, product_fit, demonstration, qualification, a complete tailored opening, contact_page and original sources; add the actual published email and phone where available. Keep buyer qualification and existing-customer exclusions with the original source. The compiler checks the exact declared quantity for each selected cohort, distinct company domains across the supplied profiles, buyer consistency, complete sources and any promised contact coverage.

Retain stable pack, lead and edition IDs, original company/case and sender, actual UTC preparation time, recorded geographic scope and complete customer guides in config/guides. The price is per complete paid pack. The free promotional edition has zero price. Read the current case and delivered roster before selecting the next distinct paid cohort.

## Prepare and independently reopen
Run from this complete source directory:

```sh
node native/prepare-cohort.mjs /absolute/path/preparation-input.json /absolute/path/Prepared-Cohort
node /absolute/path/Prepared-Cohort/native/reopen.mjs /absolute/path/Reopened-Cohort
```

Each output directory must be new. In default free-and-paid mode, preparation applies the original four operations through the maintained core, independently receives the complete working record, emits eight customer files in HTML/CSV/JSON/Markdown, writes both complete customer ZIPs, and retains the complete runtime, preparation input, configuration, source, original operations, record and guides. Reopening replays the exact original operations and independently reconstructs the saved record and all eight customer files. The original case and its actual send history remain with the existing writer.

## Original delivery and repeat fulfillment
The producing owner opens and uses the actual customer HTML and every ordinary output/ZIP, including desktop and390px where relevant, before the original sender delivers the free promotional pack. Preserve the exact delivered files and provider identity/time in that case. Route favorable replies to the designated human relationship owner and continue preparing the distinct next five internally according to the current account instruction. Use the current lead_repeat_order.cjs and original native writer for repeat fulfillment in an existing customer workspace; preserve every earlier sample, complimentary and paid edition and all actual payment/delivery events.

## Composition boundary
The compiler and native preparation entrypoints use this toolkit's complete runtime/ engine. The optional sample_quantity is retained only when explicitly supplied. Full-pack wording and all courtesy/inclusion/repeat branches remain available. Maintain these entrypoints and their runtime as one source closure; preserve customer-specific research and messages in their original cases.

## Complete first five without paid inventory

Set config.cohort_mode to "sample-only" for the initial complete promotional pack. Set config.pack.brief.sample_quantity to 5, provide exactly five complete cohort.free profiles and five stable config.lead_ids, and provide config.editions.sample and guides.sample. Omit cohort.paid or use an empty array. No paid edition, paid guide or paid filename stem is required. Nonempty paid inventory is rejected in this mode so none is silently dropped. The brief's quantity/currency/price_minor retain the actual future offer, such as five for USD 2000 cents; they do not create a paid edition.

The same two native commands prepare and reopen this mode. Preparation records three original operations, emits four customer files (sample HTML/CSV/JSON/Markdown), writes one five-member sample ZIP, and retains the complete original source, input, configuration, record and history. Reopening independently receives the record and reproduces all four outputs. Regeneration uses the retained mode and touches only the prepared edition. The core, installed UI/controller, existing records and actual sends remain unchanged.

Omitting cohort_mode retains the original free-and-paid behavior: both actual cohorts are required, four preparation operations, two editions, eight customer files and two customer ZIPs. Explicit "free-and-paid" is equivalent. Unknown modes fail before preparation. A partial free cohort is always rejected.

Prepare actual later inventory through the original customer's existing repeat-fulfillment workflow, preserving its delivered first five and all prior editions, payment/delivery events and history. This new-customer compiler is not a replacement for an existing customer ledger. Full inline first-contact delivery can use the complete researched profile text; any separately delivered attachments follow the current producing-owner inspection course.

## Retain the actual first inline delivery

After the original sender sends and reads the full actual Gmail SENT message, use native/record-delivery.mjs with the original complete source directory, complete delivery input and a new output directory. It appends the original core's event or reconciles an already-recorded identical provider event, preserves every original operation and customer output, retains the full native message and inline body, and carries existing ZIP bytes into the whole source bank. Current native reopen checks the actual message/body against the original event. Full input, recovery and legacy history details are in source/RECORD_DELIVERY.md.

## Direct source of an observed workflow

A profile may supply signal_source_url equal to one of its retained sources URLs. The compiler uses that exact URL for the customer’s Source link while retaining the company domain and homepage from sources[0]. Omit it to preserve the original homepage-source behavior. A dated article, release note or guide can therefore be opened directly from the first message without changing the company identity. An unretained source URL is rejected.
