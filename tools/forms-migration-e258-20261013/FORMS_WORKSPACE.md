## Author a complete mapping

Create a named draft from the chosen capture. It starts with the complete original inventory, six-class scope and existing attachment worksheet. The original discovery manifest and migration selection begin as visibly unfinished mapping inputs.

Work through the whole selection:

1. **Source authority and interpretation.** Give the selected edition its actual label, source owner and authority reference. Record the complete population and the interpretation of the proposed comparison.
2. **Original tables.** Bind each selected CSV table to one exact present asset. Preserve its path and hash. Declare every actual column in order, type, required flag, trimming and literal null values. Select original primary and foreign keys deliberately.
3. **Source/target pairs.** Choose actual source and target tables from the same selected class. Give the pair ordered keys, compared fields and reviewed semantic references. A target-side parent or table cannot quietly point to a source-side original.
4. **Crosswalks.** Select the actual complete crosswalk table and ordered source and target columns. Its key types and arity must agree with the original selected sides. Duplicates, collisions and incomplete mappings remain actual findings.
5. **Field meanings.** Text, integer, decimal, date and Boolean comparisons use the maintained native rules. Decimal transformations and tolerance are exact rational selections with explicit references. Dimensions such as currency must match before numeric equivalence is evaluated. No implicit currency conversion or rounding-to-match occurs.
6. **Opaque originals.** Add explicit whole-file comparisons for definitions, settings or other opaque originals. Byte equivalence has its own meaning. It is separate from a supported vendor import route.
7. **Attachments.** Preserve or deliberately author the original entry and logical identities, sides, canonical form/response/field/ordinal, body availability and exact parent table/data ordinal/raw key values. Parent inference from filenames or ZIP paths is not used.
8. **Scope and coverage.** Give all six classes an include/exclude/defer decision and source reference. Record supported routes, reviewers and decisions as actual source metadata. Each included asset needs its own examination; one compared file does not cover every other file in that class.

The complete raw intake remains available throughout this work. Extra original interpretation fields remain in that complete document. The structured controls operate on the same selection rather than maintaining a separate hidden mapping.

### Save unfinished work and preserve earlier decisions

A draft can contain invalid or unfinished JSON. Save retains the complete original UTF-8 text, its name, selected capture, native revision and original request. The current size limit is 128 MiB of encoded raw text. A saved revision is never silently truncated.

Each save names the exact revision the operator opened. A second tab or client cannot replace a later native revision using an old one. Preserve the losing draft as a complete local or downloaded working copy, open the current native history and explicitly choose a new copy or a reviewed following revision.

Every prior native draft revision is available in the history and can be downloaded in full. A same-capture fork preserves unfinished raw text exactly. It does not require a parse merely to preserve a working copy.

Numeric source text remains literal until deliberately assigned a native type. The browser's structured JSON editor must reject duplicate keys and numbers that cannot survive editing without loss. The native raw text and its downloadable copy remain the recovery source.

## Validate and calculate the selected edition

Native structural validation uses the original Forms intake, discovery manifest, migration selection and class/side binding validators. It also requires the selected asset inventory and each CSV path/hash to match the retained capture.

STRUCTURE_VALID means those structural rules pass. The actual full source scan, row quality, duplicate groups, exact field results, attachment parents/bodies and per-asset coverage are calculated by **Run edition**.

That one original native request performs the entire operation:

- Freezes the exact saved draft and selected capture.
- Runs the original complete Forms calculation into a new immutable project.
- Verifies the computed project and original selected source.
- Packs the whole project with its unchanged native application.
- Independently receives that complete archive and verifies the returned project identity.
- Saves the actual result, archive identity and original request alongside the earlier editions.

It preserves source-only and target-only records, invalid or duplicate groups, unavailable bodies, wrong parents, incomplete content and explicit exclusions. Findings are useful review material; they do not automatically rewrite an original or mark a customer acceptance.

Open the calculated project through its actual original inspector receipt. The workspace uses the unchanged Forms inspector for full source records, findings, exact parent drilldown, native row/total views and whole exports. The independently received edition is separately selectable. The service preserves actual child process ownership and its current receipt when reopening the same run.

### Original requests and interruption recovery

Before dispatch, retain the complete operation body and a stable request ID. The same request ID with the same method and parameters returns the original completed result or resumes a process-interrupted operation from its frozen inputs. The ID cannot be repurposed for another body.

The native database commits each draft change or published run together with its original request result. Deterministic output locations and exact source checks recover a native calculation or archive that completed just before a process interruption.

A returned failure remains that request's recorded failure. Correct the cause and issue a new explicit operation, preserving the earlier inputs and partial outputs. A process loss before completion leaves RUNNING and retains the exact frozen input for its original recovery.

During a long run, request.status reads the original request through a separate read-only SQLite connection. Its phases describe actual returned native stages: source receiving, completed source receiving, native calculation, completed calculation, packed project and independent receiving. A displayed percentage is not invented from elapsed time.

## Continue an existing workspace after a maintained source update

A calculated project binds its original program, and a workspace retains the
42-file program that created it. Updating HTTP or presentation must preserve
both. The supported update operation leaves `workspace.json`, its database
identity/revisions, every capture, draft history, request, project, project ZIP
and the private HTTP origin unchanged. It retains complete original and updated
programs as separate `source-editions/` members.

1. Keep the original complete source directory and receiving/browser output.
   Materialize the complete new source into a **separate** directory. Do not
   replace files in the original source directory or rewrite old receipts.
2. Stop the actual workspace server gracefully after its current request
   finishes. The workspace's existing process lock prevents concurrent adoption.
   Its owned inspectors should close through the existing shutdown path; retain
   all private origin, lease, receipt and browser-profile files.
3. From the complete new source directory run:

   ```sh
   python forms_workspace.py adopt-source \
     --workspace /absolute/original/workspace \
     --original-software /absolute/original/source
   ```

   The command verifies the original 42-file selection, all captured/project
   contents, each calculated edition's actual retained program, and the absence
   of a native RUNNING request. A browser PREPARED upload is not a native running
   calculation. Import/calculation engines must remain byte-identical; this
   update path admits maintained HTTP, renderer, workspace, guide and receiving
   code. Both complete source editions are copied and checked before their
   immutable selection record becomes available. Repeating the command with the
   same files returns the same adopted directory.
4. Start the updated `forms_workspace_server.py` with the **same** workspace
   and a **new** private receipt path. Its original private controls retain the
   same loopback port and access token. The receipt and `workspace.describe`
   expose the original `source_files` and separate `runtime_source_files`.
   The original receipt remains usable as the retained URL; its historical PID

5. Resume the existing browser using its original selected helper, original
