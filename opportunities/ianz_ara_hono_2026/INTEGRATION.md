## Maintained host interface

The source integrator published the current interface in the original company thread at 1791845236.755009:

- Project(directory, create=False, target_adapter=None).
- dispatch(command, payload), with operation_id, expected_revision and actor.
- Original accepted request replay returns its original result. The same Project instance owns one background native operation.
- The target adapter factory supplies submit(original_request, full_package_path), lookup(original_request), request_shutdown() and close().
- HTTP routes include /api/snapshot, /api/entities, /api/record, /api/history, /api/object, /api/assets and /api/dispatch, pinned original downloads, full import/handover export and new-directory receive.

The maintained financial calculation is app/ianz_billing.py: calculate(payload, tariffs), run_controls(document, tariffs), and reconcile(source_lines, returned_lines, fee_profiles, policy). The financial operator contribution uses apply_command(state, command) and mountFinancialMigration(element, {read, command, exportFile}). Source review and adapters should preserve those accepted interfaces and the original project.

## Complete source contributions

schema.py, seed.py, mapping.py, workspace.py, server.py and cli.py preserve the complete 018A source receiving, per-field provenance, immutable edition, typed mapping, original request, native comparison and portable reopening implementation. Their Workspace/HTTP interface is an integration reference for bringing concrete behavior into the maintained Project. It has not been commissioned as a separate native application.

reference_receiver.py and RECEIVING.md provide the complete actual SQLite target receiver. It assigns real stable native IDs, stores typed records and original source metadata, resolves relationships in a second pass, retains full document/source assets and visibility, preserves the original immutable request/package/result, records explicit corrections under revision checks, and exports the complete selected request cohort. Its adapter will bind to the maintained target factory once the complete original request/package contract is received.

billing.py and BILLING.md provide the complete exact financial source contribution. calculate_bill and reconcile_billing retain original/canonical lines, explicit group identity and policy, source credit components, rational calculation, cap and rounding allocation, original-versus-returned differences, and separate missing authored-source readiness. It is being compared to the already accepted maintained financial engine; it does not supersede that engine by being present here.

documents.py and DOCUMENTS.md are the document arm's forthcoming complete contribution. Their interface is inspect_document(original_bytes, filename=..., media_type=...), render_docx(template_bytes, mappings, records), and compare_documents(expected, returned). They preserve full native DOCX controls, repeated groups, exact table cells, headers, footers and package relationships, with no database or network side effects.

All modules use the Python standard library. The pure financial and document engines do not own the application store. The ReferenceReceiver owns its separate named target database, as an actual local receiving target for the maintained application.
