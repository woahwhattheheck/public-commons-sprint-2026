# Receive original scenario Parameter reports

This course finishes the original Ensemble-to-Parameter report workflow with one resumable command. It adopts the original completed native runs, prepares one ordered scientific report containing each selected scenario's Parameter study, exports the complete editable Study, restores it, and opens the retained study and report in a fresh interpreter from the transported application.

The course keeps each scenario fixed while comparing that scenario's original parameter profiles. Land-cover effects remain in the original Ensemble. Nitrogen and phosphorus retain kg/year, sediment retains tonnes/year, and the report retains the original paired-cell support, undefined percentages, input declarations and figure source coordinates.

## What completes

The command uses the existing producer and native APIs in order:

1. Continue the retained original bridge and verify the completed native case roster.
2. Freeze each Parameter specification, result descriptor, original case/run/profile IDs, model families, scenario and source provenance.
3. Register each scenario's current complete scientific source. Completed source IDs remain pinned on resume.
4. Preview, render and export one ordered SourceReports edition through the maintained shared renderer. The current source declarations and original figures travel with the selected numerical rows.
5. Export one selected Study rooted in that scientific report. The maintained Parameter lineage collector includes its editable studies, native selections, scientific inputs, report sources and original outputs.
6. Restore the Study with the ordinary NativeProjectTransfer service.
7. Start the receiver from the **restored application's own source** in a fresh Python interpreter. It reopens the original study specifications, case/run/profile selections, result hashes, source editions and report files, then checks that the received Study exposes the same report.
8. Write `START_HERE.html` over the actual restored report and original quantitative exports.

No new native model calculation is issued by this course. If a retained Parameter aggregation is unfinished, its original summary mechanism resumes from the retained native outputs. Raster difference exports likewise use the existing original outputs.

## Resume the same operation

Repeat the original command with the same operation directory and arguments. Completed bridge studies, report sources, rendered report editions, Study archive and receiving directory reopen under their original IDs. The current native transfer service verifies retained archive members and preserves recipient work. A changed original result or scientific selection surfaces directly rather than silently replacing the frozen report.

The course saves its phase before each operation. A lost reply after a completed report is reconciled from the original retained preview and native report operation. Source-formatting code may advance while an incomplete source phase is retried; already saved source IDs stay pinned. The selected native runs are never rebuilt to satisfy a report-formatting update.

Read the exact phase and exception in `state.json`, and the named file under `fresh/` for a fresh-process failure. Fix that concrete source or environment problem and repeat the same command. Each actual attempt records start/end times and measured elapsed seconds. Those are report/transfer execution times, not substituted native-model timings.

The operation does not open an operator URL, change a managed browser policy, launch another runtime service, send client communications or restart a running scientific cohort. Use the original equipped browser owner's existing application at its normal receiving boundary.
