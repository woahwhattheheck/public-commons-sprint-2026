# Workspace file operations on Windows

The operator can import its workspace primitives on Windows without importing the POSIX-only `fcntl` module. The same existing content identities, immutable publications, source verification and project paths remain in use. This does not install or replace the scientific model runtime.

`model.host_files` supplies file opening, metadata, locking and durability operations. POSIX uses `flock`, `O_NOFOLLOW`, nonblocking regular-file opens and directory `fsync`. Windows uses the standard-library CRT byte lock for actual cross-process exclusion and a native `CreateFileW` handle opened with `FILE_FLAG_OPEN_REPARSE_POINT`. The opened handle is inspected before use; reparse leaves, directories and other nonregular objects are rejected. Handle sharing permits the existing atomic replacement and verification path to observe concurrent changes. A nonblocking lock raises `BlockingIOError` on contention. A blocking lock waits until release, rather than stopping after the CRT's ten fixed retries. Lock files remain empty.

File contents are flushed before publication on both hosts. POSIX additionally flushes directory metadata. Ordinary Windows file handles do not provide the POSIX directory `fsync` contract; `sync_directory` explicitly returns `False` there. Windows therefore provides flushed file data and atomic visible replacement, with no claim of equivalent power-loss durability for directory metadata. Interrupted receiving still uses the existing source hashes, pending paths and retained-object reconciliation. Do not count source download, operator startup or these file operations as an executed NDR/SDR model run.

Implementation references: [Python CRT file locking](https://docs.python.org/3/library/msvcrt.html#msvcrt.locking), [CreateFileW handle flags](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), and [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).

Windows retained-file comparison opens the selected leaf through the same no-follow handle API used by its stream. This avoids Python 3.12’s different path-versus-handle meaning of ctime without dropping change-time checks. Existing retained objects are opened with write access when their data must be flushed by the Windows CRT; read-only result verification remains read-only. The focused receiving command is `python -B integration/check_host_files.py`. It exercises actual cross-process contention/release, immutable publication, retained input reopening and changed-body rejection after mtime restoration. Symlink creation may be unavailable to an ordinary Windows account; the command reports that specific gap rather than claiming it passed.
