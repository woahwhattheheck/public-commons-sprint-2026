# Receive and install the complete Upper Savannah application

This edition composes the maintained scientific Workspace, authenticated operator,
current source and run desks, saved assessments, programme execution, interpretation,
community planning, project continuity, editable GIS, retained economic decisions,
land-cover ledgers and original-source refresh. The scientific project directory
remains the place where its original inputs, selections and completed native outputs
are opened.

## One cumulative installation

Receive the full application source bank into a source directory. The numbered
gzip/base64 carrier is accepted by the included source receiver. Use the scientific
Python environment that runs the retained project's actual native models.

From a received source directory, create an independent installed application and
its whole ZIP:

```sh
/opt/pyvenv/bin/python -B source_tools/install_cumulative_application.py \
  --source /mnt/data/upper-savannah-source-2 \
  --output /mnt/data/upper-savannah-installed-2 \
  --archive /mnt/data/upper-savannah-installed-2.zip
```

The three paths are explicit receiving locations. Select the actual paths on the
receiving machine when its mounted directories differ. The installer uses a fresh
staging directory, applies the component authors' existing source transforms, restores
the embedded original input bytes, checks the combined Python source and browser
module, then publishes the installed directory. The complete ZIP is made from that
installed directory.

The same command reuses an identical installed edition. A changed source bank uses
its own receiving directory. The returned JSON gives the mounted application path,
actual file count, source identity and complete archive path, size and SHA256.

## Preserve the selected edition's original sources

The cumulative installer validates the selected
`integration/application_components.json` before applying authored transforms,
then checks the installed result after restoring its original embedded input bytes.
Reusing an existing output performs the same component validation before archive
publication. Preserve the maintained catalogue and `source_tools/application_components.py`
when receiving a successor source bank.

Components' `source_manifests` identify the native `upstate.sources/v1` manifests
that belong to this application edition. Their primary files and every companion
must remain under the manifest's own directory, with the original declared hashes.
The checker includes native CSV, GeoJSON and binary companions even when they are
not Python or browser assets. The installation report returns the inspected
manifest paths and original source IDs together with their member identities.

The installer continues to use each component author's maintained transformations.
A changed source bank or explicit edition catalogue uses a fresh output/archive
name. A deliberately partial application carries its own catalogue selection; keep
that selection explicit rather than labelling an omitted family complete.

## Open the retained scientific project

Launch the combined operator with its existing original Workspace:

```sh
/opt/pyvenv/bin/python -B /mnt/data/upper-savannah-installed-2/operator/server.py \
  --workspace /mnt/data/eco12-run/receiving \
  --operator-state /mnt/data/upper-savannah-operator-state
```

The Workspace path above is the existing ECO12 receiving location from the sprint.
Use the host's actual retained project if it lives elsewhere. The server prints its
loopback address and authenticated receiving information. Open that actual address
in the host browser.

The installed shared extension host also accepts repeated `--source-root DIRECTORY`
arguments for original source directories available to the source desk. Each source
selection retains its declared collection, source identity, geography, physical units
and reading mode.

## Native workflow and completed model reuse

The original profile and grid forms expose NDR, SDR or both engines. A grid can retain
and extend its already prepared source roles. Explicit `resolution_m` preserves an
original sample's native grid; omission keeps the regional 30 m default.

Completed NDR and SDR results can be assembled through the maintained
`Workspace.combine_runs` interface. Explicit prior native stages also enter the
existing run method through `reuse_source_run_ids`; the matcher checks actual physical
inputs and the receiving runtime before the original stage importer copies results.
The core run ID continues to identify its scientific selection. Execution choices and
original reuse provenance are retained separately in the saved run.

The native run desk, saved programme editor, source preparation, scientific
interpretation and utility cohort launcher operate on the same retained source
collections and native run records. Current source preparation offers direct reading
of the original national NLCD ZIP and retains complete task-request history.

## Continue work in a received project

Open **Project continuity** and create a complete project from the selected Workspace.
Its transfer includes original scientific files, completed work and the selected
unfinished operation history. Download the completed transfer ZIP, receive it through
the same desk, switch to the received Workspace, and inspect its retained history.
Resume an appropriate unfinished operation through the original action queue.

The active continuity panel refreshes from the current registry's available actions
and retained transfers after task completion. Completed source and model results
reopen through their existing writers and original archive identities.

Saved scenario assessments retain their selected methods, source operands, table
settings and revisions. Large assessment saves use the original resumable transport;
the economic and land-cover desks open retained reports through the typed file host.
Editable GIS members retain their original member checks and authenticated preview
route. **Source refresh** opens from the original source navigation and submits work
through the original queue.
