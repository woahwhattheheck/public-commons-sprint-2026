# Receive a saved original source reference

This command completes an original reviewed worksheet reference through the maintained workbench API. It saves one CONTEXT source edition, receives the readable inspection and original workbook, exports the selected source collection as an editable Study, restores that Study through the same operator and reopens its source in a fresh Python process from the transported application.

The command uses the existing operator. It preserves its native task queue, retained source identities, original completed inspection and previously saved source editions. The selected-source Study includes the original source manifest, every retained body and companion, and the saved original worksheet inspection. It reopens without the donor client-source-intake directory.

## Installed source and invocation

Use the application's qualified Python and current source:

- source_tools/receive_saved_source_reference.py
- model/study_transfer.py with source collection root admission and catalogue
- current model/client_source_inspection_report.py with retained_table_preview and the original-XLSX source-info branch
- the existing operator/workbench_client.py and model/retained_download.py API family

The source collection root reuses the original immutable dependency visitor and portable Study writer. The existing Study catalogue lists Source collections alongside its other saved kinds.

Keep the current API family from the native application. The local receiving command works with its maintained freeze, submit, task, wait, resume, upload and download methods. It does not replace the client's HTTPS staging continuation.

~~~sh
python -I -B APPLICATION/source_tools/receive_saved_source_reference.py \
  --connection PRIVATE_NATIVE_OPENING.json \
  --inspection ORIGINAL_INSPECTION.json \
  --reviewed-selection ORIGINAL_REVIEWED_SELECTION.json \
  --inspection-id ORIGINAL_INSPECTION_ID \
  --file-index 0 --part-index 2 \
  --title "Original worksheet reference" \
  --output RECEIVING_DIRECTORY
~~~

Use the installed application and exact original worksheet positions. The private native opening JSON contains origin, operator_url and workspace_key. Keep it outside outgoing deliverables. The command reads the capability in memory.

Alternatively, --original-delivery ORIGINAL.zip replaces the two JSON-file arguments. It finds the original completed inspection and reviewed selection by schema and exact inspection identity, deduplicates equal records and rejects ambiguous choices. The reviewed selection's original inspection digest must match the complete inspection before a save is issued.

When the existing operator has no registered copy of the original project, also pass --workspace-archive ORIGINAL_WORKSPACE.zip and --expected-workspace-sha256 ORIGINAL_SHA256. It restores that unchanged archive through the same original operator. If several copies of the original project are registered, --workspace selects the intended one explicitly.

## Scientific interpretation

The explicit new source meaning is CONTEXT with mapping:{} and the supplied title. Every other reviewed source fact is retained, including original identifier/label columns, units, period, reviewer and the original nonempty model-selection list required by the current schema. That list remains reviewed provenance; it does not dispatch a model or convert the reference into a biophysical input.

The original file remains unchanged. Source-info preserves positional cells, physical row numbers, original field definitions, worksheet, header, preamble, complete reading choices and the native more-rows flag. A native preview with unknown total row count remains a preview.

## Continuation

The receiving output contains the exact original inspection and review, explicit new selection, each frozen API request, every accepted task handle, native source-info responses, original downloads, the editable selected-source Study and the independent receiving result.

Each operation ID is deterministic from the original project, complete input identities, explicit choice and phase. It is written before submission. On restart, the command reads the same native task first. An authoritative missing unaccepted task can submit only that same frozen operation; an accepted missing task requires reconnecting its original operator state. Active tasks are observed, interrupted tasks resume their original handle, and completed tasks reuse their retained results.

After fixing the reported cause of a failed task, --resume-failed resumes that same handle once. A task that remains active past --seconds (default900) keeps its handle and exits with an actionable message. Reinvoke the identical command and output to continue observing it. Download interruptions retain the original checksum-bound prefixes through the existing file receiver.

## Receiving result

Open RECEIVING_DIRECTORY/START_HERE.html. It links the actual readable report, original workbook, reviewed source files and selected editable source package.

The source package is restored through the original workspace.restore API. The receiver then opens source-info on that newly registered project and compares the original worksheet data and choices. A fresh Python process runs the transported application's own receiving command against the received Workspace, checks the original source bytes and retained preview, and verifies that the donor intake directory was unnecessary.

Use the delivered workbench to open its source card, readable report and downloaded workbook. The native/API output supplies the working files and original identities for that actual recipient use.

## Older saved original tables

New selected Study exports also retain the exact completed inspection record required by an older saved original table that predates embedded native previews. This applies to unprojected client-source tables, including CONTEXT and MEASUREMENTS worksheets. The immutable source collection, reviewed selection and original file remain unchanged. The matching `client-source-intake/<inspection-id>/operation.json` and its complete original-file object dependencies are included. Shared original objects are retained once through the existing closure. Upload staging, queue state and unrelated intake operations are not required.

The Study identity records that original inspection's canonical and byte hashes, source identity and selection identity. Receiving validates its original project, complete inspection, file and part positions, original filename/hash, columns and reading choices through the maintained source preview reader. Older Study receipts retain their original dependency rules. New embedded-preview sources continue to travel without any donor intake directory.

For an existing older saved source, use its original collection as the `sources` root through the maintained Study export action. Keep the original source operation and collection; a new inspection or replacement save is unnecessary. The existing Windows saved-source course can first read source-info, export the selected original source collection, restore that archive on the existing operator, and read the same collection/source again.

## Use the normal Study desk

In the existing Study desk, choose **Saved source collections** in the Study type filter. Open a collection to inspect its original native files and worksheet summaries, then select the collection and preview the archive contents. The same export and receiving controls produce and reopen its editable source package. The contents preview explains when an older saved table also carries its original inspection. This uses the original source collection; it does not run another model or import a replacement workbook.
