# Install the Keowee, watershed and scientific setup workflows

This installer applies the cumulative native profile, watershed receiving and scientific setup review work to an existing Upper Savannah application. It composes the two maintained Python entrypoints and original Conservation browser in place, installs the complete scientific setup backend and operator desk, retains the exact original Keowee methodology, upgrades its source-interval evaluator companions through recorded owner editions, and installs the original Gura setup assembler and complete first-case receiving command.

## Install

Run with the receiving application's Python environment. SOURCE is the new application source checkout, and APP is the existing receiving application:

```bash
python -B "$SOURCE/source_tools/install_keowee_watershed_join.py" \
  --application "$APP" --source-root "$SOURCE" --dry-run

python -B "$SOURCE/source_tools/install_keowee_watershed_join.py" \
  --application "$APP" --source-root "$SOURCE"
```

The planning invocation returns the actual changed files, exact resulting hashes, source policies and current native API hashes. The installation invocation performs the same preparation under the existing application/.locks/extension-install.lock.

All package files are checked against the source manifest. Python is compiled without executing imports, JSON is parsed, and all three full edit ledgers must reconstruct their exact published source from their original preimages. The installer stages and flushes the complete receiving plan before any application source is published.

The nine-member Keowee source edition is required. The original 78,447-byte methodology remains SHA256 388f9f7ae3246dd156fad446c616bbf8d3440a09b2edd524c45cef1d6c299da0. Its evaluator, declarations, guide and import manifest have explicit known predecessor hashes for the source-interval implementation. Exact current members are retained; missing members are copied after verification; those four executable/documentation companions upgrade only from their recorded earlier bytes. Before installation the ordinary source-import manifest is checked against every actual companion, and the native binding is checked against both the original profile and current evaluator.

Implementation dependencies and source bindings are published before the modified entrypoints. The new method-view and scientific setup modules are present before the original Conservation browser is changed. Both extension descriptors are published after every implementation member; the scientific setup descriptor is the final registration. Its client module and stylesheet use the current browser host's required /web/ URL prefix; package validation checks both exact paths. When Node is available, the staged JavaScript modules are also parsed with node --check before publication. The source manifest is published last. Missing files use atomic no-clobber publication; updates compare the captured current bytes immediately before replacement. The shared installation lock coordinates with the existing extension installer. A changed or ambiguous owner block is reported without replacing it.

The installer also retains itself, its manifest and this guide under source_tools, which is included by the original application backup engine.
