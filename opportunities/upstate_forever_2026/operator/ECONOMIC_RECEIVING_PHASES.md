## Resume an interrupted native operation

Use the exact printed `native_resume_command`, or:

```sh
"$PYTHON" -B "$APP/operator/economic_receive.py" \
  --phase native \
  --application "$APP" \
  --operator-url-file "$READY_URL_FILE" \
  --output "$RECEIVING_DIRECTORY" \
  --resume-journey "$JOURNEY_DIRECTORY/operator-journey.json"
```

Every first queue POST is preceded by a durable journal entry containing the exact `workspace`, `action`, `payload` and original outer `operation_id`. The original server keys requests by Workspace plus operation ID and rejects a changed action/payload. An uncertain response is retried with that same request. The accepted review's raw bytes are copied and verified before use. Repeating an old command after that same external staging path disappears uses the retained original; a changed file or a different missing path is rejected. Once a task ID is known, the receiver rejoins that task. The server can alias an already active identical request; exact task ID, Workspace, action and payload remain authoritative even when its original task operation ID differs from the alias.

A failed, interrupted or cancelled task is not silently replaced. After addressing its actual failure, repeat the same command with `--resume-interrupted-tasks`. This explicitly invokes `/api/task/resume` on each saved task at most once per invocation. A repeated failure remains visible. A timeout leaves the original task running and preserves its request; it does not cancel or issue a new operation.

The raw Study upload has a retained byte count, SHA256, filename and media type before transmission. The existing server derives its upload ID from that exact tuple. Retrying an uncertain upload returns the same retained upload. The ID is saved before the single restore request; completing an upload is never treated as proof that restoration completed.

Source code changes do not replace a saved preview or completed request. If an unfinished operation is no longer compatible with its original expected identity, the provider's error remains visible for repair. Already completed native IDs reopen as themselves.
