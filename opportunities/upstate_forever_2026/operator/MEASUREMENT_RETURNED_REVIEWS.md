## Choose complete original editions

Open **Measurements → Incorporate returned measurement reviews**. The archive catalog offers complete native study exports and completely uploaded portable projects. Each choice binds its original native ID, byte count and SHA-256; incomplete uploads and changed or missing originals are not selectable. If the three editions are not already saved, use **Open original large-file intake**. For a portable project this retains the complete upload without applying it to the live measured workspace. Return to the review panel and choose **Refresh saved work**. These are complete native archive choices, not CSV populations or filenames used as scientific identities. No source value, detection qualifier, review history or original assignment is rewritten during comparison.

## Interrupted requests and workspace changes

The panel saves the exact action, payload and operation ID in its browser request journal before submission. The native task ID is retained as soon as the server accepts it. **Open original task** remains usable while the operation runs. Closing the panel, leaving Measurements or changing the selected workspace does not cancel an admitted native operation.

Return to the original workspace and choose **Continue original request**. The latest request pointer survives a browser restart. Reentry validates the original workspace, signed-in person, action and payload, then reads the exact native task or reissues the same operation ID if its response was lost. Failed or interrupted work resumes only after this explicit action. Mounting the panel and refreshing its catalog do not submit or resume work automatically.

A file still being read by a closed view cannot dispatch into another workspace. Late task identities remain in their original journal while late catalog responses, notices and DOM updates are suppressed. The original Collections, native-domain, large-file transfer and Chemistry controls keep their existing scoped request handling.

## Native integration

The two read operations are `POST /api/measurement-returned-reviews/catalog` and `POST /api/measurement-returned-reviews/inspect`. Reads include the captured operator workspace key. Plan requests use `measurements.returned-review.plan` with title and three exact `{kind,id,bytes,sha256}` archive choices. Incorporation uses `measurements.returned-review.apply` with the saved wrapper plan ID and original decisions upload ID. The decision document retains the distinct original native `planId`; it is never relabelled to the operator record ID.

Both actions use the existing native queue and task controls. Downloads use the original authenticated file tickets. The unchanged returned-review CLI and engine own every comparison, source constraint and original review mutation. Node 22.16 or newer is required by the original SQLite engine. Reopen the operator after installation so its normal registry loads the new backend descriptor.
