## Open an already completed report

The native standalone renderer retains an editable project capture under `observed-reports/<capture_id>/`. In **Sources → Completed reports retained with this project**, choose **Review completed report**. The preview verifies the original capture, every report file, the ordered retained sources and the original rendering identity. Choose **Add original saved edition** to retain that exact result through the existing operator queue.

Adoption does not rerender the report or execute any model. It copies the original PDF, HTML, report data, figures, source files, selection and operation record into the existing `scientific-report-editions` tree. The ordinary saved-edition controls then open the PDF and HTML, prepare its complete ZIP, create an explicitly authored Customer review, compare it with another edition, and transfer the report with its original editable studies.

Open the retained task if its response was interrupted. The request keeps its original workspace, action, payload and operation ID; the existing queue returns the same operation. A partially copied adoption resumes against its exact original capture. A completed, identical edition is reopened. A conflicting rendition under the same rendering identity is reported without replacing either report.

## Identity and portability

The capture ID and saved-edition ID describe different original records:

| Identity | Original calculation | Purpose |
| --- | --- | --- |
| Capture ID | Native digest of the complete result, excluding `files` and `output` | Addresses the existing project capture |
| Saved-edition ID | Native digest of the original `selection.json` render identity | Addresses the original saved scientific rendition |
| Capture SHA256 | Hash of the exact retained `capture.json` bytes | Pins the reviewed adoption request |

The complete result's `files` mapping stays exact. The capture's additional original `operation.json` descriptor is kept outside that mapping. No source is replaced with today's edition and no renderer identity is recomputed from today's application. Original historical source/output path strings remain provenance, not write destinations.

Each adopted edition embeds the exact capture document, its byte length and SHA256 as `capture_origin`. Original edition inspection verifies that document against its copied selection and operation records. A selected Study archive therefore needs only its ordinary saved-edition tree and declared source/study closure; it does not depend on the donor project's `observed-reports` directory. Full project backups may also retain that original directory.

All input members must be regular retained files beneath the capture. Symlink aliases, changed bytes, mismatched project or rendering identity, and undeclared staged members reject adoption. Publication uses a private sibling staging directory and one directory rename after complete verification.
