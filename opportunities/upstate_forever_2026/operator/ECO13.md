## Receive an existing scientific experiment

Open Experiment comparisons. The experiment list comes from the original model.experiments.list_experiments catalogue in the currently selected Workspace. Choose the actual saved experiment, then give this receiving edition a readable title, portable project/setup identifiers and a currency.

Receiving is queued as eco13.experiment.receive. The existing operator assigns the retained task and request identities. Open its task to follow progress. The original receiver reads the complete paged experiment population, selected model scope, case/run identities, original source objects and native outputs. Its ordinary case-page size is 250.

The receiving source may be complete or partial. The saved comparison exposes that status directly. A partial combined run can retain completed native model files while its original case and run state remains unfinished. Paired effects appear only when the original eligible case and its required native pair supply them.

The finished task opens a saved comparison. Read its original experiment ID, source Workspace identity, selected models, original planned case/run counts and case/model slot counts. Original Workspace identity is preserved as its source string; the application uses a separate registered workspace key for its own HTTP routes and task queue.

## Read the current result

The in-app table reads the saved report through paged authenticated routes. Switch between alternative outcomes, parameter/reference outcomes and unfinished cases. Scenario and metric filters, plus profile and result text search select rows from that same retained report; they do not issue native jobs.

Alternative outcome rows keep the original profile, alternative, case, baseline/run and reporting-grid IDs. Nitrogen, phosphorus and sediment retain their source physical units. Change is alternative minus paired baseline; positive avoided export means less modeled export. Read paired cells, reporting cells, coverage fraction and paired-support identity with the quantity.

Parameter/reference effects remain in their own table and CSV. The response to a different parameter profile and the response to a different landscape alternative keep their original scientific comparisons.

An unfinished row includes the original case/run state and whether its native model file was available and retained. The table remains useful while the original operator continues the pending science.

The complete standalone HTML report, full JSON, CSV files, original receiving plan, native slot states and saved report choices are available through the original verified file tickets. Download the HTML to use its complete offline filtering, pagination and printing. The in-app table provides those retained outcomes through the original operator API.

## Save costs, objectives and a budget

Choose a saved comparison and enter explicit intervention costs in the selected currency. A blank unknown cost stays unspecified. Enter zero only when zero is the intended declared intervention cost.

Select objectives from the actual retained reporting-grid and metric pairs. The underlying ECO13 ranking operation compares alternatives only within compatible parameter populations, units, directions, reporting grid, paired support and original baseline identity. It keeps each physical metric separate. Alternative costs and avoided export remain separate ranking dimensions.

The browser saves the complete chosen report edition through eco13.report.save. It resets inherited report options first, then applies the explicitly supplied costs, objectives and budget. The saved scenario_costs map contains the populated displayed costs. Clearing every objective saves a report without inheriting an earlier ranking. The budget applies only when objectives are selected.

Save report creates a new retained edition linked by source_record_id. Existing report files and download tickets keep their original bytes. Immutable native inputs can share filesystem blocks with the previous edition; each report and its portable context has an independent file.

The reset control restores the receiving plan's original costs and clears saved objective/budget choices. It creates another explicit report edition.

## Exact original-operator interface

All reads include the currently selected original workspace key.

| Route | Result |
| --- | --- |
| GET /api/eco13/catalog | Original saved experiment catalogue, saved comparison/report summaries, per-record issues and page limit |
| GET /api/eco13/record?record_id=ID | Saved edition, scenario costs, actual objective pairs, selected report choices, original ranking, file tickets and original-experiment continuation |
| GET /api/eco13/rows?record_id=ID&kind=outcomes&offset=0&limit=100 | Paged exact saved outcomes; kind also accepts parameters or incomplete |

The rows route accepts scenario_id, metric, case_id and q. A page contains at most 250 records and returns total and next_offset. Native metric rows and incomplete availability records retain the field names generated by the current scenario workbench.

| Queued action | Payload |
| --- | --- |
| eco13.experiment.receive | experiment_id, title, project_id, setup_id, currency; optional scenario_costs and page_size |
| eco13.report.save | record_id; optional title, scenario_costs, objectives, budget_cents, clear_budget and reset_report_options |
| eco13.comparison.export | record_id |
| eco13.archive.receive | upload_id; optional title |

## Retained storage and recovery

Final records live at Workspace/eco13/records/ORIGINAL_TASK_ID/. Each has an immutable record.json plus its complete comparison/ directory. The record retains its original task request hash, source snapshot times, native counts, report-file hashes and source lineage.

The native receiver requires a new destination outside the original scientific Workspace. Its initial task-owned sibling staging directory is promoted into the retained Workspace branch after the complete independent comparison is ready. When a Workspace is on a different mounted volume, the provider first prepares and verifies the complete receiving directory on that volume, then promotes it.

Report editions use separate report files and saved choices. A failed new report operation leaves the prior published edition available. Retried operations recover their own retained staging and original source selection. Original queue resume and cancellation controls remain in the task interface.

Portable exports use the original operator's outputs directory and verified download tickets. This keeps generated ZIPs outside the scientific Workspace while the underlying saved comparison records remain available for subsequent export or native project backup.
