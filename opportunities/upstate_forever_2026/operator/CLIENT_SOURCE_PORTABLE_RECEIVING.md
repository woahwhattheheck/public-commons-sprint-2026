# Original-table portable receiving

Opening an already retained CSV, workbook, raster or vector now uses the shared `model.portable_fs.publish_file` implementation. NTFS/POSIX hardlinks remain the ordinary fast path; a filesystem that declines hardlinks uses a verified, fsynced temporary copy and an atomic create-only rename. The same original filename, byte count and SHA-256 are checked on new publication and reuse. A conflicting or edited existing view is preserved and reported rather than overwritten. Windows paths use the shared extended native path form; invalid Windows aliases are rejected rather than silently renamed. Source inspection, selections, complete-table exports and saved scientific IDs do not change. The original-table component includes the shared filesystem module so native backup/receiving carries this dependency with the feature.

The cloud receiving course used the full Current195 application with its InVEST3.20 runtime: Windows-1252 semicolon CSV with a later heading and a quoted multiline field; a three-sheet workbook with header row6,137 data rows, exact text identifiers, original formulas and explicitly selected cached values; all original-row pages and full HTML/JSONL/CSV exports; an actual137-row SDR source edition; and native backup/independent receiving. The published self-contained HTML was rendered and its search, page, stored-value and cell-meaning controls operated at1440 and390 pixels. The hardlink-declined branch was exercised against both complete original files, with concurrent receiving, cold reuse and preservation of an independently edited copy. This is a manual source-receiving course; use the same affected controls in the existing final native Windows/Mac opening, rather than adding another automatic test suite.
