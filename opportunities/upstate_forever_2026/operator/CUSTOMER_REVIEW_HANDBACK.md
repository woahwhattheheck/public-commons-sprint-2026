# Customer review handbacks

The Customer reviews desk connects a customer's requested changes to the engineering work that answers them. An engineering response records the responsible person, the disposition of each request, and the actual files or requirements in a revised review. The exported handback brings the original review, revised review, customer response histories and engineering response editions together.

## Complete the review and revision journey

1. Open **Customer reviews** and choose the original retained review. Its **Files**, **Requirements** and **Response history** tabs show the selected work and the customer's returned decisions.
2. Use **Receive response** to import the complete response JSON returned from that review's offline desk.
3. Open **Engineering handbacks** and choose **Prepare engineering response**. The form identifies the exact customer response being answered. To answer an earlier response, use **Choose another customer response**.
4. Enter the preparing person's name, role, organization and a useful summary. Assign an engineer or team to each requested item and describe the planned work. Save a **Planning** edition to retain progress in the project.
5. Complete the required engineering work in its existing source, map, model or delivery workflow. Use **New selection** in Customer reviews to retain the revised work as a separate review, choosing its actual original files and requirements.
6. Reopen the engineering response and choose **Revise response**. Select that revised review. For each addressed request, select the replacement files or requirements and explain the change. For a deferred request, explain what remains and why.
7. Set the engineering response to **Ready for customer review** after every request is addressed or explicitly deferred, then save the edition.
8. Open the saved edition and use **Export complete handback**. The resulting task provides the complete package and the handback desk. The recipient can inspect both review selections and the engineering response, then continue customer review using the original review-response workflow.

A planning edition may be saved before a revised review exists. An addressed request needs an actual replacement reference in the selected revised review. A ready edition has a revised review, an assigned engineer or team for every item, explanations for addressed and deferred items, and no remaining planned items.

## Work from the actual customer request

The requested items come from the chosen retained customer response: its corrections and the artifact or requirement decisions that ask for changes or clarification. Their source references and wording remain attached to the engineering response.

The **Assigned engineer** field records responsibility for the engineering work. **Engineering disposition** records whether the work is planned, addressed in revised work or deferred with an explanation. These fields are authored by the engineering team. The customer's own decisions and acceptance remain in the customer's response history.

When selecting replacement work, the form displays the revised review's actual file names and requirement titles. A change of revised selection keeps existing mappings visible so they can be reconciled. References from a previous selection are labelled and must be cleared or returned to their original selection before saving.

## Keep the editions understandable

Every saved engineering response has its own edition and predecessor. **Engineering response editions** opens the retained history; the original summary, assignments, notes and replacement selections remain available. Open the latest edition to revise the engineering response; a historical edition provides an **Open latest edition** action.

A saved handback pins the response generations associated with its original and revised reviews. Later customer replies are retained in their own history. Exporting the saved handback preserves the generations that its engineering response answered.

The editor keeps unfinished form changes while this application remains open in the same workspace. **Save engineering response** retains an edition in the project so it can be reopened and included in the complete project transfer. Use the saved edition for transfer or handover.

## Receive and continue a handback

First select the restored scientific project that supplied the original review and its source records. In **Customer reviews**, open the relevant review's **Engineering handbacks** tab and choose **Receive handback package**. Select the complete exported ZIP. The task retains all portable files in its own receiving desk and joins the original and revised review records, customer response history and engineering response editions to that same project. The project's scientific source files must already be restored and match the selected review; receiving a handback does not substitute unrelated sources.

Use **Open engineering response** on the completed task to inspect the received edition. **Open revised review** opens the actual revised selection. The saved edition can then be exported again through the same handback workflow.

A task that reports a different project, changed member or conflicting response generation retains the original package for investigation. Select the intended workspace and reopen the complete task details before retrying. Continue from the original operation and its saved files.

## Continue exports after a project transfer

The complete project retains the review selections, customer response records and engineering editions. Exported desk folders belong to the operator computer that created them. After receiving the project on another computer, **Exported desks**, **Exported handbacks** and the original completed task identify a sender-local package that is unavailable and offer **Rebuild selected export**.

1. Open the restored source project, then the original review or engineering response.
2. Find the historical export and choose **Rebuild selected export**.
3. Check the displayed selection. An ordinary review identifies its original customer response generation, including an initial review with no customer responses. A handback identifies its exact saved engineering edition.
4. Rebuild the export. The new local task provides the desk and complete ZIP using the restored original source files.
5. Continue review from that package. Later replies and engineering editions remain in their existing histories.

A rebuild preserves the source export selection and records the source task in its queued request. The local package is newly generated; its file inventory and package identity describe those newly exported bytes. The original task and its export history remain available. Task references continue to resolve through repeated project transfers.

An unfinished export recovered by the original project-transfer operation also retains its original selected response generation when resumed. A new ordinary **Export current review** continues to check that the response shown in the form is still current.

The receiver checks the exact task request, transfer lineage, scientific project and selected edition before recognizing a missing sender export. A local package with a changed inventory, changed archive size, invalid path or symlink displays its own export issue. Other retained reviews and exports remain usable. Opening that task or serving its files retains the underlying error; the damaged row does not offer automatic rebuild. A present desk whose ZIP is absent is inspected completely before recovery is offered. A rebuild also checks the full hash of an available source archive. Original download handling verifies the selected file bytes before serving them.

## Day-to-day navigation

| Where | What it answers |
| --- | --- |
| Files and Requirements | Which original work did the customer review, and what did the customer decide? |
| Corrections | What assignments and correction states did the customer include in their returned response? |
| Response history | How did the customer's decisions change between returned responses? |
| Engineering handbacks | What work is the engineering team doing in response, and which revised files answer each request? |
| Engineering response editions | Who prepared each internal response and what did it contain? |
| Exported handbacks | Which complete handback packages were created for the selected saved edition? |

The desk uses the existing grayscale interface, authenticated operator tasks and retained Workspace. Model runs and scientific calculations continue through their original workflows; a handback selects their completed outputs for review.
