# Milestone evidence and original receiving

The Milestone handoff desk turns an authored selection of actual source collections, completed model runs, deliveries and saved map exports into an original Customer review. It keeps criterion evidence, unassigned criteria, source exceptions and returned engineering decisions together. The saved review and complete Project remain the authority.

The three criteria groups cover:

- Source and method setup: complete originals and sidecars, native opening, grid and spatial alignment, geographic domain, editable profile lineage and two explicit alternatives.
- Modeled review: baseline plus two alternatives, exact native arguments/logs/physical outputs, quantity and spatial-support interpretation, seven output families and nine principal PDFs, and editable source-to-output traceability.
- Correction and receiving: retained correction lineage, complete application/project/runtime, final human-readable outputs and independent receiving.

Only actual available selections appear. Missing evidence remains visible. The desk does not fabricate metric values, recipient decisions or a successful scientific run.

## Use the desk

Open the existing Eco operator and select the actual scientific Workspace. In **Milestone handoff**, choose the relevant milestone, describe its purpose and select original source collections, runs, deliveries and map exports. Choose **Load exact original files**. Assign files to each criterion using the complete original file identity, and record assumptions or source exceptions with their responsible owner.

Preview the complete selection. The preview lists the actual files, criterion counts, assignments and exceptions. A changed source selection or note invalidates the previous preview. **Save original milestone review** submits through the existing task queue. The entire original request is retained before dispatch. Replaying a lost response uses that same operation ID and body.

Each browser window retains its own complete working copy. Download it before leaving when browser storage is unavailable. Open an earlier working file or saved browser copy explicitly; the current complete copy is retained separately. A working file can keep unfinished notes and exceptions. Importing a pending request discards imported outcome claims and replays the original request against its original Workspace and staff session.

Open a saved handoff to read original criteria, selected recipient response, exact evidence downloads and engineering handback history. The original Customer reviews desk owns file inspection, recipient decisions, response templates, engineering corrections and review packages. Import only a real returned response naming this exact project and review. Earlier response generations remain independently selectable. The whole-record milestone binding and its complete profile travel with the original review; receiving does not replace that embedded profile with local defaults.

**Export original review package** uses the original current-response guard. If you are reading an earlier response, return to the current response before requesting a new current export, or open the original historical export in Customer reviews. The earlier snapshot's evidence JSON, CSV and HTML remain available without changing the review.

## Operate the actual source case

Use the existing equipped operator. Do not start a second operator or an overlapping scientific run. Select its exact application directory, native Workspace, Workspace key, base URL and private capability file. The capability stays outside the delivered case.

Author the definition from the actual desk selection. The definition schema is upstate.milestone-handoff-definition/v1, with title, milestone_id, notes, selection and one row for every criterion. Each row retains id, evidence_ids, note and exceptions. The four selection arrays are source_collection_ids, run_ids, delivery_ids and spatial_export_ids. IDs are the real existing source and artifact IDs. Choose **Download authored definition** after preview to retain the exact normalized definition; do not insert invented IDs or a demo dataset.

Run the same installed application programme:

    python APPLICATION/source_tools/receive_milestone_handoff.py \
      --app APPLICATION \
      --workspace ORIGINAL_WORKSPACE \
      --workspace-key ORIGINAL_KEY \
      --operator-url ORIGINAL_OPERATOR_BASE_URL \
      --capability-file PRIVATE_EXISTING_CAPABILITY_FILE \
      --definition AUTHORED_DEFINITION.json \
      --output OWNED_MILESTONE_CASE \
      --operation ECO-MILESTONE-HANDOFF-B43A-20261013 \
      --browser --node EXISTING_NODE \
      --playwright EXISTING_PLAYWRIGHT_MODULE \
      --browser-executable EXISTING_CHROMIUM

Application, Workspace and output must be disjoint. The programme binds all installed source files, original project identity and exact authored input bytes. It retains the preview and complete original queue request before dispatch; then reads the saved original review, exports its exact review package and evidence attachments, creates the full original scientific Project, restores a receiving copy and compares complete evidence, selected response and handback history.

The prepare stage needs no future recipient response. When the actual response arrives, resume that same command, same output and operation, adding:

    --response ACTUAL_RETURNED_RESPONSE.json

If an actual original engineering handback is also ready, add:

    --handback ACTUAL_ORIGINAL_HANDBACK.json

The return document must name the retained review and project; a handback must name that same response. The programme uses customer.review.response.import and customer.review.handback.save through the existing queue. It never creates example reviewer approvals.

A failed, cancelled or interrupted original queue task is retained. Inspect and repair its actual cause, then use --resume-task to resume that same task. Unknown or running work is reconciled through its original task ID. The course holds its own exclusive lock across the native and browser phases, inherits it into the one browser child, and refuses a second live child. Keep the same source and output for an interrupted continuation. A genuinely changed source edition or browser mode uses a separate owned stage and explicit previous-case reference.
