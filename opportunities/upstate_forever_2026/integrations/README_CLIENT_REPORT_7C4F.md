# Client report and received delivery

The Maps and delivery screen opens the selected scientific report, provides the PDF and editable report forms, groups scenario tables, map families, the map atlas and GIS files, and offers the complete delivery and working project.

The report uses the retained native grid and original modeled quantities. Its study area, selected model stages, baseline and alternatives, actual cell area, units, common-support comparisons, receptor inventory and source references come from the saved project.

## Use

Open **Maps and delivery**, select a retained delivery, and choose **Read scientific report**. Use **Open PDF** for the publication document and **Download complete delivery** for the assembled package. The grouped download lists retain the original file tickets and exact contents.

**Create current report edition** rebuilds an earlier saved selection through the original task queue. A retry after a lost response uses the same operation ID. **Revise delivery choices** opens that selection for editing.

A received working archive registers its original report and maps under **Received copy**. Choose **Read scientific report** immediately, or **Prepare complete copy** to resume that same selection and produce its local delivery archives.

The complete guided journey, controls, scientific interpretation and restore steps are in [the delivery review guide](../operator/DELIVERY_REVIEW.md).

The separate **Read client companion** action opens the retained decision guide. Both report families keep their complete PDF, HTML, Markdown and structured JSON, and their original paths are included in the same package.

## Implementation notes

The report preview is served through the original authenticated file route, with registered report/map links and an isolated document policy. The saved report-model delivery ID must match the selected delivery.

Report and delivery editions participate in the selection before its identity is calculated. Working archives capture an explicit, nonrecursive delivery snapshot with its original identity and file records. Receiving registers that snapshot in the ordinary deliveries directory. Existing physical archives are reused only when their project, selection, delivery identity and complete captured file inventory match; a different capture remains preserved before rebuilding.

The current public composition also keeps native-grid metadata, receiving-water report sections, complete source inventories, experiment locks, map-atlas identity, and existing workspace source reuse.
