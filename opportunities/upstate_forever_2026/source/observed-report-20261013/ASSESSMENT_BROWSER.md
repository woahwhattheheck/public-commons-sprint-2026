# Assessment receiving in the existing browser course

Maintained by TokenJunkieLabs.

The visible assessment chapter follows the complete original native preparation
into the current operator. It uses the same authenticated browser page, context
and recording as the existing scientific-report receiving course. The caller
retains the actual project, task, source and report identities.

## Complete the original native preparation first

Use [PREPARE_ASSESSMENT.md](PREPARE_ASSESSMENT.md) and the current maintained
application to prepare all three station studies and all four contexts. The
chapter reads that operation's original selection, state, saved all-editions
study and each context/report receipt. It uses the original Workspace key and
project identity in the completed scientific-report receiving receipt.

The two complete normalized published inputs are maintained at
`source/water-quality-assessments/20261013/sources.json`.
Use them with the original 705-station, WQP and 101-row draft inputs from that
guide. Preparation remains the owner of source import, geographic calculation
and independent context receiving.

If the maintained report helper changes from 1.0.0 to 1.1.0, select a new
preparation output directory. The original station and context editions are
reused through their maintained identity; the updated report sections receive
a new immutable report-source identity. Keep the prior preparation's original
selection and outputs together.

Before opening or preparing each report, the chapter selects **Refresh retained
studies** and checks the running operator's catalogue against the prepared report
version. When source has been installed over a running operator, restart that same
operator before continuing so its loaded report module matches the preparation.

## Join the already operating browser receiver

For the receiver's existing live server and completed native report receipt:

```sh
"$NODE" "$APPLICATION/source/observed-report-20261013/receive_browser.mjs" \
  --url-file "$PRIVATE_OPERATOR_URL_FILE" \
  --receiving-receipt "$ORIGINAL_REPORT_OUTPUT/scientific-report-receiving.json" \
  --assessment-preparation "$ASSESSMENT_PREPARATION" \
  --output "$ORIGINAL_REPORT_OUTPUT/browser" \
  --video
```

The original native receiver can pass the option into its normal browser
continuation. Add these options to the same single-report command, retaining
its original workspace, output, source selection, title, contact and resume
choice:

```sh
--browser-node "$NODE" --assessment-preparation "$ASSESSMENT_PREPARATION" --video
```

The ordered multi-report `--course` retains its existing separate browser
continuation. After the same native report is complete, its owner runs the
browser command above against that report receipt. This preserves the existing
course's selected report and recording ownership.

An existing broader rehearsal can call the chapter directly:

```js
import { runAssessmentReceivingChapter } from './assessment_browser.mjs';

const chapter = await runAssessmentReceivingChapter({
  page,                              // the already authenticated, recorded page
  operatorURL,                       // keep this private; do not put it in receipts
  preparationDirectory,
  receivingReceipt,                  // complete original scientific-report receipt
  outputDirectory,
  timeout: 120000,
  redact,                            // the current caller's private-URL redactor
});
```

The chapter leaves the existing browser and recording open. The ordinary report
course then reopens the original received scientific edition, operates its
download links, revises its saved source order, reloads it and opens the selected
study receiving result.

## What the operator sees

1. **Station geography** opens the completed 164-station all-editions study.
   **Use saved study in assessment context** opens that exact study and its
   three original assessment inventories.
2. **Assessment context** opens each saved publisher-watershed, computed-membership,
   July fully-supported and draft selection. The visible title and complete
   response are checked against the actual preparation receipt.
3. The ordinary download controls save each context's readable HTML, full JSON,
   original assessment CSV and complete source ZIP. Each is compared with its
   saved original member descriptor. The actual downloaded HTML is opened in
   the same recorded page before returning to the operator.
4. **Use saved assessment context in report** uses the original task queue.
   **Open scientific report** carries the exact prepared title and ordered
   source selection into the maintained composer. Each next context replaces
   the previous selection. Preview verifies the actual source identities.
5. The existing report receiving journey continues with its original HTML frame,
   PDF/HTML/Markdown/data downloads, complete report ZIP, editable source order,
   reload, narrow layout and independently received selected study.

This chapter prepares report sources through the operator. It consumes the
already completed station/context results and the same native receiver's final
scientific report; geographic calculations and final PDF generation remain in
their maintained source operations.

## Inspect the actual delivered result

Open the captured screenshots and watch the final recording. Read the downloaded
HTML and PDF as the recipient would, operate source links and download controls,
inspect the narrow layout, and reopen the complete original project. Check that
native watershed IDs, comparison-source labels, original edition/cause/use/support
and the six source differences are readable. Repair observed problems before
presenting the result.

The chapter records `assessment-browser.json` after each stage, with original
input file identities, actual queue task/source/preview IDs, saved download
identities and screenshot paths. Its state is complete only when the visible
journey finishes. The surrounding `scientific-report-browser.json` keeps the
assessment action requests separate from the existing report-reopening course,
which continues to require no newly submitted queue actions.

Keep a failed chapter's recorded source/version, downloads and images with the
same receiving operation. Fix its first actual exception and continue from the
existing project. The current chapter and runner do not create another browser
context, server or native model case.
