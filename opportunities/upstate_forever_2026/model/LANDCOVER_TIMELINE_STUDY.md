# Continue an existing observed timeline as an editable Study

This course completes the original timeline-to-report-to-Study handover. It selects an **existing completed** observed land-cover ledger in its retained Workspace, prepares that ledger's Scientific Reports source, renders its original report, exports the selected editable Study, restores the whole archive and cold-opens it with the **copied application** in a separate Python interpreter.

It does not run a land-cover reducer, hydrology model, alternative scenario or browser. Do not use it to create another scientific case when the original one already exists.

## Receive the whole current source

Adopt the complete maintained land-cover installation, including the current temporal Study helper and these two files:

- `model/landcover_timeline_study_receiving.py`
- `model/LANDCOVER_TIMELINE_STUDY.md`

The helper must recognize `input_mode=timeline` as the original retained-source binding. The application must also contain its existing Scientific Reports, selected Study and portable receiving dependencies. Use the maintained guarded installer/current source composition; do not copy just this programme over an unrelated partial application.

Use the original scientific Python environment already capable of opening this application and its actual retained source rasters. No package installation, credentials, external service, temporary proxy or replacement runtime is introduced by this course.

## Operate the selected original ledger

From the complete application directory:

```sh
GIS_PYTHON -m model.landcover_timeline_study_receiving \
  --workspace /absolute/original/workspace \
  --ledger ORIGINAL_COMPLETED_TIMELINE_LEDGER_ID \
  --out /absolute/new/timeline-study-receiving
```

Replace `GIS_PYTHON` with the actual existing scientific interpreter executable. Select the saved ledger's actual ID from the original Land-cover ledger screen or completed receiving record. The output must be a new private directory outside the original application and Workspace. An optional `--title` supplies the actual report title; omit it to retain the ledger title.

The existing Workspace and completed numerical edition remain authoritative. The course creates the explicitly selected report source and report edition through their original maintained APIs. It never modifies the original ledger tree or generates another numerical result.

## What the complete operation does

1. Open the exact completed ledger using `landcover_workspace.inspect`. Require observed timeline mode, all-observation common support and the original ordered years. Retain the complete original edition, binding, numerical report, project identity and every file in the original ledger tree, including checkpoint/output artifacts.
2. Call `landcover_report_source.prepare` with the original ledger ID and title. Reopen its immutable receipt with `get`, retaining every source member and complete report/source archive. Existing matching output is reused.
3. Prepare the real `scientific_report_editions.preview`. Retain that full preview, title, ordered source choices and rendering identity. Complete it with `render_prepared`, or reconcile its exact already completed edition. The request remains bound to the original source/title on resumption.
4. Inspect the complete scientific report and create its native full-report ZIP. Original figures, report documents, source links and every declared attachment remain present.
5. Preview and export the original selected Study rooted at `scientific-report-editions`. The native dependency closure carries the original raw-CAS source entries, selected timeline ledger, scientific report, complete attachments and application. The selected report's own complete closure is retained; unrelated results are not automatically added.
6. Inspect every member of the final selected Study archive and its actual native receipt. Require the same project and selected root. Preserve the archive at `timeline-selected-study.zip`.
7. Restore using the original `portable.restore` into the owned new `received` directory. Reconcile the published receiving through `portable.resume_restore` using the exact archive SHA-256; never overwrite an existing unrelated directory.
8. Launch the existing interpreter with `-I` and explicitly import from the returned copied application. Verify every copied application member against the original archive manifest before use. Cold-open that copied Workspace, original ledger/source/report and selected Study. Require identical complete ledger state, ordered years, source member identities, report record/operation, every report attachment and every exact archive-selected original ledger artifact. Call the copied application's `verify_received_studies`.
9. Reopen the producer ledger once more and require its complete tree/state to remain unchanged. Retain the complete receiving summary and exact archive identity.

The original producer snapshot always includes its complete ledger tree, including `.writer.lock`, and the final producer check remains byte-exact. The selected Study's original portable policy excludes locks, compiled/runtime files, transient writer files and materialized source-view/runtime directories. `study-ledger-members.json` records the exact archive-selected ledger members and each intentional exclusion with its original identity. Every selected member must match the producer snapshot; an omitted scientific/checkpoint member fails explicitly. Cold receiving compares the complete restored ledger tree to that exact archive selection. No excluded locks are added to the archive and no portable or numerical engine is changed.

The complete report source preserves the original fractional hectare method and common support. Timeline labels remain selected observations: missing years are not interpolated. An interval brackets a mapped transition and does not establish its event date. The original mapped-change interpretation and unavailable quantities remain intact.

## Interruption and same-operation continuation

The course writes `receiving-request.json` before execution and retains stage events in `events.jsonl`, current `receiving.json`, complete source/preview/report/Study receipts, error tracebacks and cold-process output.

To continue the same original course:

```sh
GIS_PYTHON -m model.landcover_timeline_study_receiving \
  --workspace /absolute/original/workspace \
  --ledger ORIGINAL_COMPLETED_TIMELINE_LEDGER_ID \
  --out /absolute/existing/timeline-study-receiving \
  --resume
```

Pass the same optional title if the initial command used one. Original request, implementation identities, ledger snapshot and saved stage values must match. A changed source or scientific case is reported explicitly; it is not silently replaced.

The original source preparation, report renderer and Study exporter reconcile their actual retained effects. If the Study archive already exists, the native exporter verifies and reuses it. If `received` was already published, `resume_restore` reconciles it against the exact original archive. The portable receiver's own unpublished staging directory remains owned by that receiver; this programme does not adopt unrelated partial directories or manufacture an interruption.

SIGTERM/keyboard interruption preserves the failure/current stage and stops only this course's owned cold process. Scientific execution and shared browsers are never started or stopped. There is no arbitrary total-runtime timeout.

## Read and use the outputs

- `receiving.json`: current complete/failed/interrupted outcome, exact original IDs, archive identity and cold-receiving result.
- `original-ledger.json`: complete original edition/binding/report plus all original artifact identities.
- `original-report-source.json` and `original-source-files.json`: full retained scientific source/attachment identities.
- `original-report-preview.json` and `original-scientific-report.json`: original native preview, complete report record, operation and attachment descriptors.
- `original-report-export.json`: the existing application's complete report ZIP receipt.
- `study-preview.json`, `study-export.json`, `study-inspection.json`: full original selected closure, receipt and archive manifest.
- `study-ledger-members.json`: exact archive-selected ledger identities and original intentional portable exclusions.
- `timeline-selected-study.zip`: the complete portable editable Study and application.
- `received/application` and `received/workspace`: the actual copied application and original received scientific project.
- `original-restore.json`, `original-restore-resumed.json`, `cold-receive-result.json`: real portable receiving and independent copied-application reopening.
- `error.txt`, `cold.stdout.txt`, `cold.stderr.txt`, `events.jsonl`: retained exact current error and operation progress.

Keep these original identities together. Do not present a retained failed or interrupted outcome as completed. A successfully received numerical/report package is still distinct from personal operator/visual acceptance.
