# Adopt completed original runs in a scenario experiment

TokenJunkieLabs · Original Upper Savannah scientific workspace

An experiment can reuse completed native runs whose requested InVEST version differs from the version that actually produced their retained outputs. The original run selection and run ID remain the source of those outputs. A saved experiment records the exact adopted source and pairs it with the appropriate baseline under the same profile.

This continuation uses the existing experiment designer, original operation queue, native run desk, reporting pipeline, and portable workspace. Its source is model/experiments.py. Conservation's existing paired-experiment continuation supplies the source IDs automatically when it uses a retained original baseline or alternative.

## Choose the physical cohort

Use a baseline with the retained original land-cover scenario. Every adopted source must use the chosen prepared grid and selected model families. Its profile must be an explicitly selected retained profile or the exact profile generated by the chosen parameter axes. Its scenario must be the baseline or a selected land-cover alternative.

A noncanonical source must already be complete, with the original exports for every selected model. The shared native version resolver reads each completed model stage first, then the observed run runtime, then the labelled legacy requested version. Each adopted producing model must resolve to the supported InVEST version, currently 3.20.0. A run originally requested under another version can therefore participate when its actual completed NDR and SDR stages meet this contract.

Current canonical prepared or interrupted runs continue through the original execution path. Their IDs can appear in a supplied source list and are removed from the normalized adoption list because the ordinary case selection already identifies them.

## Save an explicit adoption

The original experiment selection accepts one additional optional field:

```json
{
  "schema": "upstate.experiment-selection/v1",
  "title": "Selected conservation packages across retained profiles",
  "reason": "Compare the retained physical packages using their actual completed native sources.",
  "baseline_run_id": "<original baseline run ID>",
  "scenario_ids": ["<retained land-cover scenario ID>"],
  "profile_ids": [],
  "design": "one_at_a_time",
  "axes": [],
  "source_run_ids": [
    "<original baseline run ID>",
    "<original completed alternative run ID>"
  ]
}
```

The baseline is considered automatically. Every source ID is read through the original Workspace and checked against its selection digest. A source outside the selected grid, model scope, profiles, or scenarios is rejected. Supplying two different originals for the same profile/scenario case is ambiguous; choose the intended original explicitly.

Preview returns the ordinary selected cases and counts plus source_runs when adoption is needed. Each source entry records its actual run_id and selection, the corresponding current logical case ID, producing versions, and original output descriptors. The normalized selection retains a sorted source_run_ids list containing the noncanonical originals. When all supplied IDs already match ordinary current selections, both additional adoption fields are omitted; existing canonical experiment identities remain unchanged.

Save or run through the existing experiment action after reviewing the preview. The saved plan includes its frozen source bindings in its immutable identity. Reopening the programme checks those bindings against the same original runs.

## Follow execution and results

Each adopted case exposes its actual original run_id and selection. Its native_source field records the saved adoption; native_baseline_source identifies an adopted paired baseline. Reference and parameter cases compare against the chosen original baseline. Each land-cover alternative compares against the baseline under its own parameter profile.

Materializing an adopted case reads the completed original run directly. New or unsupplied cases follow the existing current-version native preparation path. Original historical partial-model case recovery continues to use its established source_run_id, source_baseline_run_id, and source_selection fields; adoption provenance has separate field names.

During execution, the engine checks per-model producing-version compatibility before comparing physical outputs. It calculates the existing common-support annual-mass metrics and retains the actual comparison ID, native runtime, per-model version provenance, source reuse, and original output descriptors. Positive reduction remains baseline minus alternative export; signed delta remains alternative minus baseline.

A completed adoption does not turn a parameter design into a statistical uncertainty distribution. Compare the retained profile outcomes and their original supports, units, assumptions, and parameter references.

## Conservation continuation

The Conservation bridge prefers a matching explicitly selected original alternative, then the retained scenario's original run, before preparing a current canonical alternative. The selected original must match the requested logical grid/profile/scenario/model case and satisfy the completed-stage contract.

The handoff records the actual baseline and alternative IDs and passes them to experiment preview. Its primary_pair and the resulting experiment therefore refer to the same physical originals. Additional explicit source_run_ids can identify already completed cases for other selected profiles or alternatives.

## Reopen, revise, and transfer

The original designer preserves adopted source IDs when reopening or cloning a design. If the chosen profiles, scenarios, or axes change, review the retained source choices with the revised preview. A source that no longer belongs to that design must be removed or its corresponding case restored.

The original experiment CLI accepts this same selection JSON. Its preview, prepare, execute, and completed-run synchronization use the same model implementation.

A complete original workspace backup includes adopted run trees and their source/grid/profile/scenario records. A selected-study export also follows every normalized experiment source_run_ids dependency before cases have materialized. After receiving, inspect the programme and its actual case run IDs, then continue through the existing native operation queue.

If a source's selection, producing version, or output descriptor differs from the saved plan, the original plan reports that mismatch. Recover the exact original source or save a new explicitly reviewed design using the desired edition. The retained plan and completed source identities provide the evidence for that choice.
