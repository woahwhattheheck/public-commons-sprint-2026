## The algorithm change

For each parameter ROOT110 supplies scale s and bias b from public size-three
training data. Its forward map is sigmoid(s*z+b). This candidate generates the
original random/corpus starts, performs original canonical clipping and converts
each coordinate to (old-b)/s. Both new treatment arms start from the same
physical designs up to recorded floating-point error. A donor's ordinary
sigmoid coordinate must never be interpreted directly as a property coordinate.

The per-coordinate clipping box is [(-clip-b)/s,(clip-b)/s], preserving the
original sigmoid preactivation range. Subsequent random restarts use the
Objective's installed inverse and retain its original uniform physical sampling.
The original feasible archive is subclassed only to measure diversity in the
actual unit space sigmoid(s*z+b); retention, ordering and min_rms stay unchanged.

The Objective differentiates the installed map itself. Its returned gradient
already includes the chain rule, including scale s relative to ordinary sigmoid
coordinates. The optimizer does not multiply the gradient a second time. This
candidate has no constraint-Jacobian, Hessian or Hessian-vector path. Topology,
physical bounds, frequency grid, loss, penalty, power thresholds, feasibility,
budgets and logging stay with the supplied original Objective.

The coordinate change deliberately changes Adam/trust/noise geometry and can
help or hurt. It does not claim identical later trajectories or an improvement.
Eight separate optimizer states, scalar confirmation of a feasible point
outside a batch's reduced minimum, finite-cap scalar tails and late quiet
polishing remain the original algorithm. Only documented pre-run mapping,
public context, Objective warmups and original result methods are used.
