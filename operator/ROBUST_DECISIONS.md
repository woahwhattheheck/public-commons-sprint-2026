# Robust decisions in the original operator

Open **Robust decisions** in the current Upper Savannah operator after selecting the
retained scientific workspace. The complete existing study editor uses the same
workspace, authenticated API, original serial task queue and file downloads as
the other application desks.

## Work from original modeled alternatives

Select a saved experiment in the receiving panel and provide the explicit decision
configuration JSON. **Use saved experiment** calls the original
`model.experiments.read_summary` through the retained robust engine. An uploaded
original summary and its decision configuration use the same existing native
receiver. A complete decision-study JSON or exported project can also be received.

Candidate IDs identify the original scenarios. Profile IDs, metric IDs and annual
units must match the retained summary. Set candidate costs, capacities, fixed
metric scales, preference weights, optional physical targets and any probabilities
as explicit planning choices. Original native packages stay whole in the original
`native_packages` calculation. The existing additive-action method retains its
explicit decomposition requirement.

The editor shows the complete original profile/candidate matrix and native
baseline/alternative identities. Edit the inputs, save a revision, then calculate
a selection or budget frontier. The existing solver reports every included
profile, physical gain, constraint margin, objective, elapsed time and status.
Earlier study revisions and their results remain in the original SQLite store.
Every native SQLite connection holds the original shared workspace lock through
commit and close; the existing exclusive workspace backup lock therefore captures
the database and its original sidecars consistently.

## Current task and download behavior

Every state-changing operation uses the existing `POST /api/actions`, existing
operation ID and original task. An interrupted HTTP exchange reuses that operation
instead of creating another study or calculation. A retained failed or interrupted
task can be opened and resumed with the original task controls. The browser retains
its pending request identity in session storage and in memory for the active page.

Large original study matrices use the operator's existing byte upload endpoint.
The task carries `payload_upload_id`; the backend resolves the actual retained
upload through `Operator.upload` before invoking the original engine. Project
continuity already captures this original upload reference when transferring an
unfinished task.

HTML reports, outcome CSV, complete project JSON and implementation selections
are saved below the operator's original output root and exposed through its
authenticated file tickets. A complete project export retains every revision,
result, original input hash and receiving provenance. Receiving that JSON creates
an independently editable study through the original `Store.receive`.

Unsaved editor state remains associated with its original workspace when switching
desks or projects. Refreshes update saved study lists and completed results without
replacing an unsaved form. The browser warns before closing a page that still
contains an unsaved study.

## Source integration

The original engine package remains at `model/robust_decisions/eco_robust`.
The current native facade is `operator/robust_decision_registry.py`; the shared
manifest is `operator/extensions/robust-decisions.json`. The browser module and
external stylesheet live under `operator/web` and retain the original panel's
complete forms, tables, result explanation and monochrome design.

The manifest registers the twelve original operation names, a read route,
workspace summary and task-file decoration. Its receiving verifier reads the
restored database, checks the complete revision chain and verifies each result's
original input binding. It uses the existing shared registry's workspace
receiving hook.

The read route is `GET /api/robust-decisions` with the original `workspace`
key and `operation=list|study|experiments`. Study reads accept `study_id`
and an optional retained `revision`. All twelve original task payloads continue
to use the retained engine's `integration.dispatch` contract.

## Native receiving exercise

After cumulative installation, use the original operator with an existing
Workspace that contains a completed experiment. Open Robust decisions, select that
experiment and its explicit configuration, save a decision, calculate a feasible
selection, download the complete project and HTML report, receive the exported
project, edit the receiving study and save its next revision. The original
workspace task view and downloaded file ticket identify each actual operation.
This exercise traverses the authored numerical engine, real registry transport,
SQLite history, file custody and independent receiving in one application.
