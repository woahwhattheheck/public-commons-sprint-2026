queue, source files, downloads and project archive.

## Prepare and open the same workspace

Keep the operator's actual workspace and operator-state directories. Run the
opening command before starting its server so the original operator can take its
existing state lock.

For the original full regional inputs:

    python -B source_tools/open_regional_workflow.py \
      --workspace /actual/regional-workspace \
      --operator-state /actual/regional-workspace-operator \
      --source-context source/water_context/20261013/full-domain-water-context.json \
      --classification-coverage source/water_context/20261013/scdes-domain217-source-coverage.json \
      --native-network source/water_context/20261013/native-network.json \
      --edition-directory /actual/regional-source-edition \
      --huc12 030601020507 \
      --opening-output /actual/Regional_Workflow_Opening.json

The original loader prepares the source edition. The original Workspace imports
it. The original watershed.context.analyze task produces its full report and
watershed.context.export saves the selected Lower Tugaloo HUC12. The launcher
retains their distinct report and export IDs and the parent report's exact SHA.
The analysis request identity includes the installed provider, native engine,
source loader and source-validation edition. Reopening after their update lets
the original analyzer retain newly supported publisher sources; its native
report identity still decides whether to reuse a report.
The queued export identity includes the installed provider, native model and
brief renderer, the original CSV/brief formats and columns, the retained report
and source-edition fingerprints, source validation, and any installed original
connectivity outputs. Reopening after a source or implementation update reaches
the maintained native export operation. An unchanged selection and installed
edition reuse its existing operation.

The profile opening uses the original fifteen-class regional biophysical table
and its editable working NDR/SDR settings. Supply --profile EXISTING_PROFILE_ID
to retain a selected scientific profile instead. An explicit --parameters file
can set its native working parameters before a new profile is saved.

The command prints the complete opening selection and then starts the original
operator. Open its actual local URL. The existing Guided journey imports
Regional_Workflow_Opening.json and checks the original project and selected
records through their maintained APIs. The same JSON is retained as
regional-workflow-opening.json inside the scientific workspace.

Use --prepare-only when another process will start the original server. The
printed operator_command gives the exact original application, workspace and
state paths to reopen.

## Reopen an existing regional report

When the scientific workspace already retains its regional report, use that
actual ID. The original report is reused and the selected watershed is saved
through its existing export action. The opening retains the source references
from the returned report, including when the native analyzer reused that report
from an earlier source import. If a new import was requested, its references are
kept separately as regional_source_request; they do not replace the report's
original source references:

    python -B source_tools/open_regional_workflow.py \
      --workspace /actual/regional-workspace \
      --operator-state /actual/regional-workspace-operator \
      --report ACTUAL_RETAINED_WATERSHED_REPORT_ID \
      --profile ACTUAL_SAVED_PROFILE_ID \
      --huc12 030601020507 \
      --opening-output /actual/Regional_Workflow_Opening.json

A prepared regional source manifest is another supported entry point:
--source-manifest ORIGINAL_MANIFEST --source-id ORIGINAL_REGIONAL_SOURCE_ID.

through the original operator_session/save_operator_session service. The
complete current guided component and registered host are F0C8QBS37TL.

The saved view keeps the existing project notes, note versions and original
start time. It opens the selected watershed and scientific profile in the inputs

The native service keeps its existing revision comparison and session lock.

The same optional native experiment stays selected for the existing experiment
and decision desks. Re-run with the same opening to reuse the saved native view.
The exported opening JSON remains available through the normal import control.

A newly opened or restored browser workspace can load this view from the
project. The native controls can open the project-saved view explicitly and
switch back to the retained browser draft. Each view keeps its selected
scientific and regional records together with its own notes. Importing the
opening JSON remains available. After editing in the browser, use the native
Save view and notes control before making the next project archive.

## Include an actual modeled analysis

Add --experiment RETAINED_EXPERIMENT_ID to bind the original experiment.
Add --baseline-run COMPLETED_BASELINE_ID and --alternative-run COMPLETED_ALTERNATIVE_ID
to bind a distinct completed pair on the same original grid. The launcher reads
their retained records and checks these identities before preparing the opening.

Guided journey displays the selected watershed context beside the original
native grid, source and profile identities. A watershed reporting selection
remains a geographic context record. Native calculations continue to use their
explicit original grids, scenarios, parameter profiles and model inputs.

Use the Profile workbench to edit and save scientific assumptions. Use the
existing experiment desk to calculate the corresponding original scenarios and
profiles. In Decision studies, configure costs, capacities, metric scales and
weights for the retained physical outcomes. The source experiment and its
complete requested scenario/profile matrix remain attached to that study.

## Transfer and reopen the complete application

Add an explicit new --transfer-output directory to capture this opening and
reopen its complete original project:

    python -B source_tools/open_regional_workflow.py \
      --workspace /actual/regional-workspace \
      --operator-state /actual/regional-workspace-operator \
      --report ACTUAL_RETAINED_WATERSHED_REPORT_ID \
      --profile ACTUAL_SAVED_PROFILE_ID \
      --huc12 030601020507 \
      --transfer-output /actual/regional-project-transfer-01 \
      --save-view \
      --prepare-only

The original queue builds the complete workspace archive. The opening workflow
streams its verified download directly into the original upload receiver and
runs workspace.restore. It reopens the same scientific project, saved watershed
selection and scientific profile in the received workspace. With --save-view,
it also reopens and compares the exact saved native journey and operating notes.
The archived
application includes the desks, source inputs and opening script.

The transfer directory retains selection.json and received-project.json.
Its destination identifies one snapshot, including the selected native view
revision when --save-view is used. Reuse that same destination to resume
its original task identities after interruption. Choose a new destination when
capturing later workspace changes.

When --prepare-only is omitted, the launcher starts the operator from the
received application's own source against its received workspace. The original
project identity is preserved; the current operator workspace key changes with
the receiving directory. Guided journey resolves the selected records in that
current project when the opening file is imported.

## Operating sequence

1. Open the saved Lower Tugaloo selection and its parent regional report.
2. Read the retained source geography and classification coverage.
3. Open the selected scientific profile, inspect its coefficient table and
   save a clearly described working change.
4. Open an actual experiment or completed native comparison and inspect its
   physical quantities, units, grid and profile selection.
5. Configure and solve a decision study using those retained outcomes.
6. Export the original report and reopen the transferred scientific project.

The default opening prepares regional context and a scientific profile. Native
ecological runs are started through the original model controls using their
selected source data and grids.
