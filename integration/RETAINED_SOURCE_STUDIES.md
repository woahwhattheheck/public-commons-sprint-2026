# Retained source context and native-study delivery

The maintained operator now connects original point-source records, native landscape comparisons and saved Programme deliveries through their existing workspaces and task queue.

## Install the complete application

Receive the complete selected application source and run its cumulative installer:

```bash
python -B source_tools/install_cumulative_application.py \
  --source COMPLETE_SOURCE \
  --output RECEIVING_APPLICATION \
  --archive RECEIVING_APPLICATION.zip \
  --scientific-source ORIGINAL_SCIENTIFIC_SOURCE
```

The installer joins the maintained conservation Programme, native-study export, retained point-source desk and Scenario source-context tab after the original scientific components. It keeps the current source collector, Monitoring edition, native supervision, model execution and saved report integrations. Repeating the component installers preserves an already composed source edition.

## Review original reported sources

Open **Point-source context** in the existing operator. Select the retained period, annual-series, routing-relation and cohort tables. Review the coverage and source calendar, then bind the source selection. The operation retains both annual and quantified-period observation editions together with the same source identity.

The source calendar keeps reported periods, original pollutant species, quantities and their represented support. Gauge routing and polygon containment are separate fields. For the original Eighteenmile source, three facilities are upstream of gauge 02186702; the fourth lies within the unsplit basin polygon downstream of the gauge.

See [the original-source guide](../source/POINT_SOURCE_CONTEXT.md) for the table contracts and command-line intake.

## Add context to a completed native comparison

Open **Scenario analysis → Source context**. Select the completed analysis region and its relevant retained point-source binding and gauge. Review the original source calendar and geometric overlap, then retain the contextual report.

Native physical rows keep their own units and paired valid support. Reported facility amounts retain their source periods and geographic relationships. The report provides HTML, JSON and CSV files alongside links to the original observations.

See [the Scenario source-context guide](../operator/ANALYSIS_SOURCE_CONTEXT.md) for the selection, export and receiving contracts.

## Export a native study from a Programme

Open a Programme containing completed NDR and SDR for its original-land-cover baseline and one or more same-profile land-cover alternatives. Choose **Export native study**, review the selections, enter the study title and purpose, and build the maps and report.

The existing delivery operation creates five model-derived map families and retains the original grid, parameter profile, input records, scenario changes and runtime. The Programme and completed task both link to the saved delivery. A teaching case should retain its simulated-input identity in the study title, purpose and source records.

See [the native-study operator guide](../operator/PROGRAMME_NATIVE_STUDY.md) for the exact UI path and API selection. Regional RFP deliveries continue to use their complete source-role, regulatory-overlay and metadata-contact requirements.

## Save and reopen

Create the portable workspace through the existing application workflow. Independent restore verifies the original point-source bindings and Scenario source-context dependencies before publishing the restored workspace. Reopen the saved Programme, delivery and contextual report through their original identifiers.

The CLI Programme catalogue also lists saved conservation studies and completed attribution results. Extension navigation preserves the currently selected desk when an obsolete asynchronous mount finishes with an error.
