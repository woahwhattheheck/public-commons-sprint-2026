# ClickHouse Acceptance Workbench

Move an agreed ClickHouse data edition into a separate candidate, compare every selected typed cell, choose the accepted consumer binding, and hand the whole editable project to its receiver. This package includes the original application, managed Applications, customer-agent tools, Installation work orders and the source needed to continue that work.

## Follow the complete customer workflow

1. Retain the complete source/target acceptance input, exact table and column selections, identities and approved observation boundary.
2. Compile and review the original candidate-transfer plan and its full comparison projection.
3. Run the original transfer into separate `commission_` candidate tables, then a fresh verification of the selected source and candidate.
4. Inspect the full typed comparison, choose the consumer declaration and exercise its original rollback.
5. Derive the agreed existing read-service source with an explicit change record, then export and independently receive the complete project, native observations and history.

The original adapter supports one to five scalar table pairs with reviewed MergeTree or ReplacingMergeTree semantics. It preserves exact integers, decimals, binary values and explicit nulls in its retained typed observations. The complete operating guide explains the actual limits, source-stability boundary and uncertain-write recovery. The consumer presents the selected retained native export with `liveQuery: false`; a new current observation comes from a deliberately selected verification job.

## Prepare the selected application

Use Linux, Node 24, CPython 3.11 or newer and the existing `flock` command. The Python HTTP worker uses its standard library. Customer source and target are their existing approved ClickHouse servers; this preparation observes the selected host interpreter and retains the complete original worker and source.

Keep private workspaces, auth files and runtime directories separate from packaged source. Run the installed command:

```sh
starforge clickhouse-acceptance-workbench-prepare prepare \
  --directory /absolute/private/clickhouse-preparation \
  --python /absolute/canonical/python3

starforge clickhouse-acceptance-workbench-prepare inspect \
  --directory /absolute/private/clickhouse-preparation
```

The result retains distinct primary and independent receiving application/runtime selections. Use the actual returned `PREPARED.json` application and runtime-ready paths when configuring the **clickhouse-acceptance-workbench** Applications provider. The preparation guide supplies exact same-request resume, export and independent receive commands; the operating guide supplies the private launch/auth schemas and original connection configuration.

The customer adapter uses the original HTTP/RowBinary route to reviewed endpoints. The original local reference course uses its owner's selected ClickHouse 26.8.24.9 binary and saved fixture request. Preserve that original course and its actual result; it is separate from preparing a customer's connection.

Review and Save the complete launch selection in Applications, complete its original connection adoption, then Start the saved application. Applications Stop drains the observer and its handles; accepted detached native jobs retain their original lifetime. Use the original `job.cancel` control for an explicit cancellation, and the original resolution flow for uncertain native effects.
