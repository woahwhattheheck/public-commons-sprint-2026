# Replication Workbench

Replicate an agreed data edition, compare every selected typed row, choose the accepted consumer snapshot, and deliver a complete editable project to its receiver. This package includes the original Sling application, managed Applications, customer-agent tools, Installation work orders and the full source needed to continue the work.

## Start with the customer workflow

1. Retain the complete source configuration and data with their original identities.
2. Compile and review the exact replication plan, including keys, cursor, types and adaptation issues.
3. Run the original native baseline and changed edition.
4. Inspect the complete typed comparison, select the consumer and exercise its original rollback.
5. Export the whole project and independently receive and reopen it with its source, results and history.

The maintained reference imports original CSV into SQLite and replicates separate SQLite snapshots. Other connector pairs need their commissioned execution and complete snapshot/export adapters. Its source-derived expected final population is 1,002 rows; actual operation results belong to the original receiving course.

## Prepare the selected runtime

Use Linux amd64, Node 24, Python 3 with its standard SQLite library, and the existing `flock` command. The standalone application uses Node built-ins and requires no npm dependency installation. Keep private workspaces, auth files and runtime directories separate from the packaged source.

Run the installed `starforge` command:

```sh
starforge replication-workbench-prepare prepare \
  --directory /absolute/private/replication-preparation \
  --python /absolute/canonical/python3 \
  --archive /absolute/retained/sling_linux_amd64.tar.gz

starforge replication-workbench-prepare inspect \
  --directory /absolute/private/replication-preparation
```

The selected Sling 1.6.5 Linux amd64 archive is **121,317,497 bytes**, SHA-256 `e4e386c7d4429b33a213c146594be0bf6efa38f4732035dd67e307616fcb9c66`. The original installer can acquire that exact release when the optional archive argument is omitted. Preparation retains two independently verified application/runtime installations and their complete portable transfer.

Use the actual returned `PREPARED.json` application and runtime-ready paths when configuring the **replication-workbench** Applications provider. The preparation guide gives exact same-request resume, export and receiving commands; the operating guide supplies the private launch/auth schemas. Applications Stop closes the observer; accepted detached native jobs retain their original lifetime and use the original explicit cancellation control.
