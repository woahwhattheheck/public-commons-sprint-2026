# Audit Exchange — complete installed package

Audit Exchange preserves original building-audit XML, official validation results, source-bound review decisions, energy-analysis inputs and results, and independently editable recipient returns. This package also carries the maintained Grant Operations Customer installations route: prepare an Audit Exchange work order from the actual case and selected plan, review its complete input, save it to that same case, and receive the completed installation through its original operation.

The application was already public in full. This selection preserves its 82 source members and adds the previously missing Installation preparation/receiving route and guides. It does not replace the native audit engine, the saved recipient-return history, or an ongoing receiving controller.

## Build from one complete source edition

From the repository checkout, use the existing builder and name the actual selected commit:

```sh
node stellar/scf-starforge-20261009/distribution/build.mjs --repo . --ref COMMIT --selection audit-exchange --out /absolute/path/audit-package
```

Use a real commit in place of `COMMIT` and a new destination belonging to this operation. The builder resolves the selected contributions, follows maintained module/browser declarations, constructs the runtime package and records the full source identity. A prior directory is resumed through the builder's documented `--resume` operation with the same selection. Its `--status` reads the saved build state. Do not turn an incomplete prior directory into a different selected product.

The installed command form is `starforge COMMAND ...`. The package selects the Audit application, Merchant tools, Grant Operations through its current full contribution. The retained base distribution, provider registries and current full Grant contribution are reused unchanged. That Grant contribution now provides both maintained work-order commands and their shared module export, together with its actual Source Desk and collection commands. The Audit selection preserves this complete current source.

## Native runtime and source requirements

The Audit package declares Node.js 22.16 or later for its SQLite-backed engine. Actual analysis additionally uses Python 3.11 or later, the original lxml environment, R 3.5 or later and the declared nmecr/R dependencies. The maintained native runner also relies on the documented POSIX locking and inherited-descriptor behavior. Use the installation's actual runtime paths and dependency records; source presence alone is not a working native analysis runtime.

The retained analysis dependency file identifies nmecr 1.0.18 and its original source commit. Keep the selected nmecr source index and R packages together. The application offers Mean, SLR, change-point, degree-day, TOW and TOWT models through the maintained engine. Run the selected model through that original R engine and retain its complete inputs and returned outputs with the saved analysis.

The source inventory includes the complete recipient browser and returned-review machinery, official standards and analysis source. Keep the whole directory. Moving only a server file or the HTML shell loses runtime-selected source and original exchange behavior.

## Work from the retained original XML

Import the complete original BuildingSync or gbXML file. Inspect the actual entities, references, time series and official validation output. The system retains the original file and each accepted revision.

Use source comparison to inspect literal field/reference changes. A field patch binds its expected original values; a source replacement creates a complete new revision. Structural XML paths identify source locations, not an invented stable business entity across arbitrary reorganizations. Keep source revision, entity and scope with every review or downstream link.

Review decisions retain actor, state, notes, evidence and the selected source. A saved edition freezes its selected reviews, links and analyses. Later edits create later work; they do not silently restate a previously delivered edition. Current and earlier-source review states must remain visibly distinct.

The native energy model binds actual building/scenario/resource-use data, units, weather, time zones and periods. Missing information remains missing. The complete analysis run, inputs, selected model and original output are part of the handover. Resume the original queued run when necessary rather than issuing another scientific job to obtain a cleaner-looking status.

## Prepare the Installation in the existing customer case

Open the existing Grant Operations **Customer installations** desk for the actual customer case. The Audit profile is selected by the maintained preparation command; the guide does not assume a profile dropdown in that desk.


The installed `starforge grant-installation-workorder` dispatches the same maintained preparation module; the current Grant contribution also provides `grant-installation-receive` and the original shared work-order export. Use the current common guide for the exact receiving input and saved-operation continuation.

The seed is an actual Installation workshare seed from the existing customer case and selected plan. Preserve case identity/version, plan digest, original source references, original task ownership, deployment identifiers and receiving host/operator. Complete the explicit binding file with facts from that operation. An example plan, sample source scenario or default package fixture is not a substitute for the customer's seed.

Preparation writes the complete `installation-input.json`, `installation-preview-input.json`, `WORKORDER.md` and `preparation.json`. Load the prepared input in the original desk, review the preview and save it through the same case's compare-and-swap operation. For a saved Installation, its existing edition can be used as a new draft; do not rewrite a frozen prior edition.

The Audit profile preserves the complete installation, source transfer, native runtime, review/analysis, independent receiving and closeout steps. Keep actual payment and workshare terms separate from technical completion.
