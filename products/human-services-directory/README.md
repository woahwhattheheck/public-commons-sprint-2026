# Human Services Directory

An installed workspace for importing and refreshing service directories, reviewing the original records, selecting a service destination and handing over a complete editable referral package.

The product connects original Open Referral HSDS source with HL7 FHIR Human Services Directory and the existing Gravity referral workspace. It preserves source records, original relationships, explicit mapping decisions, service availability interpretation and the selected clinical resources through the same operator journey.

## What an operator can complete

- Import complete HSDS JSON, individual CSV tables or CSV archives, FHIR JSON or JSON archives, and retained provider captures.
- Review the original schemas and publisher material alongside complete source rows, relationship targets and SQLite indices.
- Assess declared tabular relationships, inspect every original target candidate and matching edge, and distinguish an empty received table from an unavailable or unselected target.
- Freeze editions, compare successors, and resolve ambiguous identity links explicitly.
- Review the complete mapping preview, apply its retained rules, and inspect every generated resource, source-field cell and finding.
- Select a service using retained criteria, capacity and schedule interpretation, with explicit dispositions for the original candidates.
- Join the chosen directory destination to the exact original Gravity Task and ServiceRequest bindings in a successor edition.
- Prepare a complete handoff, receive it into another editable workspace, reopen it and retain the receiving decision.
- Prepare a complete operating procedure from the selected native records, edit and reopen its original revision history, receive customer copies and export JSON, Markdown and HTML.
- Operate the same workspace through the browser, native CLI, typed SDK, Merchant MCP and installed Applications.

## Customer correction worksheets

Select complete original rows, send a self-contained offline customer worksheet, receive the unchanged returned file and review every typed field/presence change. The review prepares the existing correction plan; preview and acceptance remain separate operator actions. Complete source files, offline editor assets, original reasons, explicit decisions and accepted editions survive cold customer receiving.

[Worksheet workflow](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/CORRECTION_WORKSHEETS.md), [native course](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/CORRECTION_WORKSHEETS_OPERATING.md), and [operator/customer/Merchant course](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/CORRECTION_WORKSHEET_CLIENTS.md) cover the complete installed feature.

## Three-way customer review

Use **Three-way review** when a returned worksheet belongs to an older edition. Explicitly match every original row to the selected current edition, review full base/customer/current values, and record each decision. Structural differences can use a complete current-row replacement. The saved review prepares an ordinary correction plan; preview and acceptance remain separate. Full source, return, comparison and review files travel in the editable customer packet.

See [WORKSHEET_RECONCILIATION.md](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/WORKSHEET_RECONCILIATION.md), [native receiving](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/CORRECTION_WORKSHEET_RECONCILIATION_OPERATING.md), and [browser/Merchant/customer receiving](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_directory/CORRECTION_WORKSHEET_RECONCILIATION_CLIENTS.md).
