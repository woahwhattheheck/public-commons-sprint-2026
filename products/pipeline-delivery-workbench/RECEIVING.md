## 1. What is completed by this course

The receiving operation is one durable continuation under a private directory. It attaches the existing installed Merchant runtime through Runtime Workspace, starts the original Staff server through Applications, uses the actual 21-tool customer-agent catalogue, and stops each actual managed observer before reopening it.

The original Staff application has one private capability and a selected writer. It does not have invented operator/viewer roles. Every new mutation retains the complete original fields:

```json
{
  "action": "project.update",
  "payload": {"id": "the-original-project-id", "description": "reviewed text"},
  "workspace_id": "the-original-workspace-uuid",
  "expected_revision": 17,
  "request_id": "one-retained-request-uuid",
  "selection": {
    "root": "/absolute/selected/writer",
    "receiving_id": "original-or-the-actual-received-id",
    "workspace_id": "the-original-workspace-uuid"
  }
}
```

The numbers and IDs in that illustration are placeholders, not programme input. The actual course reads the current original snapshot and freezes those values before dispatch. A workspace UUID can be shared by a received fork, so it cannot replace the full selection. Replaying an original accepted request returns its retained response before checking a newer current writer.

The course reads every source file from every project edition, every retained native artifact, complete log pages, all project entity pages and the complete audit. It checks bytes and SHA-256 values from the native source. It then inspects a full source ZIP, saves one explicit documentation edition through a declared input, replays that exact request, reviews the existing successful native outcome and creates a scoped client release. The new documentation edition remains distinct from the edition that the original native run actually executed.

The browser opens the actual original application at desktop and narrow width. It operates source, contract, binding, native run, comparison, review, release, receiving and history views. It downloads every selected native artifact and saved source. A single project update is retained before dispatch; its successful acknowledgement is deliberately lost, then the same original IndexedDB request is reopened and replayed. No extra pipeline run is used to demonstrate request recovery.

After that edit, the course exports a new complete workspace backup. The independent receiver opens this exact ZIP through the original receiving API, verifies the full selected history, records a local project edit, switches to its original empty writer and back to the same received directory, and receives the same archive again. That last action must preserve the later local edit. Complete receiving release and onward backup ZIPs are retained. Both managed observers then stop and cold reopen, keeping their original selected directories and native identities.

The browser also opens the real extracted client handover HTML and its complete records link. It captures the actual desktop/mobile views. The producing operator must look at those images and inspect the actual outgoing archives before calling the product ready for a customer. An automated successful course is not a substitute for that visual inspection.

## 2. The three complete deliverables

Keep all three parts together in the receiving handoff:

| Deliverable | Contains | Receiving method |
|---|---|---|
| Complete selected Merchant distribution and source manifest | Applications, customer-agent tools, source viewer, private setup, preparation and this course, all original40 sources, maintained shared dependencies | The original Runtime Workspace distribution receive/install process |
| `pipeline-delivery-runtime.tar.gz` and PREPARED/identity records | All40 original sources, the exact complete wheel inventory, installed payload identity, dependency versions, original source authority | `pipeline-delivery-workbench-prepare receive` on the selected compatible host |
| Original and onward native ZIPs | Complete project/workspace state, source history, original requests, native outcomes and artifacts, reviews and client handover | Original Staff receiving or original `cli.py receive` |

The runtime tar reconstructs environments; it does not relocate a venv. Receiving requires the explicitly selected compatible base Python binary/version/ABI/platform and uses the retained wheels offline. The native workspace ZIP is produced by the original application. A complete backup includes its original persistent Dagster instance. A scoped client release keeps that client's history, source, native outcomes and artifacts, while excluding the all-client Dagster instance and external profile credentials. The ZIP does not automatically contain the surrounding Merchant adapters or its private host configuration. The distribution and runtime handoffs cover those separate scopes.

Capabilities, tokens and external profile secrets remain private. The course does not copy the capability-bearing original `browser-input.json` into customer artifacts. Its private live connection/launch files and original Staff capability are for the local owner.

The primary observer uses the original Staff control directory, including its current selected received writer and native request history. The receiver uses a separate workspace/control tree. It adds only its authenticated managed-info endpoint around the original Staff/Handler.

A pending or unavailable owner observation does not permit another start. A launched request stays owned until the original Applications output confirms terminal closure; an inactive `PENDING`, `QUEUED`, `INTERRUPTED`, `OBSERVATION_UNAVAILABLE` or `RECEIVED_HISTORY` observation is unfinished. The course retains the same request and observer handles while shutdown is unresolved. Stopping the observer does not cancel an accepted native Dagster/dbt worker: native cancellation remains the original explicit `run.cancel` action.

The agent configuration has immutable editions as new SHA-bound input files become available. Each edition declares its exact source ZIP, complete original request JSON or delivery ZIP.
