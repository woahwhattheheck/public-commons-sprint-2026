## Prepare the actual runtime

Use an existing Linux host with Node 24, a CPython release compatible with the original pinned packages, standard venv support and kernel flock. Select its actual compatible binary and retain the original virtual-environment invocation path. Do not resolve a venv Python symlink into a different base environment.

The original packages are Dagster **1.13.26**, dbt-core **1.12.5** and dbt-duckdb **1.11.0**. The original installer resolves their compatible binary wheels, then retains the complete installed distributions and wheel population. An independent environment is installed offline from those exact wheels and compared against the selected runtime identity.

Adopt the original approved environment when it already exists:

```sh
starforge pipeline-delivery-workbench-prepare prepare \
  --directory /absolute/private/pipeline-preparation \
  --python /absolute/existing/base-python \
  --runtime-python /absolute/original/runtime/bin/python

starforge pipeline-delivery-workbench-prepare inspect \
  --directory /absolute/private/pipeline-preparation

starforge pipeline-delivery-workbench-prepare export \
  --directory /absolute/private/pipeline-preparation \
  --output /absolute/private/Pipeline_Delivery_Runtime.tar.gz

starforge pipeline-delivery-workbench-prepare receive \
  --directory /absolute/private/pipeline-received-runtime \
  --python /absolute/receiving/base-python \
  --archive /absolute/private/Pipeline_Delivery_Runtime.tar.gz
```

These paths are examples. Omitting `--runtime-python` explicitly prepares the original dependencies without starting a customer pipeline. A selected binary wheel must exist for the actual receiving environment; source builds or changed package versions are not silently substituted.

Use actual returned `primary` and `receiving` values for `applicationDirectory`, `programmeDirectory`, `runtimeReadyFile`, `python`, `dbt` and `runtimeId`. The environments and their final paths are separate. A runtime tar recreates an environment from its exact wheels; it is not a relocated virtual environment.
