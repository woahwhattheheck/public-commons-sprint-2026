# Complete Analysis projects

Open a delivered analytical project, continue its editable customer workspace, and hand the next operator the full project. The product joins the original Analysis application, Python installation, complete archive receiver and offline project reader.

A project contains the retained source responses, dataset editions and typed rows, saved SQL and parameters, reports, workbook editions, source code and native runtime. Open its `project.html` for the complete offline reader. Use **Applications → Open Analysis project** to work in the same native database.

## Installed workflow

1. Select the source-owned **analysis-project** distribution and install it through the existing runtime installer.
2. In the runtime workspace, install its original Python package with Python 3.12 or later. Select the returned installation ID.
3. Add **Open Analysis project**. Select the complete ZIP or extracted directory, a private customer database destination and that Python installation. Applications verifies the complete selection before launch.
4. Continue the original queries, reports, source review and workbook work. Stop the application through Applications when preparing a following handover.
5. Add **Export complete Analysis project** with the same database and source project. Its original archive operation produces the complete ZIP, offline reader and editable workspace. Keep that operation and output directory for retries.

The open and export entries share the original Analysis database resource. The project keeps its own verified Python and Node source cohort, and the native listener retains its original PID, private launch record and workspace identity. A repeated receive preserves later customer revisions.

[Operating guide](OPERATING.md) covers installation, command arguments, database ownership and complete export. [Receiving guide](RECEIVING.md) follows the original delivered project through installed opening, continuation, handover and independent reopening.
