HIGHWAY FIELD OPERATIONS

Staff operating guide

Use a captured asset record to collect field work, review a complete submission, coordinate the crew, compare approved changes and hand over the editable workspace.

Return to the workspace

1. Open the workspace and its source edition

Open the private launch URL provided for this workspace. It grants access to this local working directory. Keep the complete source package and OPERATING.md with the handover; that document contains the exact installation, start, capture and receiving commands.

  1. In Source editions, set your actual name and operator reference before saving work.
  2. Select the complete original capture folder and choose Import complete capture folder. Keep its manifest, original response files and attachment files together.
  3. Review the service, layer, capture date, source coverage and observations. An incomplete or changed capture remains visible as such; obtain the required following edition before relying on complete coverage.
  4. Select the actual source edition and layer for the work. Form choices and asset identities come from that retained edition.

The capture process reads the published service and preserves its original records. Source capabilities belong to the selected edition: available fields, domains, geometry, related tables and attachments can differ between services and editions.

2. Configure a collection form and record an inspection

In Collection forms, map the required source fields and choose useful labels. Add local observations where the crew needs information beyond the source schema. Set required fields, read-only fields, geometry permissions and attachment allowances deliberately, then save the form edition.

  1. Open Field inspections, select the saved form and the actual source asset, and start or reopen its inspection. For assigned work, use Inspect asset from the assignment so its relationship is retained.
  2. Enter answers using the displayed source type and domain. Choosing a subtype updates the applicable coded-value choices. Original values remain available for review.
  3. Use Null for a value that is absent. Empty text remains an intentional empty string. Numeric blanks are not measurements.
  4. Record the field note, any permitted geometry correction and the full local attachment set. Coordinate values retain their original spatial reference.
  5. Save the complete edition, then choose Submit saved edition. Save later edits before submitting them.

A form revision creates a new edition. Earlier inspections retain the form they used. Local photos and observations are preserved with the inspection and complete workspace.

3. Review the exact submission and prepare approved changes

In Supervisor review, open the submitted inspection and compare its answers with the original source record, form edition, notes, geometry and attachments. Approve, return or reject that exact submission and retain the reason.

Returned work can be corrected and submitted again. Each saved correction and decision remains in the inspection history. A correction or source rebase creates a draft requiring its own submission and review.

In Approved proposals, select the current approved inspections to prepare the candidate changes. Compatible changes to the same asset combine; conflicting field or geometry changes need resolution before the proposal can be saved. The saved proposal retains the approved editions that produced it.

An approved proposal is the reviewed local change set for the agreed implementation. Applying it to a production service requires the customer’s selected destination, supported edit route and returned per-record outcomes. The proposal and its source remain portable throughout that implementation.

4. Coordinate crews, assignments and follow-through

  1. In Crews & assignments, create the actual crew and members, the operating package and the assignments. Select the original form and asset for each assignment.
  2. Use Inspect asset to open its field work. The application saves the inspection and assignment link as separate retained requests; continue the saved original request if that second step is interrupted.
  3. Move the assignment to the appropriate working status. Submission requires its linked submitted inspection; closing requires a current approved inspection. Reopening preserves earlier closure history.
  4. Record actual effort independently from estimates. Correct an erroneous effort entry by voiding it with a reason and entering the corrected record.
  5. In Follow-through, record the responsible person, due time and status for each required follow-up.
  6. Freeze an operating report for the intended reporting edition and download its complete report or readable document.

The report brings together crews, work packages, assignments, recorded effort and follow-up work. Keep the reporting edition with the corresponding handover.

Named field copies and returned work

Use Field copies & returns to give a named colleague actual saved inspections and receive their work alongside newer supervisor changes.

  1. Set the actual operator in Source editions. Open the required inspections; for assigned work, use the assignment's Inspect asset action first.
  2. Enter the recipient name and reference, select saved inspections and add instructions. Choose Prepare field JSON and editable HTML. Download both exact original files from Issued field copies.
  3. The colleague opens the self-contained HTML, reviews the original source and assignment, edits the permitted observations and retains added files. They save attributed named editions when complete, or download unfinished work without inventing a completed edition.
  4. Select the whole returned JSON or HTML and choose Retain and receive selected file. This preserves every named edition, unfinished draft and attachment before any inspection is changed.
  5. Select a named edition and choose Compare with current inspections. For every inspection, select Keep current inspection or Apply reviewed field observations, give a reason and resolve conflicting values. The issued, current and returned values remain visible separately.
  6. Choose Save receiving decisions. Changed observations become ordinary draft or corrected inspection versions. Continue normal submission, supervisor review and assignment follow-through.

Changed form or source bindings require keeping the current inspection and reviewing it through the original source/form workflow. An unfinished return remains available for download and history, but has no named edition to adopt. A field colleague's saved edition does not grant supervisor approval.

Field request recovery retains original inputs and results in the selected directory. Continue the same pending request; inspect its original saved result before preparing a revised request. Current comparison review keeps earlier local choices visible.

After saving decisions, Open original receiving comparison shows the exact historical three-value review and saved choices. This read-only view remains available after independent receiving.

The full handover carries exact issued JSON and HTML, original returned files, source and attachment bytes, decisions and inspection histories. After receiving the complete workspace into another directory, reopen this screen to download and inspect the same files and continue work. FIELD_EXCHANGE.md contains complete file and business contracts; OPERATING.md contains native CLI examples.

Each complete field file is limited to 64 MiB including embedded content; unfinished drafts have a 4 MiB allowance. The source and archive limits remain those of the complete workspace. Capacity errors never silently shorten the chosen source or remove retained evidence.

5. Review a following source edition

Import the next capture alongside the original. Open the existing inspection and review its source assessment: changed fields, geometry, attachment inventory and schema belong to that later source edition.

  1. For each mapped conflict, choose Keep inspected value or Use current source value after reviewing both values.
  2. Choose a compatible new form edition when the schema or mapped fields change. Unmapped source attributes remain in the captured record.
  3. Rebase the inspection. This saves a new draft against the selected source while retaining its earlier versions.
  4. Save, submit and review that new edition before preparing a new proposal.
  5. For linked crew work, choose Refresh this assignment to adopt the inspection’s current source and form. Review and close the refreshed work through its normal workflow.

Original ObjectID and GlobalID bindings distinguish the intended asset across editions. A different GlobalID requires deliberate asset handling even when an ObjectID has been reused.

6. Compare captured values with an approved proposal

Dataset reconciliation uses the included original comparison engine. The operating guide explains how to connect its existing warehouse. A comparison can use two captured editions or one captured edition and an approved proposal.

Prepare and import both editions

  1. Select the Captured source edition, Saved collection form and Values to prepare. Choose the captured values for one side and the intended approved proposal for the other.
  2. Review the ObjectID delivery column and Complete field mapping. The initial mapping keeps the original ObjectID and complete feature JSON, including attributes and geometry. Additional mapped columns can support field-specific review.
  3. Choose Prepare complete original delivery. The original producer creates and finalizes the actual selected rows.
  4. In Prepared deliveries, choose Review original import. Inspect the retained projection, source identity, columns and row coverage.
  5. Choose Import reviewed edition for each reviewed side. Both imported editions remain independently identified.

Define and run the comparison

  1. Choose the source and target editions, a pair name and a useful review title. Check the column mapping: keys identify corresponding records; values identify what is compared.
  2. Choose Review comparison definition and inspect its full returned definition.
  3. Choose Save reviewed pair using the current pair revision. A new pair starts at zero; an edit uses that pair’s actual saved revision.
  4. Choose Run original comparison on the saved definition.
  5. Use Open grouped differences and Open complete row page to inspect the actual results. Continue through Next full page wherever more rows remain.

Record decisions and deliver the review

  1. In Record supervisor reconciliation, select the actual comparison, group or source/target row number, decision and reason.
  2. Choose Save original review decision. The comparison retains its review history and current review edition.
  3. Choose Freeze complete review report after recording the intended decisions, then Export complete native package.
  4. Choose Receive independent native workspace on that saved package to restore its original source and target editions, comparison, decisions and report into a distinct warehouse.

The complete Highway workspace retains the associated native requests, results and package files. Use the whole-workspace handover below to deliver the field history and comparison work together.

8. Export, receive and reopen the complete work

  1. Finish the intended saved work and open Handover & receiving.
  2. Choose Prepare complete handover, then Download complete workspace.
  3. Keep Highway_Field_Workspace.zip and its displayed byte length and SHA-256 together. It contains source records and attachments, saved commands and first results, complete revisions, retained publications, native comparison files and the selected application source.
  4. In the receiving workspace, select that complete archive and choose Inspect and receive full archive.
  5. Use the returned opening directory with the guide’s serve command to open the independent editor. The received source directory contains its own operating guide.

Receiving checks the original business history and source files before publishing the independent working directory. Repeating the same receiving operation preserves valid later edits in that directory. Keep the immutable delivered archive alongside the continuing editable workspace.
