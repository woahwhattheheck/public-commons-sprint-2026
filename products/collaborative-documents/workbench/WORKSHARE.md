# Tiptap / Hocuspocus application migration workshare

## Proposed engagement

TokenJunkie Labs proposes one complete customer application migration and operating handoff for **USD 8,400 fixed**, delivered in **12 business days** after the application, source population, host, identity adapter and written scope are accepted.

The engagement adapts the completed application source around the original Tiptap, Hocuspocus and Yjs engines. It covers the customer's actual source-to-collaboration path and the operating work needed to receive and maintain it.

This is a proposed implementation offer. It is not a customer order, a partnership announcement or a claim that a customer deployment has already occurred.

## Included scope

One application, one deployment host, one existing authentication/identity adapter and one agreed Tiptap document schema. The intake includes up to 1,000 source documents, at most 512 MiB of original source in total, and at most 32 MiB for an individual document. Supported agreed inputs are Tiptap JSON, HTML or native Yjs v1 update bytes.

The delivery includes:

1. Source and schema review, original-byte intake, field/tenant/document mapping, visible handling of unsupported schema content, and a retained migration decision for every document.
2. Native Yjs binary migration and persistence, original Hocuspocus deployment, and the customer's existing identity adapter with explicit operator/editor/viewer and tenant/document grants.
3. A working operator/editor interface for source review, migration, document access, actual deployments, durable-save status, checkpoints, restored epochs, reviews and history.
4. Two-client collaboration, a pure deletion, offline reload and reconnect/merge, read-only and tenant isolation, and revocation of an earlier document epoch after explicit content restore.
5. Configuration/runtime rollback that preserves current content, retained original job continuation after interruption, complete source/operator documentation, and a receiving package exercised on a fresh private workspace.
6. Deployment to the accepted host, two consolidated review rounds, a 60-minute engineering handoff and ten business days of correction for defects within the delivered scope.

The reference uses the original pinned open-source engines. Any additional paid extension, cloud subscription, host charge, expanded custom schema or additional application/host is agreed separately before it is included.

## Acceptance

Acceptance is the recorded operation of the agreed customer workflow with the complete delivered source and original engines:

- Every accepted source document has a retained original identity and an explicit migration outcome. Unsupported or excluded material is visible in the reviewed mapping.
- Authorized editors in the same document merge concurrent and offline changes through native Hocuspocus/Yjs. The storage receipt binds the full persisted binary, including a deletion.
- A viewer cannot commit edits, another tenant cannot access the document, and revoked or earlier-epoch clients cannot continue writing to the current target.
- The selected original job can be reconciled and continued without repeating a committed migration.
- An explicit content restore creates a new epoch from the retained checkpoint; configuration rollback preserves current content.
- The complete package opens in a fresh private receiving workspace with original source, native documents, selected histories, reviewed decisions and editable source intact.

This acceptance is for the agreed application and population. It does not claim multi-region availability, unlimited concurrency or an unmeasured performance target.
