## What is implemented

chinook-native-input.mjs verifies the complete delivered native source directory and all ten pinned upstream files, checks the actual source receiver result, creates eleven independent expected typed exports, records explicit column-name and representation decisions, retains every original member into the existing project's source history, and compiles a complete native dlt input using actual returned source IDs.

relational-acceptance.mjs binds the actual completed job, its exact selection bytes and exact original observations bytes. It invokes the maintained full typed comparator and then evaluates every primary key, foreign key and invoice/control group across both full populations. It produces complete exception evidence and stable, source/job-bound exception IDs. It never marks a customer acceptance, applies a cutover or operates a rollback.

No row-count-only acceptance, samples or aggregate-only parity replace the original comparator. Both equal totals and full row equivalence are required. The additional relational result remains review evidence even when every check passes.

## Original reference meaning

The upstream source is Chinook 1.4.5, commit 7f67772503d71ba90f19283c38e93923addb43fa, authored at https://github.com/lerocha/chinook-database. Its README describes real media titles, fictitious customer/employee records and generated sales. These are reference records, not Definian customer data. Preserve the original LICENSE.md and all upstream bodies.

The published SQLite edition is the downstream source boundary. The upstream JSON generator input differs: nullable empty strings become SQL NULL, and local datetime strings use a space instead of T in SQLite. E496's complete receiver records every original-to-native change and every row's lineage. This adapter does not apply those changes again.

The schema has no currency field. Monetary controls use UNSPECIFIED_REFERENCE_AMOUNT. Country is not treated as currency; Track.UnitPrice is not substituted for InvoiceLine.UnitPrice.

## Compile and review the eleven-object input

    const {input, compiled} = buildPipelineInput(prepared, {
      sourceIds: retained.sourceIds,
      expectedSourceIds: retained.expectedSourceIds,
      pipelineName: originalPipelineName,
      datasetName: originalDatasetName,
      title: 'Complete Chinook relational reference',
      phase: 'baseline'
    });

Every resource is NDJSON with an explicit original-to-normalized fieldMap. All keys, including PlaylistTrack's ordered composite key, are retained. Native fields use bigint, decimal precision 10/scale 2, or text as appropriate. Original primary-key columns are non-null. The reference uses replace for the complete selected table edition, freezes column/type evolution, and disables nested expansion because the original inputs are flat objects. No merge, filter or deduplication is introduced.

Source-local DATETIME values intentionally use text. The reviewed original worker's timestamp coercion assigns UTC to a naïve value; doing so here would invent a timezone. This adapter records the original DATETIME declaration and keeps its actual space-separated source text unchanged. A customer-approved alternate datetime conversion requires a new explicit mapping and acceptance edition.

The expected files are dlthub.expected-table.v1: original column names/types, complete:true, rowCount and every typed row. Their cells are null or exact strings with explicit integer/decimal/text types. The acceptance mapping selects every business column and ignores only the original _dlt_load_id and _dlt_id metadata columns.

Retain JSON.stringify(input, null, 2) plus newline through the existing source.retain path. Then use the maintained actions, preserving each original request:

| Existing action | Required payload |
| --- | --- |

The adapter does not automatically review or approve the mapping. It also does not call job.start. The existing native owner chooses the actual stage and retains all original source, runtime and target state. The maintained loader already supports the complete eleven-resource programme. ## Evaluate the actual completed original output

After the original native job has closed, obtain its retained exact selection and observations from the same object store:

    const state = workspace.store.get(projectId);
    const job = state.jobs.find(row => row.id === actualCompletedJobId);
    const {plan} = workspace.planObject(state, job.planId);
    const observation = job.files.find(row => row.path === 'artifacts/observations.json');
    const selectionBytes = workspace.store.objects.read(job.selection.sha256, job.selection.bytes);
    const observationsBytes = workspace.store.objects.read(observation.sha256, observation.bytes);

    const report = evaluateRelationalAcceptance({
      prepared, plan, observationsBytes, selectionBytes, job,
      workspaceInstanceId: workspace.store.instanceId, projectId
    });

Supply the original bytes. The evaluator checks full byte counts and SHA values against the job before parsing. It binds the actual project, job ID, plan ID, complete selection, selected source and expected IDs, exact input hashes, all original target export descriptors, field mapping and explicit type hints.

It recomputes the original comparePipeline result from those exact observations. This preserves full business row multiplicities, typed values, complete schema coverage and native pending/failed-package checks. An equality claim passed by a caller is not accepted as a substitute.

Additional output contains:

- Complete primary-key results for both sides, including null-key rows and every duplicate's full key and row ordinals.
- All eleven relationships, including Employee's self-reference and nullable foreign keys. A nullable absent relationship remains distinct from a non-null missing parent. Full child ordinals and original keys are preserved for every orphan.
- Every invoice's exact original line-price × integer-quantity extension, header amount, difference and source/target row locators.
- Complete all/customer/billing-country/calendar-year controls. Integer quantities and amounts use BigInt minor-unit arithmetic; no binary-floating sum occurs.
- Differences between computed source controls and the original receiver's actual controls, plus all source/target control differences.
- Stable exceptions bound to the full source mapping, actual native job/plan/snapshot and full original observations.

A complete pass returns RECONCILED_FOR_REVIEW, accepted:false and cutoverApplied:false. Unresolved results return EXCEPTIONS_REQUIRE_REVIEW. Retain the entire JSON as a source/supporting artifact in the original product, along with its reportSha256 and original typed comparison. The original reviewer owns disposition, role, reasoning and any accepted business deviations. A later source, rule or native result generates a new report and exception identity; previous decisions do not silently migrate.

## Baseline, changes, rollback and independent receiving

This source has one published edition. Do not manufacture a second customer snapshot, delta or rollback operation to complete a demonstration. The native product already retains baseline/incremental/rollback phases and original closed job lineage. For an actual changed customer source, retain its full original artifacts, explicit new transformation/selection decision, parent job and target observation, then create a new bound comparison.

A proposed rollback and an actual original restore/reversal are different records. Acceptance after rollback requires its real operation and full observed target reconciliation. This component does not convert a saved historical report into evidence of an operated reversal.

For independent receiving, retain the whole maintained application/runtime, original E496 source directory, all project sources including generated expected tables and intake ledger, complete original native outputs/selection/runtime, typed comparison, relational report, reviewer history and existing complete project handover. The receiving operator opens the same project through the original archive receiver, re-verifies all source and target identities, reads the saved original job and reruns this read-only evaluator against its exact bytes. The report content is deterministic for unchanged source/plan/job inputs. No encoder, source acquisition or native migration is repeated merely to reopen evidence.
