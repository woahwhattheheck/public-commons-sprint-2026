# Complete offline original-case receiving

Open recipient.html for a blank install-free recipient. In the local Partner Batch Desk, select a case and Download offline recipient to receive its full original package in that same page. It uses the unchanged core importCase and report producers. No gateway access or mutation is available in this reader.

## Exact source and separate review

The original package text is retained exactly, including outer BOM, whitespace and final newline. UTF-8 decoding is fatal on malformed input; only a leading BOM is removed for outer JSON parsing. Internal case_text/source strings remain untouched. Original package download returns those same UTF-8 bytes. Hashes check exact copies; they do not establish authorship of an operator-supplied case.

Every case history/state, including running or uncertain ingestion, stays as received. The eight original gateway/example fields, mapping, response bodies and SDK identities remain governed by core.mjs. Returned DFIDs are listed independently. Only explicit original gateway row references support associations; unassigned results remain unassigned.

Recipient notes and reviewer name live in a separate recipient-notes/1 object bound to SHA256 of the exact original package text. They never alter case state, revision, source or operations. Save Recipient review JSON or Populated offline HTML to preserve them across closing the page. A received review with distinct annotations opens as a separate retained review copy. Choosing another case or a delayed/failed file read preserves existing case/review copies.

## Complete all-row reading

Both local and offline applications import source-reader.mjs. Search examines every original row number, original source value and selected item; the table mounts25,50 or100 rows. Counts identify matching and total rows, and every page uses original source row IDs. Download matching rows follows the search; All source rows always contains the complete original table. JSON-encoded columns preserve strings, missing fields, booleans and multiline content. Per-case reading state is cached in memory and, where available, browser storage. An offline received edition is keyed by the exact package hash, so distinct histories sharing a case ID do not collapse.

## Complete files

The offline page downloads exact original package, original source, exact selected request, all-row CSV, full original HTML report, separate recipient review, populated offline HTML and a complete hashed recipient source bank. The source bank includes every browser/build dependency, license and owner instruction; it contains no generated predecessor HTML and therefore does not recursively grow. The source itself and all original case bytes remain embedded in every populated receiving copy.

To build from existing files without installing SDK dependencies:

    node offline-recipient.mjs recipient.html
    node offline-recipient.mjs COMPLETE-CASE.json NEW-RECIPIENT.html

Existing output files are preserved. The HTTP server also serves /recipient.html and /api/cases/CASE_ID/offline. Source preparation and actual SDK operations stay in the original local app.

The original file-only receiver now includes recipient.html as a seventh retained content role. Its manifest explicitly declares the recipient edition. Reopening an existing six-role completed receiving validates and returns that exact older inventory unchanged; no upgrade rewrites its original files. New receiving validates all seven roles. Use a separate output for a newly generated reader edition.
