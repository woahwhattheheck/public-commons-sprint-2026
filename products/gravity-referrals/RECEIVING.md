## Complete native journey

Run the maintained original native program:

~~~sh
python3 ACTUAL_SOURCE_ROOT/stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_referral/operate_receiving.py \
  --source-root ACTUAL_SOURCE_ROOT/stellar/scf-starforge-20261009/sf30-seller-sdk \
  --output /absolute/private/gravity-native-receiving \
  --workspace /absolute/private/referrals \
  --examples /absolute/originals/Published_Examples.zip \
  --definitions /absolute/originals/Published_Definitions.zip \
  --node /absolute/installed/node
~~~

`--workspace` defaults to the output directory's `workspace` child. The explicit Node path selects the same interpreter for the original native dataset, merchant and customer operations.

The primary result is `OPERATED_GRAVITY_REFERRAL.json`. The original journal is `RECEIVING_JOURNEY.json`. Continue using the same selected source root, original input files, workspace and output directory.

The native journey operates the original published source and complete referral domain: reviewed topology, Task editions, every requirement and field row, assessments, authored decisions, exact correction and edition changes, original conditional HTTP exchange and readback, native dataset and customer receiving, full referral handoff and whole editable restoration.

Its full receiving files include:

## Restore the original workspace on the receiving host

Receive the full original editable archive into an initialized Gravity workspace:

~~~sh
starforge gravity-referrals init \
  --workspace /absolute/private/received-referrals

starforge gravity-referrals workspace-receive \
  --workspace /absolute/private/received-referrals \
  --input /absolute/originals/Gravity_Complete_Editable_Workspace.zip

starforge gravity-referrals status \
  --workspace /absolute/private/received-referrals
~~~

The native receiver restores the original UUID and complete source, dataset and referral records. The receiving directory is the path selected on this host. Keep the original `OPERATED_GRAVITY_REFERRAL.json` unchanged and pass `--workspace` to the later receiving programs when that selected directory differs.

The private marker remains `stellar-forge.eltss-workspace.v1`, and `eltss/identity.json` contains the inherited original UUID. Gravity's saved domain is in the same native workspace; its live connection is `referral/operator-connection.json`.

## Complete private browser journey

Open the selected original or restored workspace through the native operator or its saved Application:

~~~sh
starforge gravity-referrals serve \
  --workspace /absolute/private/received-referrals \
  --expected-workspace-id ORIGINAL_WORKSPACE_UUID \
  --port 0
~~~

Use the private URL returned by that actual startup:

~~~sh
node ACTUAL_SOURCE_ROOT/stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_referral/operate_browser.mjs \
  --url ORIGINAL_PRIVATE_OPERATOR_URL \
  --receiving /absolute/originals/OPERATED_GRAVITY_REFERRAL.json \
  --workspace /absolute/private/received-referrals \
  --output /absolute/receiving/gravity-browser \
  --playwright /absolute/installed/playwright/index.mjs \
  --chromium /absolute/installed/chromium
~~~

The browser driver uses the actual open operator and unchanged original receiving result. `--workspace` defaults to the original result's workspace path.

Its full journey opens the complete private referral interface, operates the original source and authored programme views, receives the complete editable workspace and retains the actual browser result, downloads and screenshots. The result is `OPERATED_GRAVITY_BROWSER.json` and the original journal is `BROWSER_JOURNEY.json`.

Continue the same original operation and output directory after an interrupted browser step. The browser helper also serves the installed Applications journey, so the same original workflow is exercised through the managed application.

## Installed Applications journey

Attach the selected complete READY runtime to the existing Runtime workspace. Use the unchanged original native result and actual selected Gravity directory:

~~~sh
node ACTUAL_SOURCE_ROOT/stellar/scf-starforge-20261009/sf30-seller-sdk/fhir_referral/operate_installed_applications.mjs \
  --runtime-directory /absolute/private/gravity-runtime \
  --runtime-workspace /absolute/private/existing-runtime-workspace \
  --receiving /absolute/originals/OPERATED_GRAVITY_REFERRAL.json \
  --workspace /absolute/private/received-referrals \
  --out /absolute/receiving/gravity-applications \
  --playwright /absolute/installed/playwright/index.mjs \
  --chromium /absolute/installed/chromium
~~~

The optional `--credentials-file`, `--environment-file` and `--label` select existing private runtime inputs and the application label.

The installed journey opens the Runtime host, attaches the READY installation, finds or saves the Gravity application, starts the original command and opens its actual private operator. It runs the complete browser journey and receives the whole editable workspace. It then stops the managed process, reopens the host, starts the same saved application and checks the retained original records together with work authored by the first browser journey.

The result is `OPERATED_GRAVITY_REFERRAL_APPLICATIONS.json`. The original `APPLICATIONS_JOURNEY.json` retains the selected native and Runtime workspaces, original result hash, application and both managed starts. Complete original request files, history, screenshots and the workspace packet remain alongside that result.
