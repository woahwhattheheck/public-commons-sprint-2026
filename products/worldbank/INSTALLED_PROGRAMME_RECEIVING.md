# Installed World Bank programme receiving

The installed entrypoint composes the existing complete product and recurring
customer course. It first completes or reopens the original managed Applications,
42-observation source edition, four reports, workbook and independently received
customer. It then prepares one explicit review change through the original World
Bank core and calls the maintained recurring and programme receiving engines.

Use the READY World Bank source-selected installation from the final combined
published source. Its manifest must include the original product receiver, the
programme manager, original recurring engines, live programme receiving extension,
this entrypoint and the reviewed-reference helper. The installed receiver's
Analysis digest must select that same complete reviewed engine. Do not overlay
new files into an already bound installation or change a saved receiving intent.

## Run

The existing native operation owner supplies the original READY runtime and
private receiving directory. Reuse that directory throughout this operation.
Select the actual existing Python workbooks dependency, Playwright and Chromium.
No runtime download or browser install is performed by this command.

~~~sh
starforge worldbank-product programme-receive \
  --runtime /absolute/worldbank-ready-runtime \
  --workspace /absolute/original-product-receiving \
  --python /absolute/python \
  --python-dependencies /absolute/original-python-dependencies \
  --playwright-module /absolute/playwright/index.mjs \
  --chromium /absolute/chrome-headless-shell \
  --process-family /absolute/checkout/products/x402api-merchant-workspace/process_family.py
~~~

Omit --python-dependencies when the original Python environment already provides
openpyxl==3.1.5. The selected Node is the executable running the installed product
command. Python 3.11 or later is required.

The process-family file is the unchanged original 13,765-byte helper, SHA-256
8522835d848533ff66b8fad6900c5c0c781eaae4967a5b5ac2f9dac1ed458412.
It may be supplied from its existing complete source checkout; this is an
explicit source selection, not a claim that another product's files are included
in the World Bank selected package. Its identity, browser executables, installed
commit and complete manifest are retained before receiving.

## The original A/B reference

The baseline is the actual 42-row handover produced by the original installed
receiver. The helper imports it into the original World Bank core, records one
review exclusion for Canada GDP in 2018, and exports the 41-row candidate.
Both handovers must have the same capture SHA. Every remaining typed observation
and all five native identity columns are checked. This is a customer review
change; it is not a new provider data revision. No new provider request or
additional merchant operation is made for the candidate.

The complete original recurring course uses these handovers to exercise customer
SQL, report sections, worksheet names and headers, historical report sources,
exact value tokens, workbook refresh, independent workbook/workspace receiving,
and later customer edits. Its existing operation and result files are preserved.

The existing live programme extension then uses the same course workspace and
original operation ID. It performs the real programme and source review UI,
desktop and phone captures, actual downloads, and recovery from its own delivered
workspace. The restored historical delivery remains INTERRUPTED with a validated
accepted edition. A new linked delivery reuses the accepted business results
without rebuilding those jobs. See PROGRAMME_RECEIVING.md for the full native
course and the original browser/family recovery rules.

## Saved results and continuation

The original product outputs remain at the receiving directory's existing paths.
The additive installed course retains:

- installed-programme-receiving/intent.json: exact installation, helper and runtime identities.
- installed-programme-receiving/reference/: original core workspace, complete review and A/B receipt.
- installed-programme-receiving/recurring-course/: the original recurring customer, deliveries, restored workspaces and full programme browser output.
- installed-programme-receiving/receiving.json: combined COMPLETE result, written only after both original courses finish.
- installed-programme-receiving/native-errors.jsonl: retained interruption and failure details.

Repeat the same command and selection to continue. A nonblocking operation lease
prevents another installed wrapper from writing the same course; busy returns75.
Each original engine retains its own request IDs, workspace leases and child
lifetime. Completed re-entry invokes the original byte and receipt verification;
it does not replace later customer definitions. Runtime or source identity
changes require deliberate original-owner reconciliation, not an automatic reset.

Preserve the whole original private receiving directory through the existing
operating-workspace save, including browser images, downloads and incomplete
family logs. COMPLETE is the native course's result. Buyer-facing screenshot
approval still requires a person or reviewing agent to inspect the actual images;
source review and syntax checks alone do not claim native or visual completion.
