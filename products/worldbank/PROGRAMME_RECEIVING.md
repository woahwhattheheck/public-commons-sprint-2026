# World Bank recurring course: live programme and portable continuation

This is an optional continuation of the maintained `worldbank_recurring_receive`
course. It reuses that course's original baseline and candidate handovers, customer
workspace, customer-edited SQL, report, workbook and operation ID. It does not
create another source collector or substitute synthetic provider observations.

The original native owner prepares the actual baseline and its explicitly reviewed
candidate through the maintained World Bank source engine. A 42-to-41 edition made
by excluding an observation from the same capture is a review change. Preserve its
original exclusion, provider pages and full row values. The original recurring
review records that comparison before this continuation begins.

## Run the complete existing course

Use the actual merged source checkout, installed original workbook dependencies,
and the existing selected Node, Playwright and Chromium. Do not run a second copy
of an already active course. The fixed receiving directory and operation ID stay
the same through interruption.

~~~sh
node products/worldbank/cli.mjs analysis --python /absolute/python \
  recurring-receive \
  --baseline-handover /absolute/original-A.zip \
  --candidate-handover /absolute/reviewed-B.zip \
  --workspace /absolute/original-recurring-course \
  --operation-id <original-32-character-lowercase-hex-ID> \
  --programme-browser \
  --node /absolute/node \
  --playwright-module /absolute/playwright/index.mjs \
  --chromium /absolute/chrome-headless-shell \
  --process-family /absolute/checkout/products/x402api-merchant-workspace/process_family.py \
  --source-commit <actual-40-character-merged-commit> \
  --resume
~~~

The product launcher supplies its original installed World Bank core. Direct
Python invocation may instead use the maintained module with explicit
`--worldbank-core /absolute/core.py` and the same options.

The selected process-family file is the existing unchanged 13,765-byte source,
SHA-256 `8522835d848533ff66b8fad6900c5c0c781eaae4967a5b5ac2f9dac1ed458412`.
Select its real path; do not provide another cleanup implementation. The helper
enters this original scope before opening the Analysis server or browser child,
waits the main Node process first, closes the original server and workspace, then
closes and retains the same family. Browser completion is adopted only after that
actual closure has been saved. No elapsed-time limit discards a completed return.

## Course and output

The original course first completes the real A/B source comparison, customer
edits, report/workbook delivery, independent workbook/workspace receive, lexical
source-value checks and completed-request replay. Its existing
`recurring-receiving.json` remains unchanged.

The continuation opens the same customer in the existing gray Analysis browser.
Its first phase receives the complete approved candidate ZIP through **Receive
approved handover**. The browser retains the original intake ID and full file
identity before sending the first request, uploads through the maintained chunk
interface and waits for original source registration. The registered source name,
revision and document content address become the programme's exact selection.
The original source metadata and review appear in the operator page; its full
original ZIP downloads and must match the selected candidate bytes and SHA-256.
**Review in customer programmes** must select that same source in the existing
Analysis tab.

It then saves a named programme with the customer's actual view/report/workbook,
selects that exact intake-registered candidate revision, prepares the same retained
edition, reads full provider metadata and observation comparison, downloads its
complete review, and refreshes the customer's report/workbook through the real
buttons. Reusing this edition deliberately verifies unchanged source behavior;
the original A/B review remains separately retained.

Every UI-generated request is saved before its POST proceeds. Original request
IDs, bodies and historical source revision are retained through recovery.
Completed POST replay must return the exact same completed operation.

Desktop (1440 pixels) and phone (390 pixels) captures and all actual browser
downloads are retained. The full delivered workspace ZIP is received into the
course's independent `programme-received-analysis` directory. Because that ZIP
contains its own in-progress delivery checkpoint, the restored original delivery
remains `INTERRUPTED`. Its validated accepted report/workbook edition remains
visible. Before continuing that delivery, the restored browser opens the same
intake in the complete paginated intake history, reads its original source/review
metadata and downloads the original approved ZIP from the received document
store. The bytes must still match the original candidate; no former filesystem
path is used. The browser then creates a fresh linked portable delivery with a new ID,
reusing the exact accepted business output.

Before and after this new delivery the course compares the complete customer
query, report and workbook tables, their history, native business jobs and view
bindings. Only the original change-export, report-export and workspace-export
jobs are excluded from that business comparison: those are the necessary new
delivery files. Report calculations, source selection and workbook builds cannot
be replayed unnoticed. Earlier and current worksheet sources, the full original
numeric token strings/nulls and subsequent customer query edits are checked.

The complete continuation is saved under:

- `programme-receiving/intent.json`: original source/runtime/operation selection.
- `programme-receiving/programme-selection.json`: exact registered source and customer names.
- `programme-receiving/intake/`, `customer/` and `restored/`: original requests, browser
  captures/downloads and each main/family closure with complete stdout/stderr.
- `programme-receiving/programme-receiving.json`: full final continuation result,
  original metadata review and all three complete browser returns.

The command prints the original course result with an additional `programme`
field. Preserve the complete receiving directory through the existing native
owner's save workflow, including incomplete logs if a child fails. A source-only
review or successful parse does not claim that this native/browser course ran.

## Recovery

Use the same selected sources, directory, runtime paths, operation ID and command
with `--resume`. Completed phase files are adopted after their exact family
closure; unfinished original requests are inspected and continued with the same
body/ID. A recorded attempt without its original closed-family evidence requires
reconciliation by the existing owner; it does not admit another browser family.

The same original workspace receive is repeated after linked-delivery activity
and must report reuse without resetting that activity. The old interrupted
delivery remains a separate historical operation. No second source acquisition,
payment, report edit or customer-recipient operation is inferred.
