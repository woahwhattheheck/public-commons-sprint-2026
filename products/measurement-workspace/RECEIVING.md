# Measurements: complete recipient continuation

This guide receives a finished Measurements delivery through the existing native workspace and installed Applications/agent connection. Preserve the original package and continue in a separate recipient destination. The recipient uses the same scientific parser, calculation and validation modules as the sender.

## Configured scientific operations

The installed client and Merchant provider expose the original observation-edition, sediment study/model-comparison, Chiques, intake-comparison and flow-comparison families. Follow [SCIENTIFIC_OPERATIONS.md](SCIENTIFIC_OPERATIONS.md) for exact native identities, source-bound previews, save/retirement recovery, full artifacts and independent receiving. `artifact-info` and `artifact-download` materialize the original declared file from a complete successful HTTP response; ordinary `download` always retains the full raw HTTP body.

## Identify the complete delivery

Retain the selected application source manifest and its complete installed files, the full native project/edition, its original source and companion files, and all reports intended for the recipient. Keep relevant transport request/response custody when an operation remains unfinished.

| Delivered item | Content and receiving path |
| --- | --- |
| Whole portable workspace JSON | Native tables, imports, records, mappings, reviews, history and stored studies. Receive through `workspace-receive` into an empty scientific workspace. |
| Guided intake project | Saved preparation, original text, editions and origins. Use the original intake-copy function with a new preparation ID when creating an independent editable copy. |
| Benchmark project | Complete studies, drafts and native accepted request receipts. Use attributed `benchmark-receive` with its original complete project. |
| Flow study | Original source-bound daily-discharge study. Use `flow-receive` with the complete original study and keep its bundle. |
| Load result | Keep its full native bundle and original sources; preserve it through complete native workspace receiving. The client catalogue does not introduce a separate load-receive endpoint. |
| Collection edition | Whole directory/ZIP containing project, collection, companion originals, reports and edition manifest. Follow its included receiving instructions and restore both project and collection. |
| Source handback ZIP | Complete manifest, original sources, companion collections, native context, derived workbook/report and project. Use the original handback receive function. |
| Large-file edition | Original file list and chunked bytes. Use the existing large-intake receive sequence; retain exact file/chunk identities and offsets. |

A portable database export does not substitute for collection companion files. A benchmark project does not substitute for the entire scientific workspace. Keep the complete format needed for the intended continuation.

Native bundle HTTP responses may be JSON objects containing a ZIP's filename, byte count, digest and base64 body. The client download preserves that original response as-is. Do not rename a JSON response to .zip. Use the native browser download or decode the actual bundle descriptor and verify its declared byte count and hash before extracting it.

## Receive and reopen the original work

1. Preserve the sender's original files as received. Select the complete application/source edition that owns their receiving format.
2. Create a separate recipient scientific workspace using the existing installed Runtime/Applications workflow. Keep its private control/configuration and transport custody separate from the sender.
3. Open the actual recipient workspace and record its managed connection receipt. The receipt binds physical directory, native workspace ID, source manifest, configuration and current instance.
4. Use the matching native receiving operation from the table above. Whole-workspace receive requires an empty destination. Keep its full original request and response.
5. If receiving changes the destination's original intake UUID, retain the successful response, then use the existing Applications Stop, Review and Start workflow and configure its new exact connection. Reopen the received source catalogue, original records, saved reviews and applicable studies. Inspect the actual incoming IDs, source bytes, revisions, authored definitions and reports.
6. Make an attributed independent edit using the original workflow. Save a new preparation/study/edition, retaining the incoming work and its history.
7. Export the complete recipient project/edition, then reopen it in another fresh recipient destination. Use the actual exported files, including companion originals and all required software.

Receiving can preserve a logical project ID. The new physical directory and running instance still identify a distinct recipient. Do not direct a sender's pending request at the new recipient merely because a project ID matches.

## Receive through the configured client

Configure the recipient connection as described in [OPERATOR.md](OPERATOR.md). Save the complete intended receiving body under a host-declared input alias.

For whole-workspace receiving, the operation envelope selects `operation: "workspace-receive"` and sets `body` to the actual complete portable project object. Preserve all source tables and embedded originals; a pathname, summary or quoted JSON string is not the project body. For benchmark receive, use the native body containing the complete project and actual request ID, actor, note and timestamp. Source handback receive takes the complete original ZIP encoded as `contentBase64` and its `sha256`.

Inspect the complete alias, retain its digest and transport UUID, execute the original operation, then download the entire response. A local receipt only establishes that a transport result was retained. Inspect the native result and reopen the actual recipient workspace to establish the receiving outcome.

If whole-workspace receive loses its response, read the original recipient's summary, intake identity and project state before attempting another receive. Never overwrite an advanced recipient or silently switch to another destination to resolve uncertainty.

## Operate the actual outgoing product

The producing operator completes this course on the selected outgoing files:

- Open the real desktop interface and a narrow viewport. Read labels, tables, controls, status/error text and overflow.
- Receive and inspect an original source, its interpreted fields and complete rejected/accepted result. Save/reopen its preparation and original-file download.
- Open the applicable source reconciliation, scientific study or benchmark. Inspect the authored definition, full rows/periods and original source references. Save and reopen the selected result.
- Use the actual report, CSV, project and full bundle downloads. Open the downloaded HTML/report and inspect every final attachment applicable to this delivery.
- Receive the exported complete package into a separate recipient workspace. Reopen its original source, histories and derived outputs, make an attributed independent edit, and export/reopen the successor.
- Where a call was interrupted, operate the real retained request/status and response-file recovery path. Keep the actual returned native outcome with that original request.

Use the existing equipped operating owner when one already holds the original project. Preserve current user tabs, saved work and that operation's ownership. Source review, parsed JavaScript or an unavailable process is recorded for its actual scope; the native and visual observations come from the actual running product.

## Recover without losing prior work

Preserve original client custody before changing configuration or restarting a service. A managed restart gives a fresh instance receipt; review it and create a successor client configuration. Historical requests still belong to the prior instance and its actual scientific workspace.

For an uncertain write, inspect the exact native receipt, saved preparation revision, study ID, collection edition or handback ID appropriate to that action. Only use explicit transport retry where the original route supports exact replay. For a new decision after reconciliation, retain the completed earlier outcome and author a new native operation against the current selected state.

Keep unresolved local edits and the complete original incoming package. Use the native independent-copy or new-edition functions when two authors have diverged. Do not replace source history with a summary of the differences.
