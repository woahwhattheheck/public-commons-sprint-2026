# WorkSeal: read-only Solana settlement readback

`src/solana_settlement_readback.mjs` closes a judge-evidence gap in the existing unsigned transaction-plan demonstration: seeing a prepared transfer or a fabricated Explorer link does **not** mean the buyer paid. This module reads an operator-specified Solana HTTPS JSON-RPC endpoint using `getTransaction` with `commitment: "finalized"` and `encoding: "jsonParsed"`. It does not sign, send, or modify a transaction.

Call `fetchFinalizedSolanaSettlement({ intent, signature, rpcUrl })` only after the existing WorkSeal acceptance verification has produced the *current* `createSettlementIntent(state)` and the buyer independently chose to execute that plan. The returned readback contains the actual requested signature, finalized slot, matching settlement digest, and matching transfer parties/lamports. Until RPC returns a successful transaction with a single matching WorkSeal Memo and a single matching SystemProgram transfer, payment evidence remains unavailable; missing result is not an award.

The check requires the original buyer (`intent.payer`) to be an account signer, the exact accepted intent memo `WORKSEAL:v1:<sha256(intent)>`, exact destination and lamports, transaction `meta.err === null`, and one occurrence of each expected instruction. Transactions with unrelated other instructions are not proof of *only* that transfer; reviewers should inspect them too. Atomic amounts above JavaScript's safe JSON-integer range fail closed rather than silently round.

**Trust boundary:** A JSON-RPC read from a single endpoint is a provider attestation, not a cryptographic light-client or escrow-program proof. Operators must select a trusted HTTPS endpoint, verify the genuine WorkSeal signed acceptance **before** attempting payment, and preserve the real RPC response/signature for judge scrutiny. An offline fixture passing the focused check is not evidence of a mainnet payout. A production implementation should also pin chain genesis/hash and perform independent RPC or Merkle/proof verification. `workseal/src/solana_spl.mjs` handles an entirely separate unsigned SPL-token planning path and is *not* covered by this SOL-only verifier.

Focused synthetic check: `node --test workseal/test/solana_settlement_readback.focused.test.mjs` from the repository root (Node 20+). No live wallet, testnet deposit, contest submission or Solana RPC charge is performed by the check.
