# gRPC customer delivery in Merchant Console

The gRPC customer workspace carries an existing merchant preparation, captured source, retained call, contract review or service-health observation through complete file receiving. It uses the configured original gRPC workspace, the existing private Console profiles and requests, and the original immutable export store.

## Open the installed product

Open **gRPC merchant** from Applications, or use the installed gRPC product command with its existing product directory. The product exposes the native merchant editor, the original MCP endpoint and **Merchant operator**. Open Merchant operator and connect with the configured merchant access token. Create or select a named operator profile, inspect the Host page and bind that profile to the current configured host.

Open **Customer files**. The **gRPC / Customer workspace** panel appears when the host advertises gRPC workspaces. Load configured workspaces and inspect the original selection. The native merchant editor continues to own protobuf capture, reflection, requests, service-health operations, preparation and release operations.

## Select retained work

The inventory selector provides prepared merchants, captured revisions, retained calls, exports, contract reviews, service-health observations, descriptor captures and preparation intents. Each page displays the original total and snapshot. Previous and Next use that exact snapshot; Refresh starts a new current inventory.

Select a preparation to load its original revision, a retained call to read its complete outcome, or a contract review to inspect its immutable comparison. The source and contract section selector reads the original summary, source, plan, methods and routes; contract reviews also expose the complete comparison and adoption history. Methods, routes and changes retain their original page snapshots.

The original identifiers remain editable for an operator returning with a saved selection. Every request is saved in the existing private Console profile before dispatch. The page displays the complete original return and provides its exact downloadable JSON. A large native value points to a complete retained file through the same receiving flow.

## Receive complete files

Choose the export that matches the retained work:

| Delivery | Original selection | Complete files |
| --- | --- | --- |
| Generated customer | Merchant preparation UUID | methods.json, openapi.json and the five original files under client/ |
| Captured source | Source revision SHA-256 | grpc-revision.json with the captured protobuf closure, source and merchant plan |
| Retained call | Original operation UUID | grpc-attempt.json and grpc-stream.ndjson when the attempt has a retained stream |
| Contract review | Original review UUID and reviewed SHA-256 | grpc-upgrade-review.json, grpc-upgrade-base.json, grpc-upgrade-candidate.json and grpc-upgrade-plan.json |
| Service health | Original observation UUID and selected event snapshot | grpc-health.json with the complete selected event history |
| Large native result | Export returned by the original tool | grpc-result.json |

A generated customer includes these exact native paths:

- methods.json
- openapi.json
- client/seller-client.mjs
- client/seller-client.d.mts
- client/seller-openapi.json
- client/package.json
- client/README.md

Inspect the returned manifest, then choose **Receive complete files**. The receiving identity includes the configured workspace, original export ID, complete manifest SHA-256, operator profile and host fingerprint. The original downloader resumes its byte checkpoint and verifies each complete file. A workspace mismatch is rejected before customer file receiving.

Completed receiving appears in the existing customer list. The complete archive restores the original paths under **grpc/**, including **grpc/client/**. The transfer checkpoint can retain transport names such as client-seller-client.mjs internally; these transport names do not flatten the delivered client package.

Individual files and tar.gz archives stream through the same original archive owner and its retained download lease. Where the browser supports Save File, the Console streams the response directly into the chosen receiving file. Other browsers use the existing browser download behavior. The original product client and CLI remain available for receiving and inspecting the same immutable exports.

## Freeze service-health history

Choose an existing Check, List or Watch observation and read its summary and events. The event page carries both **throughSequence** and **snapshot**. Those two values select the complete durable event prefix for export, even when a live Watch later appends more events.

Previous and Next preserve that selection. Reading the latest events deliberately chooses a new current prefix. The complete health file contains every event through the selected sequence, including events on other preview pages.

List service filtering has a separate page snapshot because the filtered rows have a different identity. The Console keeps that snapshot separate from the event snapshot and always exports the selected event history. An empty event history retains sequence zero and its original zero-event digest.

## Save and resume whole procedures

The page prepares four complete procedures in the existing Workflow Recipes editor:

| Procedure | Inputs | Original work |
| --- | --- | --- |
| Customer and source delivery | Workspace and preparation UUID | Inspect the workspace, retain all seven generated customer files, inspect the preparation's exact source revision and plan, retain the complete source closure, and read current workspace state |
| Contract-upgrade delivery | Workspace, review UUID and reviewed SHA-256 | Read the original summary, plan, source, complete comparison and adoption history, then retain all four upgrade files |
| Frozen service-health delivery | Workspace, observation UUID, event throughSequence and event snapshot | Inspect the same observation, review the selected events, retain the complete frozen history, and read the current original observation |
| Retained-call delivery | Workspace and original call UUID | Recover the original saved call outcome and retain every original attempt file, including its stream when present |

Manifest pauses allow complete customer receiving before the operator continues the saved procedure. Review its selected inputs and original tool definitions, install the recipe and start its saved edition. The complete recipe and selected inputs can also be downloaded.

A customer recipe derives the source revision from its original customer export. This keeps its source package tied to the preparation actually delivered. A health recipe retains the chosen event prefix throughout the run. The existing workflow history contains the original tool returns, bindings, pauses and continuation identity.

## Return after interruption

Open the same profile and select the original request from **Saved original requests** or **Requests**. Read its native operation to recover an existing call, contract review or health observation. For an interrupted export or preparation, read the original inventory and select the retained result.

An explicit continuation uses the same saved arguments and original operation identifiers, linked to the previous Console request. A call that is still receiving remains with its original owner. Completed results remain available from the original request.

Customer transfer Pause retains its downloader checkpoint. Resume uses the same export and reviewed manifest. Profile export carries its complete receiving records and workflows; another Console receives the original files into its own private directory.

The installed Applications source selection includes the customer page, recipes, profile validator, downloader adapter and streaming archive owner. Stop drains that Console, its transfers and archive responses through the same product owner. Reopen returns to the retained private Console directory and original native workspace.

## Direct browser saving and the native receiver

Browsers exposing a direct file writer stream the authenticated response into the selected file. The Console captures the original profile, host binding and session before opening the file picker. Changing that selection while the picker is open requires starting again from the original customer.

Other browsers use the in-memory download path only for complete files or archives up to 16 MiB. Larger customer streams use the existing resumable `grpc-product receive` command shown with the selected manifest, or a browser with direct file writing. The native command retains the same export ID, manifest SHA-256 and private transfer directory when resumed. Replace the two absolute directory placeholders with the installed product and intended receiving directories.

The configured workspace, revision, operation, health event page and export selection reset together when the profile's host binding or resolved workspace alias changes. Saved requests stay in their original profile history.
