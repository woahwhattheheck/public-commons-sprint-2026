# SF73 | Pinned original seller proof to crash-atomic durable Bazaar admission

MIT. Runs the actual SF50 Ed25519 seller-quote verifier and actual SF60 durable three-projection catalog journal in one operator-controlled transaction. Does not fork their trust engines, indexer, identity, lifecycle or commerce transport. Node.js 22+, built-in Node modules only, no hosted CI.

## The paid-merchant problem solved

A verified seller declaration previously stopped at the standalone SF50 proof CLI. A separate SF60 writer needed a caller already holding trusted seller policy. This adapter makes that specific path executable: operator supplies exact original JSON bytes and one independent, **out-of-band pinned Ed25519 key**, a separately approved seller/origin/payee/network/scheme policy, and one fresh nonce+original SF50 proof for **each** offered payment alternative. It verifies all alternatives before the unchanged candidate is submitted to SF60. One bad or omitted alternative means no durable commit. No catalog is offered through an unauthenticated POST endpoint.

## Source and operator authority

- `sourceBytes` is the original UTF-8 x402 v2 Bazaar JSON as received by a permitted merchant/operator. No rewrite of signed terms, conversion to decimal amounts or generated seller rows.
- Original `resource.url` must be an exact canonical HTTPS URL; `sourceURL` must be separately recorded and on the same origin. This is provenance of the supplied source bytes, **not** a live DNS or HTTPS observation by this adapter.
- For each `accepts[i]`, retain a separate SF50 original `{nonce,proof}` at index `i`; nonce must be fresh and distinct. SF50 authenticates the exact selected amount, asset, network, payTo, scheme and complete Bazaar input/schema. Merely verifying the first option is insufficient if more are advertised.
- A trusted operator pins the seller public key independently and authorizes seller ID, signer and allowed origins/payment terms in a distinct file. The signer is that pin's SPKI DER encoded as base64url. An Ed25519 proof must never be used to auto-authorize the `payTo` wallet.
- SF60 itself enforces the native trust policy, original Bazaar parser, lifecycle corrections, monotonic seller sequence and one crash-atomic commit, with stable restart recovery. The output includes the raw source SHA256, pin fingerprint and accepted journal head, not wallet material.

## Embedded use

From the original full public checkout, import `admitPinnedSeller` from `admit.mjs` and the original `DurableCatalogTransaction` from `../sf60-durable-catalog-transaction/journal.mjs`. Open a private operator journal and pass `journal`, the original byte Buffer, `sourceURL`, ISO `observedAt`, `sellerId`, positive `sequence`, the independently configured `authority` Sets, `pinnedPublicKey` (original PEM or Node public KeyObject), and indexed `{nonce,proof}` array. Explicitly close the journal after use. SF60's exclusive lock protects the one writer and must never be bypassed.

## Local CLI

Operator keeps three independent, access-controlled files: the original seller JSON, one JSON array of indexed `{nonce,proof}` pairs generated by the original SF50 service, and a separately authorized policy. The policy has `{sellerId,signer,allowedOrigins:[...],allowedRecipients:[...],allowedNetworks:[...],allowedSchemes:[...]}`. The signer is the **independently approved** public key's SPKI DER base64url, not copied from an unverified proof.

```sh
node stellar/scf-starforge-20261009/sf73-pinned-seller-admission/cli.mjs \
  --entry /private/original-seller-x402-v2.json \
  --proofs /private/original-seller-proofs.json \
  --pin /private/approved-seller-ed25519-public.pem \
  --authority /private/approved-seller-policy.json \
  --dir /private/catalog-journal \
  --seller approved-seller-id --sequence 1 \
  --source-url https://seller.example/offers/export \
  --observed-at 2026-10-11T11:00:00.000Z
```

The directory must not be served publicly or shared with an untrusted writer. The CLI refuses to auto-steal a preexisting SF60 writer lock. **No private Ed25519 key is read by this tool.** Generate proof signatures on the permitted seller operator, not in the buyer/index runtime.

## One source-accurate focused check

```sh
node --test stellar/scf-starforge-20261009/sf73-pinned-seller-admission/test/admit.test.mjs
```

This invokes real original SF50 signing/verifying, original SF27/SF21/Bazaar via SF60 durable writer, a two-option signed Stellar:testnet-shaped local declaration, forged second-option rejection without journal mutation, missing-option rejection, owner mismatch, exact replay and disk reopen. The test's `GSELLERA`/`GSELLERB` recipients are **deliberately unspendable local contract values**, not actual Stellar account receipts. No CI or broad suite.

## What is not proved

An independent pin establishes who signed the quoted terms, **not** ownership of the Stellar payment account, merchant legal identity, current live HTTPS origin, actual hosted service availability, signed buyer payment, settled testnet ledger event, resource delivery, a customer contract or an SCF eligibility/award decision. For a *live* seller-origin HTTP attestation use SF50 `verifyOriginProof` separately, with its own DNS/TLS trust assumptions; use the actual canonical SF30/SF31/x402 SDK and independent ledger receipts for payments. This is an operator-approved admission product path that closes an existing compositional gap, not a full commerce launch.
