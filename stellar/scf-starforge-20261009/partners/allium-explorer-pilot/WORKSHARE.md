## The working customer result

The operator approves a saved Explorer query and its exact parameters, or imports an existing authorized result. The acquisition keeps the original query/run identity, complete result bytes and declared projection in a private workspace. Precision-sensitive fees and identifiers remain exact strings. Fields outside the approved projection remain in the private source.

The same operator publishes the selected dataset through one existing Stellar merchant route. Buyers review the original terms and use its declared projection, filters, sorting and pagination. A buyer request reads the selected dataset; provider acquisition follows the operator's separate approved workflow.

A later approved result becomes a new native dataset generation. The route and payment tuple remain stable while readers admitted to the earlier generation continue with their original snapshot. A change to the public field, type or query contract receives an explicitly configured route.

The receiving application retains product history, original acquisitions, native merchant versions, publisher review and buyer configurations. Its complete export and create-only import reopen the same source and operating records.

## Source and workload contract

The included product is one saved query against the customer's approved current Stellar schema, with up to twelve exposed fields and one merchant route. The source owner chooses the exact time window, row limit, declared types and intended audience.

The current acquisition transport accepts a **maximum 1 MiB JSON result**. A result reaching its row limit is displayed with that status. The agreed source selection must fit both the byte limit and its stated completeness requirement. The customer can select a smaller window or narrower projection before acquisition.

Allium's saved-query run, status and results use the customer's normal API-key access. The merchant applies the selected Stellar payment terms to its own approved delivery. Each system keeps its original account, data and payment responsibilities.

For live acquisition, the operator submits the approved query once and retains its actual run ID. Status and completed-result collection continue that run. If a response is lost, the operator attaches the existing run ID from the owning Allium workspace before resuming. A completed result can be reopened without buying another query execution.
