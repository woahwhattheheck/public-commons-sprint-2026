# Dwellir Agent Toolkit application migration workshare

## Prepared for the Agent Toolkit and integrations team

We can take one active Polkadot/Substrate application migration from endpoint selection through application rollout and operator handoff. The prepared implementation composes Dwellir's native CLI and endpoint catalog with the application's existing configuration.

The starting product is a complete migration operator, actual Node and Python application callers, a private receiving command, retained source/configuration review, and rollback. Its reference selection is Dwellir's published Polkadot mainnet endpoint and the existing rpc.polkadot.io application endpoint.

## Fixed workshare

USD 2,800 for one application on one selected chain/network, with up to three existing HTTPS endpoint bindings. Delivery is five business days after the application, endpoint/key selection, hosting access and scope are accepted.

- USD 1,400 at kickoff.
- USD 1,400 at acceptance.
- Two consolidated review rounds.
- One 60-minute engineering handoff.
- Ten business days of correction for defects in the delivered scope.

Dwellir/customer account usage and hosting remain on the selected existing service plan.

## Delivery

1. Read the original application, identify its RPC bindings, SDK/transport assumptions and historical-state requirements, and agree the intended chain identity.
2. Select the exact native Dwellir endpoint and existing named key through the customer's installed CLI/account.
3. Complete actual compatibility reads, including required block-specific state when the application depends on it.
4. Apply the reviewed configuration through the original application/deployment workflow and operate the original application against Dwellir.
5. Deliver the complete source change, retained rollback, caller examples, receiving results and operator package.

The buyer receives an application migration that their team can run, inspect, restart and reverse using its existing deployment environment.

## Accepted inputs

The selected application's source and launch/deploy entry point; the intended chain/network and actual RPC methods; an existing Dwellir account/key selection; the original provider endpoint and historical examples; the receiving host or deployment path; and the engineering owner who reviews the result.

The initial product uses the Substrate HTTPS contract. WebSocket subscription migration, EVM-specific trace adaptation, additional chains and additional applications can be selected as a separate workshare after the first application's requirements are known.

## Completion

Acceptance is the same original application operating on the selected Dwellir endpoint, with the agreed method/history observations, retained source and configuration changes, a working receiving handoff and an exercised original-provider rollback.
