# Original synthesis browser receiving

This module joins the existing source-native Research → Analysis receiving operation. The native controller keeps the selected Analysis host alive; the browser owns the first publication import, protocol save and synthesis run. The following SDK, CLI and archive steps inspect and receive that same job ID.

## Inputs and call

Import the complete source module from the selected distribution and call:

```javascript
import {receiveSynthesisOperator} from './receive_synthesis_operator.mjs';

const browserResult = await receiveSynthesisOperator({
  url: actualAnalysisLaunch.url,
  publicationFile: publicationResult.publicationFile.path,
  publicationSha256: publicationResult.publicationFile.sha256,
  protocolFile: referenceDirectory + '/reference-protocol.json',
  outputDirectory: originalOutput + '/browser',
  browserProfileDirectory: originalOutput + '/browser-profile',
  operationId: 'SCF-RESEARCH-EVIDENCE-SYNTHESIS-20261012-BCG-BROWSER',
  signal: originalAbortController.signal,
  // Optional trusted absolute paths to the already installed tools:
  playwrightModule: selectedPlaywrightModule,
  chromiumExecutable: selectedChromiumExecutable
});

```

The launch URL is the actual private loopback Analysis URL, including its original capability fragment. It stays outside retained request journals. The browser starts from that Analysis page and uses its Evidence synthesis navigation. The selected original host must serve the complete synthesis UI and allow its verified original SVG blob images through its existing CSP.

The selected Playwright module is an installed module file, not a directory. When omitted, the helper uses the installed `playwright` package or the primary runtime's existing module directory. The Chromium executable defaults to the existing `CHROME_BIN` or `CHROMIUM_EXECUTABLE_PATH` setting. The caller supplies the original persistent output/profile directories. No package installation or alternate Analysis host is part of this module.

The original publication comes directly from scanner's `publishBcgReference`. It must have the original `sf88-research-extraction-publication-report/v1` envelope, one frozen publication and thirteen complete source-bound results. The reference protocol is the unchanged original `reference-protocol.json` (SHA-256 `6a2ef0cbaf5ddd6032e78fa6a460a4f6daa91da96ff9ae747bdc4a84dfef1cf4`).

## Operator sequence

1. Open the actual Analysis launch and use Evidence synthesis. Read and bind the original Analysis workspace ID.
2. Select the complete original publication file in the real import control. Use `/publications/0/rows` and descriptor pointer `/result`. Import under the operation-derived stable name.
3. Download and compare the complete source file. Open an original result, inspect its descriptor/source bindings and four original event/non-event tagged values.
4. Build the native protocol from the frozen reference selection and the imported API's separate descriptor digests. Load it into the complete JSON editor. Verify the visible exact sums, then open and keep one original included result through the normal comparability controls.
5. Save the protocol edition, reload the page, select that saved edition from history and review its original thirteen study effects. Inspect the original numeric operands and transformations.
6. Start the first native run from Run reviewed synthesis. Observe the page's original job polling until that same job settles.
7. Read its complete result, download the original HTML report, complete ZIP and numerical JSON, display its verified original forest SVG, and capture the actual desktop and narrow result views.
8. Reload the page, open that original job ID and receive its identical HTML report. Export the browser's original recovery file.

The protocol preserves vaccinated/control orientation, the original unreported individual follow-up and allocation labels. Its primary analysis is random effects, Paule–Mandel, HKSJ t interval, 95% confidence and no continuity correction. Totals use explicit exact sums of the original event/non-event fields. The original random-allocation sensitivity retains trials 1, 2, 3, 4, 7, 8 and 9; leave-one-study-out and the original allocation subgroup labels stay explicit. The protocol records the interpretation and limitations as a published methods reference.

## Original request and process recovery

Before each of the three mutating browser requests can leave the page, the module reads the UI's already-committed IndexedDB request record. It requires the same ID, endpoint and exact body, retains the complete original portable recovery record and journal, and only then lets that same HTTP request continue.

Reinvoke with the same operation, files, host origin, original workspace and profile. The real Recovery import/row controls reopen or retry the saved request. A changed body or a new request identity for an already retained operation is rejected before HTTP dispatch. The source and protocol retain revision 1; the run retains its original 32-character ID.

The browser closes only its own persistent context, including failed-start and interrupted steps. Its final cleanup retries the same close after a rejected first close. The caller continues to own the native Analysis host. An interruption retains original request files and the profile; continue that same operation after resolving the actual native error.
