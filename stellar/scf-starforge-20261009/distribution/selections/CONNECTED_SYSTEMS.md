# Connected Systems observation operator

This selected Starforge package carries the Connected Systems operator, native dataset engine, customer packet receiving, managed Applications registration and complete merchant MCP client. It uses the maintained distribution builder and runtime installer. The source manifest names every included original file and the exact committed selection recipe.

The included reference is one unmodified illustrative temperature observation from the Open Geospatial Consortium's Connected Systems repository. The publisher's complete observation, matching datastream and schema, source capture, license, native result and customer packet are retained. Its scope is one observation resource; it is not a field measurement or a complete live collection.

## Build the selected package

Use the maintained source checkout or its existing complete Git object store. Select the full commit that contains this recipe, this guide and the installed receiver along with the Connected Systems contribution. A newer working tree does not change that selected snapshot.

```sh
node /absolute/source/stellar/scf-starforge-20261009/distribution/build.mjs \
  --repo /absolute/source \
  --ref FULL_SELECTED_COMMIT \
  --selection connected-systems \
  --out /absolute/original-operation/connected-systems-build
```

The builder resolves and retains the commit, reads the source-owned contribution, verifies the complete original file identities, follows the selected static module imports, checks the native support inventory and produces the npm archive. Its final JSON receipt identifies the archive, byte count, SHA-256 and source commit. The output's `distribution.json` and `package/manifest.json` retain the complete selection and source mapping.

Use `--offline` when the original selected objects are already present. An interrupted build continues in its existing output directory:

```sh

  --repo /absolute/source \
  --selection connected-systems \
  --out /absolute/original-operation/connected-systems-build \
  --resume --offline
```

The existing builder's lock, source pin, partial-file verification and completed-archive recovery remain the authority for that output. Use its returned receipt rather than selecting an archive by filename alone. Complete build behavior is documented in the maintained distribution's `BUILDING.md`.

## Prepare the original runtime

Use Linux, Node.js 22.16 or newer, Python 3.11 or newer, npm and util-linux `flock`. The actual source-selected dependencies may require a newer Node version; the maintained resolver reports that requirement. Keep the runtime and receiving workspace in private directories owned by the operator.

Use the original archive and its complete returned digest:

```sh
node /absolute/maintained/source/stellar/scf-starforge-20261009/distribution/runtime-install-cli.mjs prepare \
  --dir /absolute/original-operation/connected-systems-runtime \
  --archive /absolute/original-operation/connected-systems-build/EXACT_ORIGINAL_ARCHIVE.tgz \
  --sha256 EXACT_ARCHIVE_SHA256 \
  --native --feature schema --feature openapi --feature mcp --operator

node /absolute/maintained/source/stellar/scf-starforge-20261009/distribution/runtime-install-cli.mjs install \
  --dir /absolute/original-operation/connected-systems-runtime

node /absolute/maintained/source/stellar/scf-starforge-20261009/distribution/runtime-install-cli.mjs inspect \
  --dir /absolute/original-operation/connected-systems-runtime --load --source
```

Preparation selects dependency versions from that archive's declarations and retains its exact source under `RUNTIME/package/source/`. Installation uses the existing npm registry or explicitly selected cache and preserves its resolved lock and readiness results. Dependencies live in the same runtime's original `node_modules/` tree. The returned `sourceRoot`, `dependencyRoot`, `sourceCommit`, `installationId` and `profileId` identify the actual installation.

Where an existing equipped owner already holds a complete compatible dependency graph and its original lock, use the maintained `install --adopt-existing` route in the prepared runtime. That route validates the selected profile, exact imports and native bindings without running npm. A directory that merely contains some required packages is not a verified installed graph. Retain the existing cumulative build or installation owner when consuming its output.

For an interrupted installation, use `runtime-install resume --dir RUNTIME`. An explicit offline installation also needs the original cache and any matching local Node headers required by the selected native dependency. The maintained `RUNTIME_INSTALL.md` describes normal preparation, adoption, source verification, upgrade and recovery.

## State, interruption and private connection files

The receiving helper retains one original intent at `WORK/intent.json`. It binds the selected source commit, runtime installation and profile, accepted input bytes, workspace, native identities and any explicitly selected merchant/buyer inputs. A nonblocking original file lock keeps one receiver in that work directory.

An unfinished receiving journey adds a complete `generations/attempt-NNNNNN/` record. CLI stdout, stderr, exit/signal, complete MCP results, received files and the actual helper source identity remain associated with that attempt. Existing native sources, mappings, builds and exports are reused through their original identities. Continue the same command and work directory after reconciling its original process; differing retained inputs stop with the affected identity.

If the latest original attempt already contains a completed result, the helper checks its input/source/receiver identity and every listed public output's complete length and hash, then returns that same result and attempt path with `recovered: true`. It does not replay the completed CLI/MCP traversal or optional seller-offer read after a lost final stdout response. Missing, changed or conflicting completed output remains a repairable original-state error; an incomplete attempt continues through the same native workspace.

A failed attempt writes `INSTALLED_RECEIVING_INCOMPLETE` with its actual error and cleanup outcome. It does not convert an absent runtime, stopped process or partial file into successful receiving. The private operator startup record, capability URL and merchant connection configuration stay outside the result's public file inventory.

The public result inventory contains source/result data and exact exported files. Keep the complete private work directory with the original operation's normal checkpoint preservation when it must move between equipped hosts. Retain the installation and source archive identities with that handoff. The existing browser owner uses the same original product operation separately; this installed receiver does not create a second source acquisition.

## Operate the installed workspace

Use the maintained runtime dispatcher with the selected original runtime:

```sh
node /absolute/maintained/source/stellar/scf-starforge-20261009/distribution/runtime-install-cli.mjs run \
  --dir /absolute/original-operation/connected-systems-runtime -- \
  connected-systems --workspace /absolute/original-operation/installed-receiving/workspace state

node /absolute/maintained/source/stellar/scf-starforge-20261009/distribution/runtime-install-cli.mjs run \
  --dir /absolute/original-operation/connected-systems-runtime -- \
  connected-systems --workspace /absolute/original-operation/installed-receiving/workspace serve \
  --host 127.0.0.1 --port 0 \
  --connection-file /absolute/original-operation/operator-connection.private.json
```

The operator's private startup URL opens the current browser UI. Its query editor keeps the explicit collection or single-observation resource choice, schema URL policy, exact datastream/schema/observation URLs, ordered query filters and acquisition limits. Review the normalized saved query before acquisition. Sources retain every actual response page and schema identity; exhausted, capped and failed operations remain visibly distinct.

The mapping editor retains lexical values, missing versus null values, original schema types, units, quality definitions, duplicate policy, edition keys and the selected coverage rule. Saved mappings and native editions have immutable identities. The activity view can page older documents and operations through `/api/records/` with the original view guard rather than silently stopping at the latest 200 items.
