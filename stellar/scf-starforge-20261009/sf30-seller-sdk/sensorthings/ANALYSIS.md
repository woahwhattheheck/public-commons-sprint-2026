# Observation analysis, publication and project receiving

This workspace adds a complete analyst workflow to the existing SensorThings application. It uses the original persistent workspace UUID, source editions, source review, operation journal, content-addressed objects and held-file receiver. The browser, publication builder and project transfer do not create another capture, session, seller, payment history or workspace writer.

The application entry is **/analysis/** on the original loopback listener. The installed Helgoland viewer is a separately pinned original static release served by the same application. The analyst interface, its readable publications and the portable project all retain the exact saved source selection.

## Open the original private session

The original listener prints or saves a private URL whose fragment contains its existing token. On that same origin, use **/analysis/** before the private fragment. The page accepts the original token; it does not create or exchange one.

The bootstrap request is GET /api/schema with the existing Bearer header. The returned persistent workspaceId becomes the X-SensorThings-Workspace header for every later API request. The schema route is the original listener's only workspace-header exception.

After connection, the page removes the fragment from the address bar and retains the existing credentials only in this private tab session. The token is never placed in viewer settings, files, reports, project snapshots, links to other hosts or printed receiving examples. **Close session** removes that tab's stored credentials without changing the server or project. An unresolved pending-request envelope remains available for reconnection.

Enter the operator name in the header before changing an analysis, reviewing a source or receiving an attributed artifact. This is the name written into the existing original action, not an invented identity or a new authorization system.

## Complete operator workflow

### 1. Receive or select the original source

Open **Receive / export**. Its file list comes from the original host-bound source inbox and shows each complete file's name, exact byte count and SHA256. The browser does not accept arbitrary server paths.

Use **Receive original source edition** for an existing complete native source-edition transfer. This calls the original edition.import action. It does not make another provider request. Alternatively, select an edition already retained by the existing capture Desk.

The upstream source intake owns provider URLs, licenses, query selection and capture completion. A partial capture stays partial. The analyst does not turn a completed traversal of a selected query into an assertion of continuous coverage or an atomic provider snapshot.

### 2. Create the first saved analysis

Choose **New analysis** and give it a useful title. Select the exact original edition and between one and twenty retained scalar Datastream keys. Each choice exposes its original observation type, unit metadata, occurrence count, numeric eligibility and source identity.

The saved period is either the entire retained source extent or an inclusive start and exclusive end. Enter offset-qualified timestamps such as **2026-06-01T00:00:00Z**; the original input spellings and their normalized UTC forms are retained. Result time and valid time remain separate source fields.

Choose the saved event, map or numeric view. Select an installed immutable viewer ID when the analysis will use the original Helgoland client. Saving creates an immutable version with an exact content identity and makes it the project's head.

### 3. Review source meaning and findings

**Source review** shows the full original plan/query, source scope, source files, occurrence summary, issue codes and local review history. Open any exact original source member through the maintained file reader.

Choose accept, reject or follow_up, record the interpretation, and explicitly acknowledge the original required findings when accepting. The original core computes those required findings from the entire edition, including duplicate and unkeyed observations. The browser does not replace them with a shorter preview.

Publication requires the latest original source review to be accepted. The core pins that exact review before building files and checks it again before recording the finished publication. Imported source reviews remain history; the receiving workspace records its own decision.

### 4. Inspect original events and rows

**Events / rows** pages through complete original occurrence rows in blocks of one hundred. The displayed range and total are explicit. An expandable row shows every original field, typed identifier, exact result lexeme, original JSON, source SHA and JSON pointer.

The timeline covers that displayed page. A circle is an original instant. A bar is an explicit original interval. Missing, local, unresolved or otherwise unplaced source times remain in the table. They are not dropped or assigned an invented duration.

**Cite this occurrence** carries its exact edition, source SHA, JSON pointer and occurrence identity into the annotation form. The original source file remains available separately.

### 5. Open the actual native viewer

Receive the pinned original Helgoland archive through **Receive original viewer archive**, then save its immutable viewer ID in the analysis selection. Installation verifies its actual archive and asset bytes and retains original publisher source/licence files.

**Native viewer** first reads the protected deployment metadata for the exact viewer/version/mode. It shows native compatibility findings before a launch. The actual frame is registered in the analyst parent before its src is assigned.

The parent exposes existing headers only when the request comes from that exact registered iframe contentWindow, on the same origin and within its selected viewer path. The deployment owner's XHR bridge sends those headers only to the selected same-origin retained-analysis routes. Closing the frame or leaving the tab removes that registration.

The native map and numeric diagram remain distinct. The native expanded map uses retained Thing Locations; those locations do not automatically establish the location of each Observation. The native client also has explicit original-ID and metadata compatibility requirements, visible in the saved summary and deployment metadata.

Save or capture actual native output through the existing receiving operator, place the complete resulting file in the original inbox, and attach it under **Publication**. The file is bound to the exact saved version. A later selection or annotation revision requires evidence explicitly bound to that later version.

### 6. Add attributed annotations

**Annotations** retains notes, quality interpretations and operator interpretations with source citations. A change creates a new saved version; the provider record is unchanged. Editing requires the exact current project head.

Annotations carried from an earlier source edition continue to cite that original edition. They are not relabelled as evidence for a later source. The current source-bound annotation validator governs edits and withdrawals; a new interpretation can cite the newly selected source explicitly.

Historical versions remain selectable in the version control at the top of the page. They show their original source, comments, evidence and publications. Open the current head before revising a project.

### 7. Compare later retained data explicitly

**Compare editions** compares the selected saved version against another original edition. It records unchanged, changed, observed-only-left, observed-only-right and ambiguous keys, as well as unkeyed occurrences and missing later stream keys.

Inspect source-query compatibility before interpreting a difference. The complete comparison remains saved even when the readable UI pages its changes. One-sided retained observations are not assertions that a provider inserted or deleted records.

The comparison UI and readable publication also show the frozen **sourceContext** independently of observation counts: both original source/query/scope/issue records, each selected stream's opening and closing response states, exact SHA256/bytes/request/URL, and distinct source-capture, connector-received, native-start and native-completion clocks. Original response buttons use the same native source-file receiver. Unchanged observations can coexist with different closing metadata bytes. A byte difference does not identify a particular metadata change, changed units, quality approval or a synchronized provider revision. Older retained comparisons that lack this context are labelled without reconstructing it.

A comparison does not silently move the project to its later source. After review, explicitly edit the current selection, choose the later edition and valid stream keys, retain a reason and save a new version.

### 8. Prepare the publication

**Publication** lists comparisons and supplied evidence bound to the selected version. Choose the exact items to include, enter the publication title and interpretation, then use **Prepare publication**.

The result includes:

| File | Contents |
|---|---|
| observations.csv | Every selected occurrence, all original observation columns and its exact selected stream key |
| observations.ndjson | Every selected row plus original occurrence, semantic and source-position bindings |
| selected-view.json | Complete saved version, source-edition manifest, summary, accepted review and rendering description |
| events.svg | Labelled original categorical/general source events and explicit intervals |
| numeric.svg | Labelled eligible original numeric instantaneous observations, with independent stream scales |
| locations.svg | Original finite Point coordinates from retained Thing Locations, without a basemap or inferred observation location |
| comparison-<id>.json | Each complete explicitly selected saved comparison |
| evidence-<ordinal>-<id>.<ext> | Exact bytes of each supplied evidence file, with its original record retained in the manifest |
| analysis-brief.html | Standalone readable and printable report with source/selection/review, data preview, annotations, comparisons and supplied evidence |
| publication-manifest.json | Exact file inventory and selected source, review, rendering, comparison and evidence bindings |

The complete native publication record includes every file's name, media type, byte count, SHA256 and original held-file descriptor. The manifest binds all preceding files; its own physical file identity is in that native record. The report is standalone and does not contact a mapping service, font service or external script.

The readable report and SVG views use deterministic source-order previews of at most **600 placed events and 600 eligible numeric points per stream**. They say how many occurrences are previewed and how many remain in the full data. Its row preview contains at most forty rows, category tables at most thirty categories, and comparison tables at most thirty changed/one-sided/ambiguous keys. The source, CSV, NDJSON, selected-view JSON and comparison files remain complete within the declared native capacities.

Quality-field presence counts report only value/null/missing states. The row preview also prints each original publisher-supplied resultQuality payload exactly, including its source citation; those declarations do not become independent quality approval. The complete payloads remain in the original data files.

The source-derived renderings are labelled separately from actual supplied Helgoland evidence. A missing screenshot is not replaced with a fabricated native output. Small original PNG/JPEG evidence can be embedded into the standalone report; all selected evidence files are retained regardless of the embedding limit. Other evidence formats are linked as exact original files.

CSV source cells are not rewritten to turn strings into numbers or alter provider formula-like text. Import such cells as text in a spreadsheet when the original representation matters.

It streams and resumes without making another file journal.

On the selected receiving environment, retain the real receipt or output from the actual configured receiving route. **Attach original receiving receipt** binds that complete file to the exact publication and records the operator's provenance note. Local hash verification and assertions made by the external receipt remain distinct.

For full editable handover, choose **Export complete project**. The original core freezes the complete selected project history when it reserves that operation. ## Data and numeric meaning

The implementation uses the original model's numericEligibility(row) for publication. A numeric rendering accepts only original JSON numbers from the explicitly declared OGC measurement/count families, with explicit instantaneous phenomenonTime. Count values must be integral; non-finite browser values and nonzero underflow are excluded. Exact source decimal lexemes remain in the original data.

OGC SensorThings 1.1 Table 12 distinguishes count, measurement, category, generic and truth observation result families. The corresponding source type remains part of each selected stream. See the [original OGC specification, Tables 10–12](https://docs.ogc.org/is/18-088/18-088.html).

The original Helgoland v2.2.3 client has its own browser ID and metadata constraints. Its native numeric connector is not used to encode categorical status values. The actual upstream viewer release and source declarations remain in the [52North Helgoland repository](https://github.com/52North/helgoland), with the original selected edition in the retained viewer manifest.

For the coordinated initial receiving workflow, the Hamburg charging-status observations and the separately acquired BGS pressure window are distinct original sources. Choose their actual imported edition IDs from the original intake result. Do not copy an illustrative ID, substitute a publisher example for a live retained capture, or acquire the same source again for this downstream application.

## Interrupted requests and revision changes

The browser keeps one private tab-session pending envelope containing workspaceId and the exact original action/payload/operationId/expectedRevision. It is a request cache, not another project database. Tokens are separate and never included in that envelope.

After an uncertain network reply:

1. Choose **Read original outcome**. The UI reads the same operation and checks its request hash against the retained action/payload.
2. COMPLETE returns the original result, including a result whose successful reply was lost. The UI clears only its pending cache and refreshes the original project.
3. RUNNING remains the original operation. **Resume exact original request** reuses its exact request. The original core either returns the in-process operation or continues the same retained execution after reopen.
4. FAILED retains the original failure. Inspect it and make a new explicit correction if required; a new operation must not masquerade as a retry of the failed one.
5. A 404 proves only that this read found no original reservation. **Review current revision** shows the exact pending payload, current revision and current project head before resubmitting an unreserved request.
6. If the project head changed, open that current head and reconcile the intended edit. The UI cannot silently rebase an annotation or selection onto a different version.

Do not create a fresh operation ID merely because a reply was slow or a browser page reloaded. The native journal remains authoritative. The page does not cancel a server operation when its frame or session is closed.

The original core's FAILED/RUNNING/COMPLETE behavior remains unchanged by these modules. The transfer's retained partial prefixes and completion records support the original operation's recovery; they do not invent another scheduler or policy.

## Portable project format and exact closure

~~~js
await exportProject(store, {snapshot, id, createdAt});

await importProject(store, {
  inboxDirectory, filename, expectedSha256, expectedBytes, id, createdAt
});
~~~

The snapshot schema is **stellar-forge.sensorthings-analysis-project-snapshot.v1**:

~~~text
originalWorkspaceId
project
versions[]      {record, version, summary}
comparisons[]   {record, comparison}
evidence[]
publications[]
receipts[]
viewers[]       complete original viewer manifests
editions[]      {edition, reviews}
analysisContract
~~~

The project archive is gzip-compressed framed NDJSON. Its first record contains the full snapshot and explicit original object/file inventory. Each member has its exact key, byte count and SHA256, contiguous base64 chunk ranges, and an end record. A final completion record binds the full manifest and member count. No host path is accepted from the archive; object targets and safe held-file storage paths are derived from the validated original manifests.

Validation includes:

- Original project/workspace identity and included head.
- Exact version/body identity, record bytes, summary bytes, parent/source relationships and acyclic history.
- Exact comparison content and its version/left/right source binding.
- Original edition source closure from the original native validator.
- Annotation references to included original editions/source members, with the exact JSON pointers checked against original bytes.
- Complete original viewer archive, declared assets, upstream source/licence objects, manifest identity, index/settings paths and content hashes.
- Exact evidence, publication and receiving-file storage/name/byte/hash descriptors.
- Complete explicit archive member order and every byte/chunk/hash/final-record check.

The export reads original CAS and held-file members through the original private-file helpers. It verifies complete file identity before and after streaming. The receiver first verifies the entire archive into an owned attempt prefix; it publishes objects, files and edition bodies create-only only after complete closure and citation validation. An existing target is reused only when its complete original size/hash matches.

The receiver returns the frozen snapshot and receipt to the original core. It never mutates project/workspace state, replays a capture, records a local source acceptance or imports payment operations. The core adopts compatible histories and preserves any existing local head.

A completed receiving operation can reopen from its retained manifest and exact target bytes even after the input archive is moved out of the inbox. Incomplete or failed attempt prefixes remain retained. Reusing an operation with a different input identity is rejected. Do not edit these records to force a receive.

## One combined receiving journey

The existing deployment/receiving owner runs the single coupled application journey on the original imported source IDs. The intended complete journey is:

1. Open the original workspace and actual categorical/numeric source editions.
2. Receive the original viewer archive once and save explicit event/map/numeric selections against actual source metadata.
3. Inspect original rows and metadata, record a source review and add cited operator annotations.
4. Review an actual later retained edition, then save an explicit revision where appropriate.
5. Launch the real original Helgoland map and eligible numeric diagram, using their actual visible controls when required by the original client.
6. Retain the actual resulting native evidence under its exact version.
7. Prepare and read the full source-bound publication through the original file API/downloader.
8. Export the entire editable project, receive it through the same native protocol on the selected receiving workspace, record local source review, and reopen its original selections/files/history.
9. Attach the real receiving output to the original publication and verify the final original result/history.

Preserve the actual original IDs, requests, source files and native result. A source checkpoint or JavaScript grammar check is not recorded as a completed native browser or receiving result.
