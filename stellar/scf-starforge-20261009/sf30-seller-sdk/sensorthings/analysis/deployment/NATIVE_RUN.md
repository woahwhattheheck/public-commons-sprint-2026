# Complete original analysis, publication and receiving run

This guide operates the existing SensorThings workspace, pinned Helgoland deployment, original file receiver and Python Analysis programme together. The native caller is [native-journey.mjs](native-journey.mjs); [native-journey.example.json](native-journey.example.json) describes its input.

The example contains clearly marked placeholders. It is not a returned workspace or an execution receipt. Fill it from the actual stopped original intake and selected installed runtime before running it. The caller rejects missing source identities and does not create a replacement source workspace.

The full deployment and manual operator flow remain in [OPERATIONS.md](OPERATIONS.md). [The analysis guide](../../ANALYSIS.md) describes the original forms and file actions. The [original Python guide](../../../../sf88-operator-buyer-cli/python/SENSORTHINGS_ANALYSIS.md) describes its editable queries, reports, workbooks and receiving behaviour.

## What this continuation owns

The original source owner acquires and retains provider responses. The maintained receiving drivers consume those exact recorded responses into the selected application workspace. This continuation starts from their actual returned workspace UUID, immutable edition IDs and completed source-export receipts.

It then uses the visible analyst forms to retain selections, responsible source reviews, cited annotations and comparison choices. It observes the real Helgoland map or eligible numeric diagram, records the actual source responses and native geometry, and attaches those exact output files to a frozen publication. It downloads the publication through the original file client, imports the complete editable project into a distinct receiving workspace, reopens the native view, records actual local receiving and exports the complete received project.

When the Python section is selected, the same run prepares each original source through the analyst's existing Python action, downloads every prepared file through the native manifest-bound receiver, and invokes the maintained complete Python programme. That programme produces editable SQL, complete query outputs, reports and workbooks, exports and restores its original Analysis workspace, and continues a saved query/report/workbook revision.

Finally, the caller closes its original listeners and browser, starts one fresh Node child, and reopens the same received application without a business action. The child verifies original source/viewer/version/publication objects and actual native output again. The native result is written after the owned processes and file readers have drained.

This caller does not acquire new provider data, start a payment, replace the source parser or implement a second analysis store. A local receiving record describes this installation's actual bytes and application readback. It is not an external customer acknowledgement or scientific approval.

### The two original view types

The Hamburg observations are categorical strings. Use the native map and the analyst's literal source/event view; do not assign numeric category codes, duration or uptime. The second Hamburg edition supports a real retained-edition comparison even when the observation values are unchanged.

The separate BGS stream is a scalar barometric-pressure source in mbar for the original 2026-06-01 UTC window. Its recorded source contains 96 observations. Use its actual edition and stream key for the eligible numeric view. Keep the original IDs, source units, timestamp precision, query window and source-quality declarations.

A selected numeric family alone is insufficient. The maintained model checks original JSON-number values, explicit instantaneous times, supported native IDs/relations and browser-safe representation. The caller observes the actual deployed availability and refuses to report an unavailable configuration as a rendered view.

## 4. Select the existing runtime and run once

The complete product and its existing dependencies must be installed together. The entry imports the maintained SensorThings server, managed client, native downloader and original store. Use the existing equipped Node, Playwright and Chromium selected for the original operation; this command performs no browser installation.

~~~bash
node /absolute/sdk/sensorthings/analysis/deployment/native-journey.mjs \
  --handoff /absolute/private/analysis-native-handoff.json \
  --output /absolute/private/analysis-native-output \
  --playwright-module /absolute/runtime/playwright-core/index.mjs \
  --browser-executable /absolute/runtime/chrome-headless-shell
~~~

The command opens the existing application only after checking its UUID. A second caller cannot own the same native output journal concurrently. The caller's process-held lease is separate from the original application's own writer lease; both remain authoritative.

The original listener uses its retained session and the original Bearer/workspace headers. Session values are passed in memory to the managed client and the selected same-origin browser. Progress records and publication evidence omit them. The actual native frame receives headers only through the analyst's existing registered-iframe function. There is no extra cookie, session, external data proxy or copied token literal.

Keep the configured memory, disk and inode envelope appropriate for the complete application, browser, archives and optional Python outputs. The source driver does not create a second scheduler or modify host reservations. Use the existing operation owner's supported admission and resume controls.

## 5. Understand the observed native rendering

The output records the selected deployment descriptor, exact saved version, original viewer assets and actual retained SensorThings responses. It waits for real data geometry in the pinned native viewer.

For map mode, it selects the original provider item by label and exact retained API URL, then observes the native Leaflet station layer. Visible original point/cluster markers or actual source geometry paths qualify. Tiles, controls, an empty container and a loading flag do not. Cluster icon counts are not station counts.

For numeric mode, it observes the main Helgoland D3 diagram's actual data path, points or bars. Axes, clipping paths, overview charts and loading completion alone do not qualify. The original v2.2.3 renderer filters zero-valued samples from some line/dot representations; generalization and surrounding values can also change the rendered point count. The native output records this limitation and retains all source observations separately.

The saved native historical URL uses the original native IDs and displayed millisecond bounds from the deployment descriptor. The source timestamps remain exact. The display's rounded viewport does not add observations or convert point observations into intervals.

A rendered chart is evidence that this native application rendered the selected source configuration. It does not certify sensor accuracy or establish a scientific conclusion. Cited operator interpretations remain attributed annotations alongside the original rows.

## 6. Publication, complete project receiving and continued edits

The run uses the original visible forms and retains their complete action body before dispatch. Publication includes the exact current analysis version, accepted source review, explicitly selected comparison and actual native evidence.

The distinct receiving application imports that exact downloaded archive through analysis.import. The caller verifies actual original object bytes, then records the required local source review and opens the same native view. It downloads the received publication again and compares the complete original filename/length/hash set.

Its text identifies it as local receiving evidence. The original project attaches those actual bytes to its publication, makes a final complete export, and receives that later archive while preserving the local head.

The final receiving backup is another original complete editable project export. It carries the original history, local review, actual receipt and any explicitly continued local annotation.

## 9. Resume the same original work

Use the same input file, output directory and original operation. Do not delete its requests, marker, application state or partial native receiver directory to make a retry appear new.

| Observed condition | Supported continuation |
|---|---|
| UI action response was lost | Read its saved original operation; the caller reuses the exact request body and ID |
| A form was partly filled but not dispatched | Reopen the same form; no action exists until the retained request boundary |
| An original source receiving is incomplete | Continue its same recorded-transport driver and inspect its actual failed request |
| A source warning is unreviewed | Review that exact edition; retain an explicit basis and required warning codes |
| Native diagram or map is unavailable | Read its exact retained metadata/eligibility findings; do not manufacture geometry |
| Native file download stopped | Continue the original selector, manifest and receiver export ID |
| A differing file occupies an output | Preserve it and the original expected hash; do not overwrite it |
| Project import response was lost | Read the existing import operation before any retry |
| Receiving has a later local head | Preserve it; the original importer retains both histories |
| Python programme stopped | Continue its original control/request and deterministic jobs |
| SIGINT or SIGTERM arrived | Let owned work drain, then resume the same retained invocation |
| native-result.json already exists | Verify its recorded complete outputs; do not repeat business actions |

The process lease prevents concurrent ownership, and the original application/store and Python programme keep their own existing concurrency controls. An unresolved missing original output remains unavailable until its exact bytes are restored. The caller does not silently re-render an already committed publication or obtain new provider values to fill a missing source file.
