# Complete worksheet operator, customer and Merchant receiving

This course consumes the actual completed native worksheet result and the exact editable packet named by that result. It receives that packet in a separate private workspace with the same original UUID, then operates the customer worksheet round through the real product.

## Inputs and command

Use the original native output OPERATED_DIRECTORY_WORKSHEETS.json and its workspacePacket. The native course is documented in [CORRECTION_WORKSHEETS_OPERATING.md](CORRECTION_WORKSHEETS_OPERATING.md). Preserve the unchanged native JSON bytes, its measured SHA-256 and the selected complete native ZIP together.

Run the complete installed source with existing Node, Python, Playwright and Chromium:

~~~sh
node ABS/fhir_directory/operate_correction_worksheet_clients.mjs \
  --native-receiving ABS/OPERATED_DIRECTORY_WORKSHEETS.json \
  --native-sha256 EXACT_NATIVE_JSON_SHA256 \
  --native-archive ABS/EXACT_NATIVE_WORKSPACE.zip \
  --workspace ABS/PRIVATE_CLIENT_WORKSPACE \
  --out ABS/PRIVATE_CLIENT_OUTPUT \
  --playwright ABS/EXISTING_PLAYWRIGHT/index.mjs \
  --chromium ABS/EXISTING_CHROMIUM_EXECUTABLE
~~~

Set SF30_DIRECTORY_PYTHON (or the existing inherited SF30_REFERRAL_PYTHON/SF30_ELTSS_PYTHON) to the actual interpreter when needed. No browser or dependency installation is part of the course. The complete source edition and all original source identities are bound in the journey.

## Complete sequence

The first phase imports the selected complete native ZIP through the original receiver, requires its actual completed receives row and original UUID, then verifies every immutable original Directory record by source-defined HTTP response bytes. It does not rerun source acquisition or the native worksheet construction.

Every original native returned file is received from its full file route. Only after those files exist does the course declare them as Merchant input aliases. That retains the actual original file hashes while allowing portability from the first producer's paths. Each original native accepted request is replayed against its expected immutable result, including raw returned-file PUT through the existing saved import.

The browser then selects the actual original CSV and JSON rows through the installed worksheet operator, prepares a new explicitly authored worksheet, and exports its portable package. The full native package is received and checked before extracting its unchanged customer.html and worksheet.json. The offline customer page uses the original embedded source and editor assets.

The course authors a quoted, multiline CSV description and an explicit JSON null plus a separately reviewed field. It downloads complete working JSON, closes and reopens the offline editor, imports that working file, and downloads the whole unchanged returned JSON. Original lexical JSON text is retained around the authored fields; no original numeric values are reserialized.

In the private operator, the complete returned file receives a saved byte-bound intake. The original raw bytes are retained before comparison. The full changes JSONL is downloaded and the operator uses its complete-file fallback. The course inspects absent versus null, accepts the explicitly selected proposals, keeps the separately reviewed field original, and records a reason for every decision.

The reviewed correction plan is opened in the existing source correction workbench. Candidate preview and exact acceptance are separate visible actions. The result keeps all worksheet/import/return/review/plan/preview/accepted-edition identities, complete working files and browser observations.

Connected receiving reads all four worksheet collections, complete records, pages and files, portable customer packages, original and derived correction sources, edition/comparison indices and complete changes. Large rows use full native files. Historical original records are compared before and after the round. Merchant closes and reopens against the same operator, then a read-only browser reopens the worksheet history.

Finally, the producer's complete editable workspace is exported and its operator closes. A fresh customer workspace imports that exact archive. The receiver requires the actual immutable complete import receipt and original UUID, checks every complete original record, closes its operator, starts it again, reopens all received history and exports the customer's actual completed state.

## Results and packet identity

The final result retains:

- nativeReceiving and nativeSha256: the exact unchanged native result.
- nativePacket: the selected original native packet bytes and SHA.
- originalCases and originalDirectoryReceiving: original native history and basis.
- browser: all retained request bodies, original upload descriptors, offline working and returned files, authored case IDs and screenshots.
- connected: original request replays, full records/pages/files and prepared exports.
- reopened: the same-instance Merchant reopening observation.
- customer: the actual fresh receiving workspace, original receive receipt, cold reopening and its complete exported workspacePacket.
- sourceWorkspacePacket: the producer's completed editable archive.
- workspacePacket: the final customer's completed editable archive.
- recordIds: the complete immutable registry inventory.

sourceWorkspacePacket and workspacePacket may have different hashes because the receiving workspace retains its own completed import receipt. Each completed result must travel with the exact packet it names. Never select an older packet solely because the workspace UUID matches.

All files and the complete journal remain under the selected private output. Save the whole output and the completed result independently before retiring a transient worker. The programme does not infer that an external customer submitted the authored example, accepted a service, or changed a publisher.
