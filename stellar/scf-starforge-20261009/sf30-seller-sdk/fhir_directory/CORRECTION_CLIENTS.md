# Complete correction operator, Merchant and customer receiving

The complete client course consumes the actual completed native correction result and its original received workspace. It performs original browser editing, explicit candidate acceptance, complete SDK/MCP reads and files, Merchant reopening, and fresh customer workspace receiving. It does not acquire a provider dataset or repeat the native source construction.

## Input and command

Keep the native OPERATED_DIRECTORY_CORRECTIONS.json unchanged. Its schema is stellar-forge.directory-corrections-operated.v1 and operation is SCF-DIRECTORY-CORRECTIONS-450E-20261013. It supplies the original UUID, native cases, exact accepted replay inputs, original Directory record hashes and complete editable workspace.

```bash
node fhir_directory/operate_correction_clients.mjs \
  --receiving /ABS/OPERATED_DIRECTORY_CORRECTIONS.json \
  --workspace /ABS/RECEIVED_ORIGINAL_WORKSPACE \
  --out /ABS/CORRECTION_CLIENT_OUTPUT \
  --playwright /ABS/EXISTING_PLAYWRIGHT/index.mjs \
  --chromium /ABS/EXISTING_CHROMIUM
```

The optional --playwright selects an already installed module. --chromium names the actual existing executable; no browser acquisition is part of this programme. Use the same source, native JSON, workspace and output directory after an interrupted attempt. The original operation lease prevents simultaneous writers to this selected client output.

The client operation is SCF-DIRECTORY-CORRECTION-CLIENTS-450E-20261013. Its journal is CORRECTION_CLIENTS_JOURNEY.json and final result is OPERATED_DIRECTORY_CORRECTION_CLIENTS.json, schema stellar-forge.directory-correction-clients-operated.v1.

## Whole receiving sequence

The programme opens one original native Directory operator and connects the maintained Merchant host. It reads every immutable Directory collection through complete native JSON responses, verifies all original Directory hashes and checks each completed correction plan/preview/accepted record against the native result.

The browser opens each original saved plan as an explicitly labelled working copy. It reopens actual original rows, retains lexical JSON or physical CSV values, modifies its own review reason, saves complete unfinished and finished working JSON, reloads the browser state, saves the native plan, builds its candidate preview and explicitly accepts that exact candidate. The browser then uses **Start successor from accepted edition**, selects a row from the actual derived directory-capture source and completes another explicit correction. It verifies the accepted predecessor and candidate chain. The original native cases remain unchanged. Desktop and mobile observations retain actual page images and errors. A request observer journals every exact browser mutation before dispatch; resuming an uncertain response reconciles that original body.

The connected course replays only the original accepted native requests with their expected immutable IDs. It reads every contiguous change page and receives the complete plan input, review graph, change JSONL, original and derived source files, candidate/source edition indexes, comparison index/changes and complete correction packets. Full downloads are reopened and checked against their original descriptor and manifest. Original numeric values are never reconstructed from a shortened UI view.

Merchant closes and reopens while the native operator preserves the same original workspace. The course compares all immutable native record response hashes and reopens every authored correction stage through a read-only browser. It then exports the whole producer workspace and releases that original host before opening the separate customer receiver.

The customer imports that exact archive using the original native complete workspace receiver. A repeated import is verified using the actual full receives row keyed by the original archive hash, kind workspace, state complete and original UUID; mutable workspace state is not used as a stable receipt identity. It compares every original immutable record, reopens each full correction stage and finally exports the customer's actual received workspace.

## Files that travel together

Retain the complete output directory and both selected archives:

- The unchanged native result and original native archive identify the basis.
- CORRECTION_CLIENTS_JOURNEY.json retains original input/record/file bindings, request recovery and every actual browser attempt.
- OPERATED_DIRECTORY_CORRECTION_CLIENTS.json contains browser cases, connected results, original record IDs, customer receiving and full file identities.
- sourceWorkspacePacket is the complete producer archive before independent customer receiving.
- workspacePacket is the complete archive exported from the actually received customer workspace. This is the final editable customer handover.
- downloads/ contains complete original response manifests and files, including raw source and full correction packets.
- browser/ contains complete unfinished and finished working JSON; root images contain actual desktop, mobile and reopened views.
- inventories/ contains complete immutable record hashes before, after, across Merchant reopening and after fresh customer receiving.

The selected result must travel with its own workspacePacket. A later export of another state can have another hash even when it has the same original UUID.

Completed journal steps reopen their existing complete files. An interrupted original request retains the exact action and input. The course keeps source-file identities in its binding and rejects silently changed source, inputs or output roots. Customer import completion and file custody are checked against the actual native receiver, including full registry and correction semantic verification.
