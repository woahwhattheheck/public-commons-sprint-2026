# Operate the native Python producer

The complete application includes an OpenLineage Python 1.53.0 producer. It sends original events through the released SDK's serializer and HTTP transport, retains the SDK's actual request bytes, and reconciles the workspace acknowledgement against those bytes. Use it to connect an existing pipeline or deliver retained producer files into the same operational workspace.

## Prepare the selected runtime

The pinned client requires Python 3.10 or later. Prepare a private runtime once:

```sh
python3 -m venv /absolute/private/openlineage-python
/absolute/private/openlineage-python/bin/python -m pip install \
  -r /absolute/application/python-producer-requirements.txt
```

The requirement pins `openlineage-python==1.53.0`. The producer verifies the installed distribution version before opening the transport. A prepared environment can be carried through the operator's existing runtime/dependency transfer workflow. The application's Node receiver continues to use Node builtins; Python dependencies belong in this selected producer runtime.

## Send complete original files

Start the workspace as described in [PRODUCERS.md](PRODUCERS.md), using a separate producer token when authentication is required. Supply its actual current connection file:

```sh
node /absolute/application/cli.mjs native-python emit \
  --python /absolute/private/openlineage-python/bin/python \
  --directory /absolute/private/pipeline-delivery \
  --connection /absolute/lineage-project/connection.json \
  --token-file /absolute/private/producer-token \
  --input /absolute/original/events.ndjson \
  --input /absolute/original/next-run.json.gz \
  --operation-id daily-pipeline-20261012 \
  --compression gzip
```

The installed merchant command is `starforge openlineage native-python` with the same arguments. Direct Python use is also supported:

```sh
/absolute/private/openlineage-python/bin/python \
  /absolute/application/native_python_producer.py --help
```

Inputs can be a JSON event, event array or NDJSON, optionally gzip compressed. The operation retains each complete original file and emits its events individually through the SDK. Source files stay unchanged. The workspace receives the actual SDK-serialized event body, with its own original wire identity and decoded identity.

The directory belongs to one intended delivery. It records the selected workspace, original inputs and event positions, stable operation IDs, each prepared request, and each acknowledged outcome. Repeating the command with the same directory and input plan continues the original delivery. A different input or workspace needs a new directory.

A settings file downloaded from the browser or generated by `producer-config --client python` can be passed as `--config /absolute/private/python-openlineage.json` instead of `--connection` and `--token-file`. The generated settings are JSON and valid YAML. This producer reads their JSON form directly. Settings and tokens remain private host configuration.

## Continue an interrupted delivery

Inspect retained progress without installing or contacting the SDK:

```sh
node /absolute/application/cli.mjs native-python status \
  --python /absolute/private/openlineage-python/bin/python \
  --directory /absolute/private/pipeline-delivery
```

Resume from the original retained inputs after observing the restarted workspace's current connection:

```sh
node /absolute/application/cli.mjs native-python resume \
  --python /absolute/private/openlineage-python/bin/python \
  --directory /absolute/private/pipeline-delivery \
  --connection /absolute/lineage-project/connection.json \
  --token-file /absolute/private/producer-token
```

The workspace pin must remain the same. The address and server instance can change after a restart. An already acknowledged event is reconciled locally with its retained original request and receipt. An unacknowledged event reuses its original operation ID and exact first SDK wire body, including gzip bytes. This preserves the original source identity even when the next SDK serialization would give a different gzip timestamp.

Successful delivery requires the original receiver's acknowledgement to match the workspace, operation ID, wire SHA-256 and byte count, plus the decoded identity for gzip. Redirect following is disabled. HTTP errors remain native SDK errors; the next invocation continues from the saved original request. Each receipt records the committed revision and any server replay.

The private directory contains:

| File or directory | Purpose |
| --- | --- |
| `producer.json` | Selected workspace and SDK version |
| `plan.json` | Original input ordering, event counts and operation family |
| `originals/` | Complete original files in byte-preserving records |
| `requests/` | First actual SDK wire bytes and original event attribution |
| `receipts/` | Matching saved workspace acknowledgements |
| `complete-result.json` | Completed operation's retained result |

Configuration and token values are omitted from these delivery records. Keep the directory with the pipeline's private operational state. Carry the original directory to the receiving host when continuing that same producer delivery.

## Use inside an existing Python pipeline

```python
import json
from pathlib import Path
from native_python_producer import WorkspaceProducer, configuration

settings = configuration(
    Path("/absolute/lineage-project/connection.json"),
    Path("/absolute/private/producer-token"),
    "gzip",
)
event = json.loads(Path("/absolute/original/event.json").read_text())
with WorkspaceProducer(settings, "/absolute/private/owned-event-delivery") as producer:
    saved = producer.emit(event, "existing-pipeline/run-20261012/event-1")
    print(saved["acknowledgement"])
```

Use the pipeline's existing stable delivery identity. The serializer accepts the original event mapping and the SDK's typed event objects. A changed event under a retained operation ID is rejected. For file input attribution and full operation continuation, use the CLI's retained input plan.

The implementation constructs the released `HttpTransport` directly and injects the supported requests session. This allows the original SDK request and actual receiver response to be retained together. The pipeline controls the event content explicitly; configuration downloaded from this workspace selects the native HTTP endpoint.

## Original SDK contract

The implementation uses the released [openlineage-python 1.53.0](https://pypi.org/project/openlineage-python/1.53.0/) package. The original [HTTP transport at tag 1.53.0](https://github.com/OpenLineage/OpenLineage/blob/1.53.0/client/python/src/openlineage/client/transport/http.py), Git blob `b90d33de88803fd8bc8ac65163f2af1e5cb760c1`, defines the supported session injection, compression, custom headers and response handling. The existing workspace producer guide explains its corresponding receiver contract.
