Handover workflow

  1. Preserve each original JSON-v4 file and its source details.

  2. Follow site, equipment and point references within each source.

  3. See each before-and-after value, then accept or reject deliberately.

  4. Capture the selected sources and reviewed changes together.

  5. Export a register, a native grid, or the complete editable workspace.

Open or receive a local workspace

The local server opens one explicit directory. Use the CLI to create a workspace, start it, or receive a complete bundle into a new directory.

node cli.mjs init --directory ./handover --title "Building handover"
node cli.mjs serve --directory ./handover
node cli.mjs receive --file ./handover-workspace.json --destination ./received-handover

Use the server address printed by the local command and, when configured, the token from its private file in .

Package the application, every original source file, saved editions, proposals and workspace history together. The receiver verifies the package and creates a separate local workspace.

Receive a workspace

Download the complete workspace file, then choose a new local destination with the CLI.

node cli.mjs verify --file ./handover-workspace.json
node cli.mjs receive --file ./handover-workspace.json --destination ./received-handover
node ./received-handover/application/cli.mjs serve --directory ./received-handover

The receiving command reports the exact application path and launch command for the installed bundle.
