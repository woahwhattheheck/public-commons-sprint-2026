# PRS source API

This leaf is the single XML engine for the existing ClinicalTrials workspace. It accepts original bytes and returns JSON-safe reports or a separate generated byte document. It performs no service request, stores no credentials, starts no database and changes no host workspace revision.

## Installation and direct import

Python 3.10+ and lxml are required. The operated source used Python's installed lxml 6.1.1 with libxml 2.14.6. Install the declared requirements in the application's selected Python environment. Keep this entire directory, including schemas/ and profiles/, beside clinical_prs.py.

~~~python
from prs import (
    PrsError, doctor, inspect, compare, prepare, apply,
    preview_upload, reconcile, catalog,
)
~~~

The API can also be imported as clinicaltrials.prs when the parent is a Python package. All functions accept schema_dir=None; its default is this component's schemas/ directory. A supplied directory contains the same source-contracts.json and its three exact original files. XML validation supports a deliberately selected new source directory; the migration, merge and typed field profiles identify and require the original source edition against which they were authored.

PrsError extends ValueError. Its public properties are code and details. as_dict() returns {error:{code,message,details}}. The host may translate this to its existing HTTP status and request identity. lxml schema error dictionaries contain original line, column, level, domain, type, path and message.

## doctor(schema_dir=None)

Returns schema=stellar-forge.prs-doctor.v1, ready, available, lxmlVersion, libxmlVersion, maxXmlBytes, schemaSetSha256, schemaSources and bundledProfileMatches. A missing dependency or uncompileable source set is reported as ready=false. The complete Protocol XSD imports the retained Results XSD through the resolver's exact local source closure. It never resolves an input document's schemaLocation over the network.

Each schemaSources row retains filename, byte length, SHA-256, original/final URL, observedAt, response status and original headers. The Protocol header is 2018.05.08; the Results header is 2023.03.30. These are the exact files captured from the official endpoints on 12 October 2026.

## inspect(xml_bytes, schema='protocol', schema_dir=None)

xml_bytes is bytes, bytearray or memoryview, containing 1–268,435,456 original bytes. schema is protocol or results. The result is:

~~~json
{
  "schema": "stellar-forge.prs-inspection.v1",
  "inputSha256": "complete SHA-256",
  "bytes": 7853,
  "schemaKind": "protocol",
  "wellFormed": true,
  "schemaValid": true,
  "schemaErrors": [],
  "schemaSetSha256": "complete SHA-256",
  "schemaSources": [],
  "rootName": "{http://clinicaltrials.gov/prs}study_collection",
  "encoding": "UTF-8",
  "legacyElements": [],
  "studies": [],
  "sourceIssues": [],
  "references": {"valid": true, "ids": {}, "references": [], "errors": []}
}
~~~

A parse failure is an inspection with wellFormed=false and schemaValid=false. A source/dependency failure raises PrsError. Validation uses the full original XMLSchema, including sequence, xs:all, required children, attribute types, namespace and results references. XSD validity and documented PRS business expectations remain distinct fields.

Each study retains its 1-based index, original organization/protocol identity, provider's internal identifiers, exact expanded-name occurrence path, title, protocol upload intent and any nested results upload intent. A legacy occurrence has elementId, ruleId, studyIndex, studyKey, original path/line/value, allowedReplacementFields, currentReplacement and its NLM notice/XSD location. Identical local names outside the source-defined legacy paths remain regular source content.

An occurrence path is an array of {name,occurrence}; name is the complete Clark expanded name, and occurrence is 1-based among siblings of the same expanded name. An elementId is bound to the complete original XML hash and exact occurrence path. Read the IDs from the current inspection; never manufacture them from a displayed label.

The references report checks document-wide RRS ID uniqueness and every reportingGroupId/outcomeReportingGroupId against the original declarations. It retains duplicate, missing and ambiguous references even when a schema engine reports a different subset of those issues.

## compare(original_bytes, candidate_bytes, schema='protocol', schema_dir=None)

Returns stellar-forge.prs-comparison.v1 with both SHA-256s, byteIdentical, before/after inspections, comparable, contentEqual and the full changes array. Each change identifies the source organization/protocol key and exact expanded occurrence path, and retains its before/after attributes and leaf value.

The comparison ignores indentation on complex parent elements but preserves exact leaf strings, original same-name occurrence order and all attributes. A pure serialization change can therefore be byteIdentical=false and contentEqual=true. Duplicate study identities remain separate original occurrences and are also reported by inspection.

## prepare(xml_bytes, decisions, reviewer, rationale='', schema_dir=None)

Returns the immutable, JSON-serializable stellar-forge.prs-modernization-plan.v1. The caller supplies the actual reviewer label and explicit decisions:

~~~json
[
  {
    "elementId": "copy from this original document's inspection",
    "action": "replace",
    "reason": "The reviewed current completion date belongs in the supported field.",
    "replacement": {
      "last_follow_up_date": "2026-09",
      "last_follow_up_date_type": "Actual"
    }
  }
]
~~~

Supported actions are keep, remove and replace. Every selected occurrence requires a nonempty reason. Replacement values are explicit native strings; they are limited to the selected rule's fields:

| Original occurrence | Explicit supported replacement fields |
|---|---|
| end_date | last_follow_up_date, last_follow_up_date_type |
| sponsors/resp_party/name_title, organization, phone, phone_ext, email | investigator_username, investigator_title, investigator_affiliation |
| study_design/interventional_design/masking | no_masking, masked_subject, masked_caregiver, masked_investigator, masked_assessor |
| Other deprecated names | Removal or retained review decision |

A replace decision can deliberately change an already populated supported value; its previous and new values appear in applied[].nativeChanges and the full comparison. Two decisions cannot supply conflicting values to the same replacement field. The investigator username comes from the operator's known PRS identity; the engine never derives it from a display name or email. Individual masking roles come from the reviewed study design. The original XSD describes yes/no spellings; the full validator still reports its actual declared string semantics.

The plan retains exact input/source hashes, normalized decisions, original occurrence values, changes, candidate hash/length, before/after inspection, unreviewed occurrence IDs, candidate schema validity and source-based semantic issues. planSha256 covers the entire plan before the digest is appended. Unselected legacy content remains present and visible.

## apply(xml_bytes, plan, schema_dir=None)

Returns (candidate_bytes, report). Apply checks the complete plan digest, original input hash and source edition, reconstructs the same reviewed changes, and requires the candidate and plan hashes to reproduce. The original and candidate are separate artifacts in the existing host.

Candidate serialization is UTF-8 XML with a declaration when an edit is made. With only keep decisions or no changes, apply returns the exact original bytes. Schema validity and masking contradictions are returned in the report; creating an inspectable candidate does not claim acceptance by a PRS account.

The host's accepted actions are:

| Existing workspace action | Direct leaf operation |
|---|---|
| prs.import {original XML} | inspect(original bytes), retain input and complete report |
| prs.plan {documentId,decisions,reviewer,rationale} | prepare(retained bytes, ...), retain full plan |
| prs.apply {documentId,planId} | apply(retained original, retained plan), retain candidate/report |
| prs.reconcile {documentId,captureId,plan} | reconcile(retained XML, original capture study objects, plan) |

The original Workspace.act(..., expected_revision, request_id) remains responsible for mutation custody, revision checking and idempotency.

## preview_upload(base_bytes, incoming_bytes, schema='protocol', rules=None, reviewer='', schema_dir=None)

Returns (candidate_bytes, report) for a local source-attributed composition. It retains the two inputs' hashes, complete incoming inspection, source edition, operations, unresolved rows and base-to-candidate comparison.

| Source instruction | Composed behavior |
|---|---|
| Protocol normal/full record | Replace the included record's content; other records in the retained collection stay present |
| Protocol partial_upload=true | Match the explicit organization/protocol identity and process the source-defined submitted units |
| Omitted or empty protocol partial unit | Retain the previous value/list |
| Included nonempty protocol partial unit | Replace the entire value or list, preserving incoming occurrence order |
| One otherwise empty delete=true tag | Delete the complete source-defined value/list |
| Results partialUpload=true | Replace each included results subset; retain omitted subsets |
| Results partialUpload absent/false | Replace all results content |
| Delayed disposition after established results | Preserve the established resultDisposition under the original source instruction |

Protocol and Results use different attribute spellings. The mandatory empty outcomeMeasures container counts as an included results subset. It therefore replaces the old outcome list in a results partial preview.

complete=false means the report contains a precise unresolved operation. The preview retains that unit's previous content. A missing partial base, mixed replacement/deletion list, nonempty delete tag or undocumented current top-level partial unit is reported. The original comments still name old design tags where the actual schema has study_design. An optional rules mapping such as {"study_design":"replace_unit"} records a named reviewer's interpretation; it stays separate from NLM-defined behavior.

Always inspect incomingInspection and comparison.after as well as complete. A documented delete intention can coexist with an actual XSD error when the source complex type requires children.

## catalog(schema_dir=None)

Returns the complete selected profile with 185 explicit field routes, profileSha256, source hashes and schemaSources. Each field has id, label, xmlPath, apiPath, type and any enum, repeated-field or identity-link specification. xmlPath is relative to an original clinical_study and uses exact expanded names. apiPath is relative to a complete native API study object; "*" is an array occurrence selector.

The profile includes 97 protocol and 88 results routes. It preserves source dates, source-language enum spelling, partial dates, exact numerical tokens and explicit result-record identities. Unmapped source fields remain part of the reconciliation report and original artifacts.

## reconcile(xml_bytes, api_records, plan, schema_dir=None)

The host passes exact per-study raw JSON from its existing retained capture:

~~~python
api_records = [{
    "rawJson": original_complete_study_json,
    "source": {
        "captureId": capture_id,
        "pageReference": original_page_reference,
        "observedAt": observed_at,
        "apiVersion": "2.0.5",
        "dataTimestamp": "2026-10-09T09:00:05"
    }
}]
~~~

Every native study must contain its own valid NCT identifier at protocolSection.identificationModule.nctId. The parser rejects duplicate keys and nonfinite numbers and preserves each JSON number token. If supplied, source.sha256 must match the exact rawJson bytes. A capture containing multiple editions of the same NCT must select one exact edition before reconciliation.

~~~json
{
  "studyLinks": [
    {"studyIndex": 1, "nctId": "NCT03529110", "reason": "Explicit original protocol identifier matched by the disclosure reviewer."}
  ],
  "fieldIds": ["protocol.organizationStudyId", "protocol.enrollment"],
  "recordLinks": [],
  "idLinks": [],
  "decisions": [],
  "reviewer": "Actual reviewer",
  "rationale": "Original sponsor edition compared with this retained public registry edition."
}
~~~

A study link is an explicit operator assertion. The engine reports both identities and source hashes for that assertion; it never equates provider_study_id, a PRS internal identifier, with an NCT number. An empty studyLinks array returns the source inventories and unlinked records for selection.

The result has schema=stellar-forge.prs-reconciliation.v1, original inspection, selected profile/source hashes, API sources, study joins, complete findings, unlinked studies, original plan/reviewer, summary and reportSha256. Each finding includes its exact XML values/paths and API values/JSON pointers, typed normalized values, comparison basis and status. Original number lexemes are carried as raw.kind=number/raw.numericLexeme; exact decimal normalization never passes through binary float.

Missing, null, empty string and empty array are distinct source states. Partial-date precision remains explicit. Text comparisons preserve the exact captured Markdown and XML textblock content. Simple repeated protocol values use original document order, with that basis clearly identified. Correlated protocol records such as outcomes, arms, interventions and sites require explicit recordLinks, as do results collections; this prevents a missing field in one row from silently shifting its comparison to a different row.

### Explicit results record and group links

Fields in correlated protocol records and result collections require recordLinks to establish source row identity. Each entry pairs one original XML complex element with one original native API object:

~~~json
{
  "studyIndex": 1,
  "xmlPath": [
    {"name":"{http://clinicaltrials.gov/prs}study_collection","occurrence":1},
    {"name":"clinical_study","occurrence":1},
    {"name":"{http://clinicaltrials.gov/rrs}result","occurrence":1},
    {"name":"reportedEvents","occurrence":1},
    {"name":"interventionGroups","occurrence":1},
    {"name":"interventionGroup","occurrence":1}
  ],
  "apiPointer": "/resultsSection/adverseEventsModule/eventGroups/0",
  "reason": "Exact sponsor intervention description and original disclosure row reviewed."
}
~~~

Use paths and pointers returned by the current reconciliation, rather than constructing labels as IDs. Links are one-to-one inside a study. Descendant comparisons use the most specific explicit link. Group declarations on such an explicit pair provide its XML-ID to API-ID mapping in the actual API module or outcome scope. Nested secondary_id lists use their actual id_info parent in partial composition. Full protocol replacement still applies an explicitly partial nested results update against the retained results section.

An optional idLinks entry supplies {studyIndex,xmlId,apiId,apiScope,reason}; the XML declaration and API scope must exist.

Unlinked result rows remain record_link_required. Unmapped group references remain group_identity_link_required. Original IDs are not made equal by matching spelling or numeric suffix. The complete linked or unlinked source data remains in findings and unmappedXml/unmappedApi.

### Review dispositions

First run the report, then reuse its findingId with a disposition:

~~~json
{"findingId":"copy exact report ID","decision":"revise_xml","note":"Reviewed source-specific correction and supporting record."}
~~~

Supported decisions: accept_difference, revise_xml, revise_source, investigate, accept_equivalence. A decision needs an actual reviewer and note. Finding identity covers original XML/API hashes, selected profile, exact links and comparison. A disposition from another edition or scope is rejected. Dispositions annotate findings; they never rewrite source data or mark an unresolved comparison as an equality.

## Command line

From the clinicaltrials parent directory:

~~~bash
python -m prs doctor
python -m prs inspect source.xml --schema protocol --output inspection.json
python -m prs prepare source.xml --decisions decisions.json --reviewer "Disclosure operator" --output plan.json
python -m prs apply source.xml --plan plan.json --candidate candidate.xml --output application.json
python -m prs compare source.xml candidate.xml --output comparison.json
python -m prs preview-upload previous.xml partial.xml --candidate composed.xml --output impact.json
python -m prs reconcile source.xml --api-records retained-studies.json --plan reconciliation-plan.json --output reconciliation.json
~~~

The optional global --schema-dir precedes the command. Output files use no-clobber atomic writes; --overwrite explicitly replaces an existing output. Source and candidate/report paths remain distinct.

A CLI API-record descriptor can use rawJsonFile instead of rawJson. Relative paths are resolved beside the descriptor:

~~~json
[
  {"rawJsonFile":"capture/NCT03529110.json","source":{"captureId":"the existing capture","pageReference":"the original page"}}
]
~~~

Reports print as JSON when --output is omitted. A successful inspect command can report schemaValid=false: inspecting invalid source is a completed operation. Native dependency/input/review errors return exit 2 with structured error JSON on stderr.
