# Receive a retained public-source acquisition

Use `capture-received` when the original CKAN responses have already been acquired
through Commons' connected public-source helper. It consumes the complete bundle
locally and produces a normal CKAN capture for import, semantic projection,
merchant publication and reviewed refresh.

The receiving command invokes `captureCkanResource()` from this directory.
The existing engine parses the literal source bodies, follows the selected
pagination, checks the provider's exact totals and field declarations, preserves
exact numeric tokens, and compares source metadata before and after paging.

## Acquire and retain the complete source

The acquisition carrier is Commons
[`host/connected_public_source.cjs`](https://github.com/woahwhattheheck/commons/blob/main/host/connected_public_source.cjs).
Keep the literal acquisition result and its complete `commons.source-bundle/v1`
JSON file with the original operation ID. Its receipt identifies every original
public HTTPS URL, successful upload/download, response byte count, digest and
acquisition time.

Acquire these named members in order for the exact selected resource:

| Member | Original response |
| --- | --- |
| `package.json` | `package_show` for the selected package |
| `resource.json` | `resource_show` before paging |
| `schema.json` | Selected CSVW schema, when configured |
| `pages/00000000.json`, and following numbered pages | Each original `datastore_search` response through its terminal page |
| `resource-after.json` | Independent `resource_show` after paging |
| `schema-after.json` | Independent following CSVW schema, when configured |
| `public-source-receipt.json` | Complete acquisition receipt, included by the helper |

The DataStore URL must be the exact request generated by the selection: resource
ID, limit, `sort=_id asc`, records format, total flag, filters, optional query
and offset or keyset cursor. Preserve each literal JSON body. A selected page
size is a request; pagination completion follows the returned page limit and
total through the original engine.

The helper's JSON members use `encoding: "base64"` and the `content` field.
The receiver validates each decoded member against its declared bytes and
SHA-256. It also binds the successful carrier receipt to those same source
members, upload IDs, download IDs and original URLs.

## Receive, import and refresh

Place the complete bundle and selection in a private directory. Use the original
bundle's exact byte count and SHA-256; receiving is a local operation.

```sh
node sf30-seller-sdk/ckan/cli.mjs capture-received \
  --bundle ./ckan-work/source/source-bundle.json \
  --bytes BUNDLE_BYTE_COUNT \
  --sha256 BUNDLE_SHA256 \
  --operation ORIGINAL_OPERATION_ID \
  --selection ./ckan-work/source/selection.json \
  --out ./ckan-work/received-capture

node sf30-seller-sdk/ckan/cli.mjs import \
  --project ./ckan-work/library \
  --capture ./ckan-work/received-capture/capture.json
```

The command prints the real capture path and manifest SHA-256, complete manifest,
and acquisition binding. The existing workbench accepts this capture through
`import`. Follow [REVIEWED_REFRESH.md](REVIEWED_REFRESH.md) to compare an
existing published source with the following edition, review its actual changes
and publish the accepted successor.

Programmatic callers import `receivePublicSourceCapture` from
`retained-public-source.mjs`. The first argument has the same six named
inputs as the CLI: `bundleFile`, `bundleBytes`, `bundleSha256`,
`operationId`, `selection` and `captureDirectory`. The optional
second argument passes the original capture capacity, cancellation and
`onProgress` callback. The receiving transport always reads the selected
bundle.

## Continue an interrupted run

Re-run with the same bundle identity, operation, selection and capture directory.
The receiving path binds these inputs before capture. The original capture lock
and progress journal own the operation.

On resume, the receiver checks actual saved response files before constructing
the remaining source sequence. This covers a process stopping between saving a
response body and updating capture progress. A completed capture is reused after
its full retained body hashes and selection are checked. Existing raw responses
require the original capture progress.

The capture directory contains:

- The normal `capture.json`, `progress.json`, original metadata and numbered pages.
- `source-input.json`, binding this capture to the bundle and selection.
- `source-acquisition.json`, the literal original acquisition receipt.
- `source-acquisition-binding.json`, binding the completed native capture
  hash and row/page counts to that receipt.

Keep these companions and the complete source bundle in the delivery alongside
the native capture and any resulting merchant workspace. Companion paths are
relative to their capture directory, so separate editions remain independent.

## Metadata and resource limits

The connected import returns the complete body and its successful transfer
receipt. It omits upstream HTTP response status and headers. Native capture
receipts therefore retain `status: null` and empty HTTP headers; the
acquisition receipt retains the original connector metadata and source times.
The native capture's receiving clock describes local consumption of those saved
responses.

This path accepts public sources on the selected HTTPS catalogue origin.
Credential-bearing selections continue through the ordinary direct capture
route. The original capture limits remain in force. The complete source bundle
has a 96 MiB receiving limit and up to 256 acquired members, matching the
connected source helper's maximum source count.
