# Gravity Referrals

Gravity Referrals is a complete private operator for a source-selected referral. It retains the original Task, ServiceRequest, Consent and related resources; reviews all 57 source requirements and 24 operating fields; records source, target and intermediary ownership; preserves responsible decisions and reviewed corrections; operates conditional HTTP exchange; and delivers a complete editable workspace and native customer dataset.

The eleven views are Queue, Sources, Referral editions, Requirements & fields, Actors & servers, Decisions & consent, Corrections & history, Native exchange, Datasets & queries, Handoffs & receiving, and Source guidance. The neutral industrial interface keeps local drafts and saves complete native records.

## Open the private operator

From the original SF30 SDK directory:

~~~sh
node fhir_referral/cli.mjs init --workspace /absolute/private/gravity
node fhir_referral/cli.mjs serve --workspace /absolute/private/gravity --port 0
~~~

The installed command is **gravity-referrals**. Open the emitted private URL, enter the responsible operator name or role, and continue in that workspace.

Python 3.11+ and Node 22+ use the existing FHIR/eLTSS source, native dataset, credential and receiving engines. SF30_REFERRAL_PYTHON and SF30_REFERRAL_NODE select installed executables. Existing authenticated connections use a local --credentials-file. Reopening can require --expected-workspace-id ORIGINAL_UUID.

## Complete operating sequence

1. **Retain complete originals.** Upload original JSON or a declared native source ZIP. Published-example intake also retains the original archive, every JSON member and explicit reference-base assignments.
2. **Select actors and servers.** Choose direct, direct-light, intermediary or intermediary-light. Keep exact organization references, operating owners and saved connections. Recipient-server ownership is an explicit selection.
3. **Save the referral edition.** Select the source and 1–100 original Task records, reference policy, configuration and predecessor. The graph retains focused requests, subjects, outcomes, consents and unresolved relationships.
4. **Adopt the complete review.** Keep every requirement and field key. Each reviewed disposition carries its owner, reviewer, reason, mapping, citations and receiving reference. Changes create complete successor reviews.
5. **Assess the source.** Freeze the edition and review. Each Task detail opens all 24 field observations beside unchanged source JSON. Complete files retain the full queue and every finding.
6. **Record responsible decisions.** Save scoped ownership, consent, workflow, finding, contact and resource-link records. The source Consent and a purpose-specific operating permission remain separately inspectable.
7. **Review an exact correction.** Select original resource IDs and JSON Pointers, inspect old and new values, and apply the retained preview/hash. The successor preserves its predecessor and qualified resource mapping.
8. **Operate native exchange.** Select saved capability, role and endpoint. Conditional updates retain the actual preimage, ETag, request, response and readback. Continue the same UUID. Task search and instance history retain their supported parameters.
9. **Build and receive the native dataset.** Save the source-derived mapping and original keys, inspect projection, build, query and compare, then download the complete merchant/customer packet.
10. **Deliver and reopen.** Freeze the full handoff, receive its ZIP, attach the actual result file and destination/operation, then receive the whole editable workspace into a fresh directory under the original UUID.

## Source and capacity

The installed publication is [Gravity SDOH Clinical Care 3.0.0](https://hl7.org/fhir/us/sdoh-clinicalcare/3.0.0/) on FHIR 4.0.1. The source envelope retains 191 complete repository files with original paths and hashes. The profile retains 57 original requirements and the separately authored 24-field interpretation. Selecting legacy 2.3.0 requires its complete original profile artifact.

The native catalogue exposes the enforced limits: 256 MiB complete source/artifact input, 10,000 indexed resources, 100 referrals per edition and 512 MiB editable workspace archives, alongside the existing member, reference and interactive limits. Input classification distinguishes published examples, client originals and authored transformations.
