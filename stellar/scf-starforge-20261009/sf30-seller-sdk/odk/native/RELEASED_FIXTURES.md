## Existing driver contract

Each `forms[]` entry contains `key`, `formId`, `versions[]` and `submissions[]`. A version supplies its original `xml`, `version` and `versionRouteToken`. A submission supplies its original `instanceId`, `formVersion`, `xml`, `updates[]` and `attachments[]`. Updates explicitly include `rootInstanceId`, `deprecatedId` and their new `instanceId`. Attachments supply `name`, `contentType`, exact `base64`, bytes and SHA256.

The native driver selects its already-authorized project and adds that actual project ID to each source selector. The constants contain no endpoint, credential value, assumed project ID, created-at timestamp or native completion receipt.

Use the released REST routes, with the original `/v1` prefix:

1. Publish the first exact form XML through `POST /projects/:projectId/forms?publish=true`.
2. Create an additional version by posting its exact XML to `/forms/:xmlFormId/draft`, then post to `/draft/publish`.
3. Post exact submission XML to `/forms/:xmlFormId/submissions`.
4. Put the edited XML to `/forms/:xmlFormId/submissions/:rootInstanceId`. Its `deprecatedID` must identify the current original version.
5. Post the decoded exact attachment bytes to that original submission’s `/attachments/:name`, using the retained content type.

All these REST operations return HTTP 200 in the released source. The alternate OpenRosa multipart submission endpoint returns 201; the constant does not interchange those envelopes. A blank published form version uses the reserved `___` token only in its version retrieval route.

The driver must retain its exact request and reconcile uncertain results by reading the same original form/version/submission/media. REST submission creation is not a generic idempotency service. Do not repeat a creation under another identity because a response was lost.

## Original receiving assertions

`scope.pageSize` is 2. `expectedTables[]` binds form ID, native table, exact row count and minimum page count. The child and toy tables retain the native parent-key names. No repeat key is synthesized by this module.

Bind `expectedTables` to the actual project and pass those selectors to the original `receive.mjs` specification. `dataset` supplies the original `simple/Submissions` selector and the native dataset export configuration. The selected CSV fields are `__id`, `name` and `age`; complete native source retention remains the workspace’s existing behavior.

The set contains five current submissions, six submission versions, four published form versions and two attachment bodies. These numbers are source expectations. The original receiving operation must establish the actual returned table pages, native identities and parent references, original version/XML/media bytes, dataset/report output, archive restore and cold reopen. It must retain its actual provider and workspace receipts before describing the run as complete.
