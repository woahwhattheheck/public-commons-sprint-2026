# Receiving the retained OpenCage workshare

The original provider, merchant workspace, and Buyer have distinct operation histories. These entry points join those histories using the native request, terminal result, and selected artifact manifest. They reopen the saved source response, candidate decision, and staged merchant release.

## Source selection

The receiving selection is the complete 439-file merchant/OpenCage/MCP closure at `5e323e89a92b8859eb851205d69c6cc420ff7020`, with the published OpenCage browser release-selection correction from `f2d1e326f2c7f60db77e5ea264c235590af84daf`. Its retained source manifest SHA256 is `be4e5afaf63ca73f8285b439abf3c42be0e81cdafd9a4223b2b6f7122826b290`.

The product branch also composes the later main merchant MCP configuration, source tools, and distribution mappings. That source composition and the frozen receiving closure are recorded separately.

## Retained merchant and Buyer completion

`complete-workshare.mjs` accepts the original provider record, its installed receiving source, browser runtime, and the original Buyer and PTY entry points. It verifies the original response and HTTP observation against the provider's selected artifacts. It reopens the saved workspace and its staged `geocode-v1`, reviews and starts it, changes the atomic price, starts the reviewed release, and rolls back through the original SF82 lifecycle.

The original Buyer script uses the actual response at this immutable HTTPS resource:

https://raw.githubusercontent.com/woahwhattheheck/public-commons-sprint-2026/f2d1e326f2c7f60db77e5ea264c235590af84daf/stellar/scf-starforge-20261009/sf30-seller-sdk/opencage/fixtures/native-reverse.json

The response is 2,785 bytes with SHA256 `94831ba4c34acf608585d242baa998c4ee58a190bf1e4ed3040897800f5797dd`. It was returned by the official OpenCage test-key contract. The original SF88 initializer creates the private operator configuration, policy, ledger, and keys. The original Node Buyer reviews, executes, reads, and recovers the same intent under its controlling PTY. The fixed resource returns HTTP 200; the merchant's separately reviewed testnet payment challenge retains its own terms and release history.

Run this entry point through the existing native foreground launcher with declared memory, output capacity, runtime paths, and its exact argv. Preserve the original provider request and result. The driver writes a complete report only after both the retained merchant lifecycle and original Buyer recovery finish.

## MCP receiving

`run-mcp-receiving.mjs` requires both `--producer-record` and `--continuation-record`. The first supplies the provider's response, observation, and source-workspace history. The second must contain the successful retained completion, joined provider hashes, Buyer report, and release stages.

The MCP entry point reopens the same operator workspace, imports the original observation, reviews and saves a response-bound candidate decision, exports the full customer bundle, and receives every original manifest file through SHA256-pinned chunks. It demonstrates offset resume, original Buyer recovery and package adoption, shared browser state, exact price change, restart and rollback, and credential-independent workspace reopen.

Both entry points retain their source manifest and the original request/result/artifact hashes in `journey.json`. Their output directory belongs to the declared native project. Use the terminal native artifact manifest to select completed delivery files.
