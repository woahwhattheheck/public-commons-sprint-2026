# Preservation transfer inspection desk

The Delivery tab opens a complete supported BagIt ZIP, verifies its original profile and manifests, and exposes every recorded metadata and file-selection row. An ordered comparison presents each original identifier or path with its complete previous and current values. The research and original-file collection profiles use their existing verification and comparison engines.

This desk supports two concrete package profiles: the research preservation profile generated by preservation.py and the original-file accession profile generated by collection_accession.py. A generic third-party BagIt archive or a provider export with a different profile is rejected visibly. Verification establishes consistency of the selected package and its recorded review; it does not establish repository acceptance, a preservation action, permission, a contract or payment.

## Select and inspect original packages

Open the existing Workbench and choose **Delivery**. Under **Inspect and compare preservation transfers**, the first selection is the package for inspection and the previous edition for comparison.

Choose **Saved delivery package** to reuse an original Workbench artifact. Its retained path, full byte count and SHA-256 are checked before use. The desk does not copy that archive again. Choose **Original ZIP on this host** to enter the complete path to an incoming regular ZIP. The application retains its exact bytes once under its SHA-256 in the existing operator directory. It checks the original selection again while copying and verifies the retained copy through the original profile engine.

**Inspect selected package** creates a retained Activity operation. The report contains all original mapping rows, inclusion decisions and the complete verification receipt. An invalid profile or checksum leaves an explicit failed Activity operation. A retained incoming original remains available for investigation; failure does not create a successful report.

For comparison, select the previous edition on the left and the current edition on the right, then choose **Compare complete editions**. Both packages must use the same supported profile. The original engine determines changes, and the desk joins all unchanged rows as well. A missing source row is an observed difference. It does not authorize deletion of an existing preserved object.

## Read the whole result

**Retained complete reports** contains successful inspections and ordered comparisons. Selecting a report clears the previous report while the chosen source loads. A failed read identifies that selected report and leaves its old rows and downloads unavailable. If an operation completes while you are reading another report, changing a filter or opening a row, the application retains your chosen view and announces the newly available report.

The browser displays 50 complete rows per page. Search checks all full values, including the complete before/after pair; it is not limited to a shortened display label. **Changed rows only** filters comparisons. **Open full original values** presents the entire recorded row or full previous/current pair. Row values and downloadable reports are not shortened.

Package identities include the original artifact ID, path, filename, bytes and SHA-256. Inspection preserves the original verification receipt. Comparison preserves the full original comparison result as well as the complete row list. Keep the selected order with any exported findings.

## Downloads and receiving

Every successful report has three full downloads:

| File | Contents |
| --- | --- |
| JSON | Complete package identities, original verification or comparison result, summaries and every row |
| HTML | Readable complete selection and all full row values; opens independently |
| CSV | Every original identifier/path, selection or change labels and full original/before/after JSON |

The review CSV escapes spreadsheet formula prefixes in human-facing cells. It is a readable review export. The original import-ready package metadata remains byte-exact inside the original ZIP. Use **Download original ZIP**, or the separately labelled previous/current links, when transferring the original packages.

**Export complete editable workspace** includes the original application source, operator history, all retained transfer reports, original selected ZIPs and any research/accession workspace already present. An incoming-package-only workspace can be exported after a successful inspection, even when it has no research collection. Existing accession-only exports remain supported. The manifest's historical collectionOnly flag represents the absence of a research root; transferReports and collectionBindings describe the actual retained content.

The receiver validates every archive descriptor and checksum, binds each report to its exact original package members, and requires the complete installed transfer-desk source group. Received report and package downloads use the same artifact identities. Reopening the same complete archive validates its immutable report/source/application members again. Existing received local work is not replaced by another handoff.

For a receiving copy:

~~~sh
python3 research/preservation/workbench.py receive \
  --source /absolute/private/complete-workspace.zip \
  --output /absolute/private/received
python3 /absolute/private/received/application/research/preservation/workbench.py serve \
  --workspace /absolute/private/received/workspace --port 0
~~~

Keep the full receiving directory, its application and workspace.operator together. Open the emitted local URL and choose Delivery. Source revisions, provider operations and accession metadata remain governed by their existing application controls.

## CLI inspection

Run from the actual buyer SDK directory:

~~~sh
node research/preservation/cli.mjs transfers inspect \
  --source /absolute/private/current-transfer.zip

node research/preservation/cli.mjs transfers compare \
  --previous /absolute/private/previous-transfer.zip \
  --current /absolute/private/current-transfer.zip
~~~

The corresponding native entry is transfer_inspection.py with the same subcommands and flags. CLI output is the complete JSON report on stdout. It does not create or modify a Workbench. The selected regular files are hashed before and after observation; changed source bytes are rejected.

Limits are inherited from the original profiles: a complete package is at most 2 GiB, with the original profile's per-member checks. Complete JSON, HTML and CSV report outputs must each fit 64 MiB. The application refuses an unsupported complete report; it never truncates rows to make one fit. Complete workspace archive limits and path rules remain those in WORKBENCH.md.

## Original-case native continuation

The optional manual programme uses the original accepted research or accession Workbench and two existing complete package editions. It does not build a replacement collection or run a provider action. Stop its original local server so the maintained Workbench lock can be acquired. Preserve the existing operation directory and all earlier results.

~~~sh
python3 research/preservation/receiving/transfer_inspection_receive.py \
  --application /absolute/installed/buyer-sdk \
  --workspace /absolute/original/workspace \
  --previous /absolute/original/previous-transfer.zip \
  --current /absolute/original/current-transfer.zip \
  --operation /absolute/original/receiving-operation
~~~

The programme stores its fixed selection, full producing code, package identities, original source/review observations and phase journal under transfer-inspection inside that same operation. It holds an inherited kernel case guard. It uses original queued Workbench jobs, reuses completed matching jobs and preserves failed/interrupted predecessor jobs before continuing the same request. It compares the complete reports against the original profile engines, checks that original source/review history is unchanged, retains full JSON/HTML/CSV, and publishes a complete editable workspace archive.

The complete export is checkpointed before independent receiving. The copied application then verifies the original package in a separate native Python process. Full first-copy member identities and original source/code identities are checked. Reentry reuses the fixed archive and receiving receipt; it permits only the original local job/artifact bookkeeping to have advanced after an earlier completed course. A changed original input, selected source cohort or saved review fails visibly and preserves the current operation.

An interrupted programme must resume with the same paths and selected source bytes. A later deliberately changed application or workspace needs an explicitly selected continuation, not an overwrite of the original selection.json. This course is manual source, outside default tests and hosted CI.

## Original-case browser and rendered inspection

After native COMPLETE, run the separate browser suffix using the same original operation. Use already installed Python, Chromium and Playwright; the programme installs none of them.

~~~sh
node research/preservation/receiving/transfer_inspection_browser.mjs \
  --application /absolute/installed/buyer-sdk \
  --operation /absolute/original/receiving-operation \
  --browser /absolute/existing/chromium \
  --playwright-module /absolute/existing/playwright/index.mjs \
  --python /absolute/existing/python3
~~~

This suffix verifies every installed source member against the native course's complete producing-source manifest before opening the original retained workspace, and checks the same identities again before completion. It retains those source identities in its own fixed selection. It deliberately operates the browser's inspection and comparison controls with the native course's exact persisted artifact-or-path selections. Incoming path selections keep their original filename identity; they are not silently converted into selections of the digest-named retained copy. Its two UI jobs are derivative report operations; they do not repeat source receiving or change review decisions. The reports must equal the already verified originals exactly. Each UI request records its preceding job identities before the click, and each completed result/download is retained. An uncertain or failed original job stays explicit rather than being silently submitted again.

The programme visits every report page through the actual API, opens a complete row in the UI, uses the comparison filter, downloads all three full reports, opens the actual downloaded HTML at desktop and 390-pixel widths, exports the complete editable workspace, receives it through the original native receiver, reopens the copied application and downloads the exact original reports and ZIPs again.

All output is retained under transfer-inspection/browser. Attempts have unique directories. Ten desktop/narrow screenshots are evidence for the producer's rendered inspection; the automated result explicitly remains PENDING_PRODUCER_LOOK. The producer must open and inspect every outgoing screenshot and the downloaded complete HTML, JSON, CSV, original ZIPs and received application. Check visible labels, important controls, populated and empty views, loading and source-specific error states, normal narrow-screen use and the full download/reopen journey. Record actual observed defects and corrections. Source review or a screenshot file that has not been viewed is not rendered acceptance.
