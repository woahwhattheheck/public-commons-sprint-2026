# Native receiving: saved Analysis export to dataset publication

This programme operates the complete Dataset publication product using an existing, completed Analysis query export. It retains the selected export, recipe, local job IDs, original Frictionless operation IDs, publisher candidate and review, complete file indexes, and original archive/restore receipts.

## Original input and scope

The selected input is the original complete Analysis workspace archive (SHA-256 `4daa8c2c28cfe14263a69c32cb0e3733e043d223a320fdf83cc7daef51f7d0e3`). The original export is `96fc26d02bd44f2197afdea394b4b6a1`, manifest `266d598d6fe9dea6fed8d0867468587a7b0a0f139707615c9c705934f56a392e`. It contains three full rows, with `event_index`, `domain`, `title`, and `bot` columns. Its earlier saved SQL preview contains one row and is marked truncated. The programme reads the full retained export; it does not execute another query, import, acquisition, or model.

The operator chooses integer, text, text, and boolean01 representations for those columns. The public ZIP contains the reviewed descriptor and JSON resource. The private recipe, source rights, original SQL/source/version binding, typed export identity, validation report, native decisions, and complete original source export remain separate retained files. No new public redistribution license is inferred.

The external JSON resource uses general Data Package/Data Resource profiles and an explicit Table Schema. The Frictionless v1 Tabular Data Resource profile restricts external resources to CSV, so that profile is not applied to this JSON resource. The original Frictionless source parser and publisher remain the runtime authority.

## Receiving sequence

1. Open the actual Dataset browser pane and select the completed export. Save the exact recipe before building the package. The programme captures one actual accepted package reply, retains it, then discards only its delivery to the browser. The same saved request reopens the original job.
2. Initialize the maintained publisher in a private unpublished stage using the exact package bytes. An interrupted empty initialization is retained under its original locks before the native initializer is continued. Existing publisher actions are never discarded or reset.
3. Start the original authenticated Merchant MCP host and configured Frictionless workbench. The Analysis interface selects the declared alias; credentials and filesystem input paths remain host-side.
4. Use the original capture, edition, review, source selection, plan and extraction operations. Each native ID comes from the actual retained response. A complete candidate is reviewed against the original empty target and published by the original publisher.
5. Capture one actual successful native PUBLISHED response before discarding its network delivery. The bridge then reconciles the same run/review against the retained native result. An accepted local Analysis job is distinct from an asynchronous native workbench operation; the programme reads the original native request to completion.
6. Export the original Frictionless source edition and receive its complete original files. Download all six package files and the complete source file set through the browser, Python streaming interface and native MCP.
7. Interrupt one actual durable MCP byte prefix, restart only the owned MCP listener, and continue the same directory/index/job. Verify every completed file offline.
8. Create the original full Analysis workspace archive, close the source host, restore to the original absent cold destination, and replay the same restore operation. Reopen the Dataset browser and MCP files without a merchant connection. Compare all original package/source bytes and protected Analysis data.

Desktop and 390-pixel browser checks use the actual rendered product. Screenshots are retained only as the authorized receiving evidence. They are not a substitute for the native job, file or restore receipts.

## Interruption and ownership

`operation.json` holds the immutable selected source/runtime/input request and original restore/archive IDs. Browser journals persist exact request bodies before POST; complete local steps validate their original configuration and saved artifact hashes before reuse. The Python owner flock remains inherited by the browser and original Analysis child. An interrupted transport does not prove the application stopped: reconcile the same saved operation and owned process before invoking the command again.

A new observed native workbench interruption gets an explicit local resume decision tied to that original operation's retained updatedAt/stage/error. The native operation ID remains unchanged. A completed publisher candidate can be recovered by its original run ID. An incomplete native extraction requiring operator review remains visibly unresolved; the programme does not invent a replacement run or silently publish another candidate.

The bridge's confirmed-unsent result and uncertain-dispatch result remain separate. A lost or malformed successful response does not prove rejection. Original publisher review/publication is reconciled before any potentially duplicated write.

## Complete artifacts

The private receiving directory retains the whole operation and source selection, three browser phase configurations/results/journals, original accepted response captures, original native IDs, all downloaded package/source files, full Analysis archive and manifest, exact restore receipts, Python delivery receipts, MCP prefix/resume receipts and offline verification, and a final `result.json`.

A result is COMPLETE only after the actual native publication, full downloads and cold restore. A syntax check, source bundle, accepted queued request or partial browser step is reported with its actual state.

For the public maintained code, use the cumulative Dataset source contribution and original standalone build. Save customer/private receiving data through its ordinary artifact route; no API token or private workspace journal belongs in the public repository.
