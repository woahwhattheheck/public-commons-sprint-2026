# Protocol and methods in the installed Research workspace

The **Protocol and methods** control opens the complete registered NCT03529110 capture beside an existing dossier and question. It displays the original PDF, complete extracted pages, page-linked methods and the original SourceBundle preview. The browser and terminal retain a complete request before the existing Research source operation saves it.

This addition uses the original registered-protocol capture, methods map, SourceBundle importer, revision store and portable receiver. The existing study-extraction owner continues the same workspace and operation. The installed capture and complete handover commands remain **research-study-protocol**; the complementary **research-protocol-review** command prepares, inspects, receives and reconciles the exact browser-compatible request.

## Browser recovery and concurrent editing

Before POST, the browser commits a full immutable request to IndexedDB. The request contains the original workspace, dossier, question, bundle bytes/hash, expected revision and complete source text. Its request ID is derived from that exact selection. The browser passes the selected workspace identity on subsequent requests.

| State | Continue from the retained original |
|---|---|
| A source is selected or inspected | Open that saved review, inspect it and preview its question changes. |
| A request is prepared | Review its methods and save that same request. Its question and original source are fixed. |
| The reply was interrupted or the server returned an ambiguous failure | Choose **Read original import state**, then **Recover original import**. The same request and expected revision are retained. |
| The server reports a definite revision or selection conflict | Read the original state. Keep the old request; **Start another review** creates an explicit new preview against the current dossier. |
| Another tab saved this draft | Reopening adopts the matching saved snapshot and storage revision together. A locally unsaved conflicting copy is retained separately and cannot overwrite the other tab’s saved request. |
| Browser storage is unavailable or full | Download every displayed **unsaved review**. Submission waits until the exact request has been retained; the full copies remain in memory across dossier navigation. |
| A saved request came from another workspace or dossier | Open its original attachment, or extract its source bundle and start an explicit new review in the intended workspace. |

**Download complete review** includes the full browser draft and original request. **Download exact request** supplies the same request used by the terminal/client. **Preserve this draft separately** commits a new local draft copy before releasing an unsaved conflicting copy. **Start another review** retains the old request/result and begins a separate explicit preview; it never changes an accepted request in place.

A received result exposes revision-pinned HTML, Markdown and editable-dossier downloads. The original source bundle and each original member remain separately downloadable. The existing Research receiver opens the editable dossier and verifies its full saved history.

## 3. Prepare a complete review at the terminal

Inspect a completed source without contacting a Research listener:

~~~bash
starforge research-protocol-review inspect \
  --source /ABS/original-protocol-capture/source-bundle.json \
  --out /ABS/private-review/source-inspection.json
~~~

Prepare the exact source against the existing question:

~~~bash
starforge research-protocol-review prepare \
  --source /ABS/original-protocol-capture/source-bundle.json \
  --connection /PRIVATE/original-application-url.json \
  --workspace-id research_ACTUAL_WORKSPACE_ID \
  --dossier d_ACTUAL_DOSSIER_ID \
  --question ACTUAL_QUESTION_ID \
  --directory /ABS/private-review
~~~

Replace the identity placeholders with the actual original connection and dossier values. The workspace ID is the original research_ prefix plus 64 hexadecimal characters. A source SHA-256 can also be supplied with --sha256.

The command writes **REVIEW.json** exclusively. This file includes the full request, inspection and original preview; the browser accepts it directly. Repeating prepare with the same directory verifies and reuses that saved request before creating another preview. A different source or question cannot replace it.

For source-checkout operation, run the same arguments through:

~~~bash
node /ABS/selected-source/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/research-dossiers/study-protocol-operator.mjs
~~~

## 4. Receive or reconcile the exact request

A browser’s downloaded original request or complete terminal REVIEW.json can be used here:

~~~bash
starforge research-protocol-review reconcile \
  --review /ABS/private-review/REVIEW.json \
  --connection /PRIVATE/original-application-url.json
~~~

The result distinguishes ALREADY_RECEIVED from NOT_RECEIVED and retains the original expected revision alongside the current original-store preview. It does not submit, change a question or rewrite the request.

After reviewing the original selection:

~~~bash
starforge research-protocol-review receive \
  --review /ABS/private-review/REVIEW.json \
  --connection /PRIVATE/original-application-url.json \
  --directory /ABS/private-review
~~~

The exact review is durable before the original source mutation. **RECEIVED.json** retains the actual native metadata response, selected source edition and original request fingerprint. A repeated completed command verifies the retained source at its saved revision and current original import state, then returns the existing receipt.

If a save succeeded but its reply or local receipt write was interrupted, the same request recovers the existing edition. Keep its original directory and source. An explicit new preview belongs in a separate review directory.

The review directory is private. Immutable files use the original Node store’s exclusive, synchronized publication and are verified on reuse. No listener token or connection-file body is copied into a review.

## Original SDK attachment

The existing ResearchWorkspaceClient exposes studyProtocol(). Its methods are:

| Method | Input and result |
|---|---|
| inspectBytes(bytes) | Read-only complete original bundle inspection |
| inspectFile({file, sha256}) | Read and verify a regular original source file |
| inspectCapture(directory) | Original completed capture inspection plus protocol methods inspection |
| capture(input) | The existing captureStudyProtocol operation after attachment identity validation |
| prepare({dossierId, questionId, bytes}) | Original inspection, native preview and immutable request |
| prepareFile({file, sha256, dossierId, questionId}) | Same operation with a complete original host file |
| reconcile(request) | Read the original bundle/question state without mutation |
| receive(request) | Receive the exact validated prepared request through the original SourceBundle API |
| receiveCapture(input) | Run the existing complete protocol receiving/export operation on this same attachment |

These methods use the parent client’s existing request tracking and identity checks. Await the selected operation, then close the client so its outstanding work drains. They borrow the original listener; closing the attachment does not stop that listener.

The installed module exports are:

- ./buyer/research-dossiers/study-protocol/client
- ./buyer/research-dossiers/study-protocol/inspection
- ./buyer/research-dossiers/study-protocol/operator

The existing source, methods, receiving and capture CLI exports remain available. For example, from an installed SDK root:

~~~javascript
import {readFile} from 'node:fs/promises';
import {ResearchWorkspaceClient} from './source/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/research-dossiers/workspace-client.mjs';

const saved = JSON.parse(await readFile('/ABS/private-review/REVIEW.json', 'utf8'));
const client = ResearchWorkspaceClient.fromFile('/PRIVATE/original-application-url.json', {
  expectedWorkspaceId: saved.request.workspaceId
});
try {
  const protocol = client.studyProtocol();
  const state = await protocol.reconcile(saved.request);
  console.log(state);
  // After the original operator has reviewed this exact saved request:
  const received = await protocol.receive(saved.request);
  console.log({dossierId: received.id, revision: received.revision});
} finally {
  await client.close();
}
~~~

The terminal command is the complete local receipt-producing interface. Direct SDK callers retain their actual response in their own original operation’s journal.
