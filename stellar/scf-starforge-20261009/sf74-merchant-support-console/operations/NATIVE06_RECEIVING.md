## Actual case flow

The programme restores the original full TAR into a separate sender pricing directory. It opens the original SF97 workspace and planning APIs, selects the same saved plan and pricing version, and obtains the original five-file quotation source with a newly retained full WORKSPACE_BACKUP. The cost origin must still identify the original edition and supplier source bytes.

A matching Merchant Support case is created with explicit source, scope and receiving responsibilities. It has three operator-created tasks: preserve the selected source and quotation; receive the complete case/source history; and restore the original pricing/cost workspace independently. The case does not acquire an unrelated diagnostic report or workorder merely to satisfy a schema.

The original commercial APIs attach the selected pricing source and full backup under their separate retained request UUIDs. The quotation draft uses the original selected route IDs, monthly request quantities and USD valuations. It adds explicit internal deliverables and acceptance terms, without inventing implementation fees, service fees or an external agreement.

The original local quotation page performs preview and edition publication. The programme captures the browser's exact publication request before it is sent, retains the resulting quotation ID and digest, and records the actual desktop and 390-pixel views. Page errors, external requests and whole-page overflow are checked in that same operation. The original browser and server close before the complete case is packaged.

The original complete package engine exports the exact sender revision, all selected source files and full retained case history. Its receiver opens a separate case/source store. The commercial receiving adapter pins the original quotation and backup to the imported revision, preserving their sender identity.

Independent pricing restoration reads the retained original backup from that received case. The existing SF97/cost engines reopen the same plan, scenario, pricing version and cost edition; every retained supplier source is checked by its original byte count and digest.

The programme records those actual technical results against the selected operator tasks and original materials. Null workorder receiving is permitted only when every selected task is itself operator-created with editionId:null. Existing non-null workorder checks and original task/material/plan subject hashes remain unchanged. Technical acceptance here does not create a commercial customer response.

Finally, the receiver continues the case with a saved local edit and replays the original complete-package receiving request. The replay must preserve the receiver's newer revision, the original imported revision, the exact quotation and the unchanged customer-response history. A complete receiver package is then exported with that actual technical receiving and continued case state.

## Interruption and reopening

The programme retains source selection and request identity before each original mutation. It uses the existing native case, pricing, backup and package recovery paths. Repeated calls do not mint replacement quotation or receiving UUIDs.

If the browser publish response is lost, its original captured request is reused and the saved quotation is reconciled before another click. Once the browser phase is complete, its original two screenshot digests are verified and the phase is not rerun.

Once RESULT.json exists, the programme verifies the original completed selection and completes or reopens the full archive. It does not rebuild a new completion timestamp or replay the whole case. A complete staging ZIP can be published after an interrupted atomic handoff. Incomplete staging files remain retained while a new staging archive is written; an existing final archive is never overwritten with different bytes.

The whole ZIP contains an OPERATING-FILES.json inventory. Reopening checks its exact member set, lengths and streamed digests, including the complete result. If publication completed but its small archive receipt was not saved, the receipt is recovered from the verified exact archive. Later output receipt metadata is excluded from the original package file set.

A failure returns INCOMPLETE with the actual code and message. Preserve that output and stopped workspace. It is not a successful receiving result, and it does not justify creating a competing native job.
