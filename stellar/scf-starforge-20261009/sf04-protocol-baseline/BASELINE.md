## Practical delivery order for build seats

1. **Foundation contract lock**: pin the exact upstream x402 tag/commit, package tarball integrity and compatible license set; run the actual unmodified canonical client against the real `exact` service on testnet and, only once separately authorized/funded, mainnet. Track both `payload.transaction` and `/supported` `areFeesSponsored`, return every rejection reason. Record original tx receipts; this document provides **no** receipts.
2. **Bazaar is the primary original product**: implement automatic cataloging on verified payment payloads, HTTP+MCP resource keys, `routeTemplate` percent-decoding traversal defense, seller-proof/prevention of client-side forged metadata, lifecycle index, pagination, realistic natural-language ranking, query error codes. Treat spec churn as a versioned compatibility surface.
3. **Add `upto` as a separate security-reviewed branch of work**, not a renamed `exact`: single settlement, cryptographic recipient binding, usage cap, expiry, and safe ledger model. Contribute `scheme_upto_stellar.md` upstream through appropriate process with team/owner authorization; independently audit any Soroban contract.
4. **MCP interop**: deterministic discover→paid-call→retry through canonical protocol shapes, two production-ready integration examples, operator runbook, Prometheus/logging/alerting and service budgets. Do not rebuild generic SDK transport already provided in Apache-2.0 libraries.
5. **Acceptance requires real conformance**: source correctness is not an end-to-end pass. The [SCF RFP §3.6 and §5](https://stellar.gitbook.io/scf-handbook/scf-awards/build-award/rfp-track) demands both networks, canonical client, e2e suite, real settled tx hashes per network/scheme, full audit and 99% service target. Run those only in an approved actual environment with real permissible data/network resources and the owner’s focused-validation policy. No grant submission is made by this research.

## Boundary conditions for a competitive grant

- **SCF #46 eligibility**: the x402 RFP is listed under Q3/#45 in the official handbook; a separate SF-01 lane determines #46 applicability. This is *not* a claim that any #46 application is eligible. Owner has held submission/contact.
- **Version drift**: SDF sample service declares `@x402/stellar ^2.23.0`, whereas current Foundation monorepo manifest declares `2.28.0`. Re-resolve actual installed lockfile and test compatibility when integrating; do not claim either works with the other without execution.
- **Licensing**: Foundation and SDF repos are Apache-2.0. Exclude AGPL relayer codebase, plugin and SDK entirely from dependencies; check every *new* package transitive license and permission before public distribution.
- **Proof class**: source-exact GitHub blobs and directory enumerations are real first-party technical evidence. No browser-hosted settlement, provider uptime, fees paid, audit acceptance, scheme conformance or SCF award result was produced here.

## Machine-readable handoff

`inventory.json` contains exact repository commit SHA, source blob SHA, implementation-vs-spec decisions, known missing functionality and excluded dependency notes. `check.mjs` performs one tiny offline structural sanity check with Node 22 (no network calls, no GitHub Actions):

```sh
node check.mjs
```

Any new upstream commit, RFP update or published package release should create a new dated inventory rather than silently overwriting the pinned record. The SCF engineering wave may consume it to avoid duplicate settlement implementations and to route original work to the Bazaar, Stellar `upto`, MCP and actual acceptance owners.
