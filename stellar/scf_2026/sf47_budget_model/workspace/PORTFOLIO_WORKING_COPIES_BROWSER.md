This public edition joins them to the existing public Portfolio calculator, owner-key authentication and recording-operator workflow. Merchant-only staff sessions, currency controls and Installation-phase inputs are not prerequisites for this edition.

## Recovery and output identity

Outputs remain in the supplied directory:

- `browser-portfolio-progress.json` and `browser-portfolio-result.json`.
- `browser-portfolio-cold-progress.json` and `browser-portfolio-cold-result.json`.
- `browser-portfolio/` and `browser-portfolio-cold/`, containing images and exports.
- The original parent's durable browser profile, retained by that parent.

Each phase stores its start before invoking the existing course action and its completed result afterward. Progress uses a fully written/fsynced stage, atomic rename and directory fsync. Completed phases are reused. Once every original phase/export is recorded, final publication is artifact-only: it reconstructs the same result from those immutable phase receipts, preserves the final phase's completion time, and does not rerun the browser course. The complete result is staged and fsynced, published without replacement as a retained completion file, then linked without replacement to the final result and followed by directory fsync. A completed result is reopened without timestamp rewriting; all its export byte counts/hashes and original saved Portfolio hash must still match. Do not delete the progress, exact request files, source pins or browser profile to work around an interruption.

The controlled save writes `original-portfolio-save-request.json` before dispatch and retains the full native response separately. A true rejection remains a rejection. An accepted request with interrupted delivery is retried under the same request ID and original version, preserving the native writer's replay contract. No replacement case or fresh command is invented.

A same-directory invocation is owned by its existing parent; this supplied-page library is not a cross-process scheduler or lock service. Keep the original parent's exclusive execution and reconcile its uncertain result before invoking another process.

The full working-copy export limit is128MiB including its JSON envelope, head, checkpoints and recursive lineage. Source bytes are verified against their original metadata. A storage conflict or quota error does not block exporting the current in-memory copy. Complete source downloads do not create native records.
