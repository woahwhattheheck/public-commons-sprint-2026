# Flowable programmes in the original Source Desk

The Flowable tab joins a complete exported Flowable workspace and a selected programme edition to the customer's existing SF47 Workshare and Installation. It uses the original source service, browser working-copy journal, case Preview and Installation Save. Preparing this source does not dispatch a process, case, decision, payment or acceptance action.

## Open the customer's actual operating case

Open Customer installations in the current SF47 operating case, then its existing Source Desk. Create or open the original source preparation and choose **Flowable programmes**. Keep the real source preparation, its complete Workshare and current plan. The Flowable fields belong to that same case and saved browser working copy.

An original attached Workshare can supply the current native seed and complete commissioning source. Alternatively, open their complete original JSON files in the Flowable tab. The seed must identify this actual operating case and current source version. The service checks the original Workshare rather than accepting a manually relabelled foreign seed.

Each browser window owns a separate working copy. The original Source Desk controls download the complete working state, reopen a saved local copy, import a complete working JSON file or fork another local copy. This includes unfinished Flowable JSON, exact request UUIDs, selected file identities, complete current source/receipts, bindings and original pending requests. Local storage conflicts preserve both copies. Full large original files remain in the source service; a working-copy JSON is not the source archive or the finished customer handover.

## 1. Retain the complete workspace

Choose the original flowable-workspace.ndjson exported by the maintained Flowable workspace. The desk reads the complete file in chunks to calculate its whole-byte SHA-256, freezes its name/length/hash and request UUID in the original browser journal, then uploads the whole file through the current authenticated staff session.

The whole archive is limited to 256 MiB and is retained as a mandatory source sidecar. It is not squeezed into the generic 8 MiB source-file or 24 MiB case-attachment limits. Keep the actual original file available until the upload is recorded. After a browser reload during an unfinished upload, select that same file and use **Retry exact saved request**; name, bytes and hash must match. A renewed upload URL or another file does not replace the original intent.

Choose **Read complete programme catalogue**. The original Flowable receiver inspects and adopts the unchanged archive in an owned temporary workspace, lists all retained programme record editions and closes its receiver. It does not connect to or dispatch an engine.

Select one actual retained programme edition from the catalogue, then choose **Inspect selected programme and original outcomes**. The programme ID, saved revision, original programme-source SHA-256 and native progress basis come from the complete catalogue. They do not need to be retyped.

The three identities mean different things:

| Identity | What it identifies |
| --- | --- |
| Saved programme record SHA-256 | The immutable saved programme record at its exact revision |
| Programme-source SHA-256 | The original complete programme JSON bytes |
| Native basis SHA-256 | The selected operation/result projection retained in that archive |

The archive's whole-byte SHA and its native body SHA are also distinct. The source service and complete receiver retain both.

Read the displayed complete step table. Unprepared, prepared, unknown, rejected or confirmed native work remains in its original observed state. Expand the full selected source report and download original model/input/source files, saved operation records and available reviews. Source inspection does not promote an unresolved operation to success.

## Reopen and recover

**Refresh saved requests** and **Load next saved requests** read complete request pages. Enter an original UUID and choose **Open saved result** to reopen its actual retained preparation. Original seed, binding and commissioning text are downloaded and verified from the saved result before being restored. Prepared source and every sidecar remain tied to their original request.

Before replacing edited working fields with an older saved result, the desk parks the complete previous working copy through its existing journal. The working fields are editable copies of the original source; they do not change the retained preparation.

| Observed outcome | Operator continuation |
| --- | --- |
| Request is complete | Open its original result and verified files |
| Request is pending or reply was interrupted | Read the original UUID, then retry that exact saved request |
| Request is not yet recorded | Preserve the same UUID and full input; retry the original intent |
| Upload interrupted before completion | Reselect the same complete file; length, name and hash must match |
| Explicit input/version rejection | Keep the complete rejected request, then explicitly edit inputs for a new preparation |
| Case changed after preparation/preview | Keep the old preparation; read a fresh original seed and prepare a reviewed successor |
| Original native Installation save uncertain | Use the original Installation writer's saved request, not a new Source Desk preparation |
| Browser working-copy conflict | Keep/download both complete copies and explicitly fork or reopen |

An explicit rejected source request remains in the original history even after **Keep rejected preparation and edit new inputs**. Network failure or unknown response does not enable that correction path: first read or retry the retained request. No browser preparation recovery replays a native Flowable engine operation.

## Original application and API composition

The new operations_flowable_sources.mjs module is mounted by the existing operations_installation_sources.mjs; it stores state.flowableWork in the existing Source Desk working copy. It has no second browser datastore. operations_flowable_sources.css limits its neutral styles to the new Flowable course.

| Route | Complete operation |
