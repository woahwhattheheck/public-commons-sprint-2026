# Portfolio working copies

The Portfolio desk keeps complete named working copies beside its existing saved allocations. Use a copy for an unfinished resource plan, a different staffing assumption or a retained decision checkpoint. The original Portfolio preview and save remain the only allocation calculation and native writer.

A working copy contains the current base plan and alternatives; the selected input and result alternative; the original saved Forecast; complete saved or previewed results when still applicable; exact partly typed controls; unfinished capacity forms; and any original pending save request. Checkpoints retain the whole session at that moment. A later edit changes the head, not a prior checkpoint.

## Start and continue a copy

1. Open the original operating case and **Portfolio delivery allocation**. The named-copy section opens the retained selection for this local operating case and browser origin.
2. Use the existing **Create plan from this forecast** or **Saved allocations** controls. The same original Forecast and allocation IDs are retained.
3. Enter the resource calendar, daily capacity, dependencies and assumptions. Changes are retained in IndexedDB under this browser origin and the exact local operating-case namespace.
4. Enter a useful copy name and use **Rename copy**. **New copy from this draft** creates a separate local identity with complete source-copy lineage.
5. Use **Save complete checkpoint** at a decision boundary. Give it a note explaining the source or assumption selected. Checkpoints keep complete original source bytes.
6. Select a retained checkpoint and choose **Open checkpoint as another copy**. The original head and checkpoint stay intact; the new copy is independently editable.

Checkpoint choices include the original copy name, checkpoint note and time. Imported and forked copies retain earlier copy histories in their lineage, and those retained checkpoints remain selectable. Merely opening, naming, importing, checkpointing or archiving a working copy changes no native case record.

**Archive copy** retains its entire head and history. Choose an archived copy and **Restore selected copy** to continue it. Archiving selects the next active copy, if any; the editor adopts that copy's own state.

## Unfinished inputs are real working state

Numeric and date controls retain exact text. A partly entered number such as a minus sign or an unfinished date stays visible across the copy's export and reopening. Empty capacity remains unentered; an explicit 0 remains zero. The original native validator decides whether a completed allocation can be calculated.

An unfinished numeric value in any alternative prevents preview until it is completed. The retained raw control and its normalized draft value are checked together; a received working file cannot show one value while submitting another.

**Distribute a weekly total** and **Dated resource capacity** retain their unfinished fields by original resource ID and alternative. Closing the dialog retains its draft. Use **Resume unfinished capacity form**, or open the same resource control again, to continue. **Apply to this draft** uses the original exact distribution or dated-capacity operation and then clears that form's completed draft.

Removing a resource or alternative clears only the controls and forms that refer to that removed item. Other unfinished forms and assumptions remain. Starting a revised allocation from a saved result starts its matching editable form state while preserving the immutable original result.

## Preview and save through the original case

Use **Preview allocation and cash** to invoke the maintained Portfolio calculator against the current original case version. Review its delivery and cash alternatives and all incomplete-input findings. **Save reviewed allocation** retains the exact original request ID, expected case version, actor, complete inputs and preview digest before sending the original command.

If a response is interrupted, **Retry the same save request** sends that retained body unchanged. The native writer returns its original receipt if it already completed. A source or version rejection is kept with its exact request; **Keep draft and prepare a new request** is the explicit original path for a reviewed successor. It does not silently reuse another case version.

Working-copy storage must succeed before a new native save is sent. A failed storage write leaves the exact request in memory for recovery. Source copying and local checkpoints do not create new Forecasts, sources, invoices or case records.

A recovered preview remains tied to its original inputs and source. The current case may have advanced elsewhere. Preview again before preparing a new request; a retained pending request always keeps its original version and identity.

## Download and receive the whole working copy

**Download complete working copy** writes one JSON file containing the exact current in-memory head, every checkpoint and the complete recursive source-copy lineage. It retrieves any missing attachment bytes through the original authenticated source download, verifies each original byte count and SHA-256, and retains original metadata. The frozen Forecast, native preview or saved result and unresolved request stay in that same file.

This recovery download does not depend on a successful storage write. It remains usable after a conflicting-window revision or storage quota error. The outgoing head is the current editor state; the stored collection is not overwritten.

**Receive complete working copy** validates all sessions and every source attachment in the head, checkpoints and recursive lineage before changing the selected copy. The received copy gets a new local working-copy ID and preserves the entire incoming copy as lineage. Existing local copies are retained.

Working-copy receiving is for the same original local operating case. It can continue in another browser that can access that case. The current public host uses its original owner access key and recording-operator field, rather than the newer Merchant staff-session module. All authenticated native requests keep that host's original authorization and exact retained actor. Use the original full native-case export/import to transfer immutable case records into a distinct receiving workspace; that operation deliberately creates its own local case identity. This feature does not rebind an unresolved command to another case.

The source collection is limited to 64 MiB of decoded attachment bytes per session, and complete working files to 128 MiB. Full source histories can be large. Keep meaningful named copies and checkpoints rather than creating a new checkpoint on each keystroke. Normal autosave updates only the current head.

The existing **Download draft**, **Import plan JSON**, **Download retained request**, saved Portfolio ZIP and complete native-case export remain available. Their original formats are unchanged. Use the complete working-copy file when unfinished controls, source bytes and request continuation must travel together.

## Concurrent windows and recovery

The store uses a namespace-wide revision check. A window with an older revision cannot overwrite work saved by another window. After a conflict:

1. Download the complete current working copy to retain this window's head.
2. Choose **Reload stored copies** to open the latest collection.
3. Receive the downloaded copy as a separate local identity when both alternatives are useful.
4. Review the original native case before continuing a pending command.

The storage transaction includes copy metadata, head, selected copy, checkpoint and lineage records together. Autosaving a head does not rewrite all prior large checkpoint and lineage records. Storage failure leaves the previous committed collection and the current in-memory session intact.

An unreadable previous store is preserved. **Download retained store recovery** exposes its complete original stored records for repair. It is not silently replaced by an empty session. A previous legacy browser-session draft is retained as exact text; **Receive previous session draft** explicitly imports it into a new named copy. The old session record remains unchanged.

## Maintained source and API

The module `portfolio-working-copies.mjs` validates complete sessions, source bytes and raw controls. `portfolio-working-copy-store.mjs` owns the local IndexedDB collection and atomic revision checks. The original `portfolio.mjs` composes these with its existing allocator preview, source download and save command; `portfolio.css` keeps the industrial layout. `operations_http.py` serves the two scripts and this guide. The selected public `sf47_budget_model` component includes the complete workspace source. Its browser-assets manifest registers both new browser modules; the optional receiving callbacks and both guides travel with that same component.

Session schema: `stellar-forge.portfolio-working-session.v1`. Portable copy schema: `stellar-forge.portfolio-working-copy.v1`. Collection schema: `stellar-forge.portfolio-working-copies.v1`. Local storage records preserve original opaque native requests; they never dispatch requests themselves.

This public edition preserves the existing owner-key host and exact recording actor; it does not import Merchant-only staff, currency or Installation-phase features. Browser storage is scoped to its original origin and local case. Close access and use a separate browser profile when changing operators on a shared device. All original sources are downloaded as bytes rather than executed inline.
