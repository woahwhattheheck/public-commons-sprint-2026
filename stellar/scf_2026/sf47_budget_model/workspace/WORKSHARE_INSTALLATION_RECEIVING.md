# Complete original Workshare Installation receiving

This programme receives the saved Freeform association Workshare into the maintained SCF Customer Installation application. It opens the complete original grant case, attaches the full commercial case and saved plan, saves two useful Installation editions, exports their entire operating case, and reopens both editions in an independent workspace through the original MCP and Python CLI.

## Original application

Use the full repository `woahwhattheheck/tjlabs-stellar-merchant-workspace` at commit `e79373952c93d09168072014f670f32b18fdea2e`, which includes merged PR203. Retain the entire `stellar/scf_2026/sf47_budget_model` and `stellar-forge/mcp-merchant-operator` source directories. The maintained launcher checks its original mounted application files before starting.

Place these two complete entrypoints beside the existing `workspace/cli.py`:

- `stellar/scf_2026/sf47_budget_model/workspace/workshare-installation-inputs.py`
- `stellar/scf_2026/sf47_budget_model/workspace/workshare-installation-receiving.mjs`

Use native Node.js and Python 3. The receiver calls the original local application and requires its normal local process and loopback socket support. It adds no external package dependency.

## Run the receiving operation

Use a private persistent working directory and absolute paths. The same directory and input paths recover the original operation after interruption.

```bash
node /absolute/repository/stellar/scf_2026/sf47_budget_model/workspace/workshare-installation-receiving.mjs \
  --work /absolute/work/scf-workshare-installation-20261012 \
  --case /absolute/inputs/SCF_Operating_Case_with_Freeform_Event_Timing_20261012.zip \
  --commercial-case /absolute/inputs/Freeform_Complete_Case_and_Operating_Handover_20261012.zip \
  --python /absolute/python3 \
  --scenario /absolute/repository/stellar/scf_2026/sf47_budget_model/sf10_current_candidate.json
```

The full grant case retains its saved plan content `97bb2797558058e1b4c4f4f386bffc6241f246661656dfcd92d9f6e395f7bb84`, all original records, eight deployments and eight purchases. The scenario argument supplies the original application's normal boot selection; the imported case retains its own saved plan.

## Work performed

The input preparer reads the actual saved Workshare plan and explicitly matches each phase to its original estimate-role name. It preserves the original allocation: intake 8 hours, mapping 12, native integration 14, operations 14, handover 10 and support 6. This is the original 64-hour upper estimate, with the source's 52-hour sensitivity retained. The original support phase remains fourteen calendar days after acceptance.

The first Installation edition contains the complete original proposed $8,800 Workshare, two $4,400 milestones, original scope and acceptance conditions, phase dependencies and effort, full task, source cohort and field meaning, receiving application, recovery and support instructions. The six commercial phases retain stable acceptance identities alongside the original funded-plan criteria. The complete commercial source remains attached, including the original thirty-member case and application archive.

The second edition completes the onward source refresh and operator recovery instructions. Both editions remain available after export and independent receiving. The receiver downloads all original commercial attachments from the receiving workspace and verifies their complete bytes. It also reopens and exports the second edition through the original Python CLI.

The installation remains at its original planned commissioning stage. Complete source captures, native customer configuration and customer acceptance can be entered through the existing Installation desk as the original work proceeds.
