# Delivery risks browser receiving

This companion operates the complete installed Delivery risks desk in the same
WALKTHROUGH case produced by operations_risks_walkthrough.py. It uses the real
staff forms, original navigation, native preview, original request reconciliation,
case history and download controls. The integrated execution owner starts and
closes the original managed Operations host. This module starts one selected
Chromium process and owns that browser through actual process closure.

Files:
- operations_risks_browser.mjs
- RISK_REGISTER_BROWSER.md
- risk-browser.example.json

## One selected case and source

Run the native HTTP course first. Keep its risk-course-browser.json and
risk-course-source-selection.json unchanged. The browser handover contains the
original case, two independently received cases, both immutable risk editions,
the original risk/issue/action/source identities, the two exact native commands,
their receipts, preview hashes and saved sources. It also binds the actual
origin, installation and enrolled staff IDs.

The final complete source manifest must select every actual installed member,
including the original operations_walkthrough.py helper, the new native course,
this browser module and both guides. Paths are repository relative; every row
contains path, bytes, sha256 and the original mode. The native and browser phases
verify the same whole source. Add all receiving files before freezing that
manifest and executing the native course. Do not append browser source to an
already-executed native source selection.

The input has schema stellar-forge.sf47-delivery-risks-browser.v1.input:
- repositoryRoot: absolute actual repository root;
- sourceManifest: absolute path/bytes/sha256 of that exact complete manifest;
- native: absolute path/bytes/sha256 of risk-course-browser.json;
- outputDirectory: a separate private browser directory beneath an existing
  private parent;
- ownerKeyFile: the original private installation access.key, supplied separately;
- node: exact canonical executable path/bytes/sha256 selected by the parent;
- browser: playwrightModule, playwrightSha256, executablePath and executableSha256;
- parentGuard: path, fd, device and inode of the original held course flock.

The example supplies the shape only. Replace every illustrative path, size, hash
and guard identity with the actual original descriptors. The four staff codes
are read only from the native handover's .private/risk-staff-codes.json relative
to its original output directory. No credential is placed in a URL, source file,
shareable observation or result.

## Original guard and host ownership

The parent keeps its existing original course flock and passes a duplicated
descriptor to this child. The child's parentGuard.fd must be at least 3 and
present in the parent's pass_fds. Device/inode are decimal strings. The module
compares its actual descriptor with the original nonsymlink path and those
identities, retains it through browser drain, and closes only its own duplicate.
It never calls flock LOCK_UN, unlinks the lock, creates another domain host or
replaces the native case.

The parent must await the actual Node child close, including its inherited
descriptor, before host shutdown, cold reopen, case packaging or another
continuation. The runtime descriptor number is excluded from stable selection;
path/device/inode remain bound, so the same parent operation can reopen with a
different duplicated descriptor number.

The actual authenticated browser staff session must match the handover's
installationId and original enrolled staff ID. Origin is the native loopback
origin. A changed host port or source selection is not silently adopted into an
existing browser journal.

## Invocation

Using the selected Node, invoke:

    node operations_risks_browser.mjs run --input /absolute/private/browser-input.json

The CLI writes one final JSON result only after its owners close. Keep stdout
and stderr as original per-attempt private files in the parent execution record.
Signals stop new browser work and close the same retained contexts to interrupt
outstanding browser reads; those actual close promises are then drained. Accepted exact commands stay retained for
reconciliation. The companion never sends SIGKILL.

Read-only completed inspection:

    node operations_risks_browser.mjs inspect --input /absolute/private/browser-input.json

This checks the complete source, native input, fixed result, every manifested
file, closure and export descriptors. It creates no browser or host. It returns
null if there is no completed result. Do not describe a null result as a native
failure or as permission to launch a competing invocation.

The exported programmatic entrypoints are:
- receiveRiskBrowser(input): complete same-case run or local completed recovery;
- inspectRiskBrowser(input): read-only complete local inspection.

## Complete operator journey

The finance and reviewer logins use the original staff forms. Each opens the
original case, reads its first historical edition and its source-change
explanation, opens the second edition, follows original entry history and
previews a native seed. The real save control must remain disabled for both
reader roles.

The contributor signs in to the original contributor desk, selects the same
assigned case and downloads its original records. The operator link remains
hidden. No synthetic contributor permission or risk writer is introduced.

The lead opens the same original case and seeds the second edition through the
desk. It records an explicit assessment/review note on the retained risk, keeps
all original entry/action/source/package IDs, reviews the complete native
preview and saves one third edition through the original Save reviewed edition
control. The third edition must supersede the original second edition. Before its first
save, the case must still be at the native handover's exact original version.

Before that browser command is allowed onto the network, its full original
body and actual desk sessionStorage are durably retained. The companion admits
only this one same-case risk-register.save command. Its request ID, actor,
expected version, normalized document, expectedPreviewSha256 and note are
unchanged on recovery. Other domain mutation routes are rejected. Login,
logout and the original risk seed/preview/request reads remain native.

The lead then reopens the accepted third edition, downloads the complete native
case ZIP, downloads and SHA-verifies the original attached source, reads all
three editions in history, and downloads the original desk/request receipts.
An installation-owner view separately opens both independently received cases
and downloads their complete second-edition case ZIPs. Neither received case
gets a new domain edition.

The browser result is an operator observation. Native scientific, commercial,
funding and cash outcomes remain those of the original product. The course
records no monetary risk exposure and changes no Forecast or task outcome.

## Interrupted request and download recovery

Reuse the same input and outputDirectory. SELECTION.json binds the native
handover, complete installed sources, Node/Playwright/Chromium, private credential
hashes, original guard identity and installation. Attempt ID and inherited FD
number do not change that stable selection.

risk-browser-journal.json retains completed role steps, the exact third command
and the current full observation inventory on every durable journal write.
Before dispatch, .private/third-admission.json publishes one immutable record
containing the actual full command and its actual pending UI desk, bound to the
selection hash. The public command, private desk and journal are then published.
If any later publication is interrupted, reopening reconciles that admission,
the original command artifact, all retained third-edition observations and the
saved desk's pending/accepted/receipt state before choosing a workflow branch.
It verifies the original staff, case version, predecessor, command and known
result; older desk publication cannot trigger a new seed or request ID.
On reopen the original UI receives that unchanged pending desk, reads its native outcome and,
only when the original table reports absence, offers the original same-command
retry. A changed command, predecessor or accepted result is a conflict; the
companion does not make a replacement key.

A known native response is retained before advancing the role checkpoint.
Response observations have content-addressed names so a later successful
same-command recovery does not overwrite an earlier rejected/uncertain attempt.
The complete request and immutable saved review are checked against the native
preview hash before the lead step is accepted.

Each browser download is saved to its owned attempt temporary. Its complete
bytes/hash and source role are frozen in a private download receipt before the
final create-only file is published. Reentry can finish that same retained
download from its original complete temporary or verify its final bytes. It
does not regenerate an export merely because a later journal publication was
interrupted.

Profiles and credentials are private. The companion saves context storage and
the original risk desk through its own private atomic files. A prior live
Chromium process or a process still using an original attempt profile prevents
a new browser launch. Its original execution owner must finish that invocation.

## Browser and output closure

The companion launches the exact selected Chromium with a private per-attempt
user-data directory and a loopback ephemeral CDP endpoint. Playwright attaches
to that original process. The direct child, its actual start/namespace identity,
observed descendants and exact-profile processes, contexts, requests, response bodies, downloads and log
file handles remain owned until closure.

Normal role transitions wait for the original desk and request bodies, preserve
the original local desk, use the native sign-out control and close that actor's
context. Failure cleanup stops admission, cancels remaining downloads, closes
the same contexts/connection, terminates the same retained Chromium owner with
SIGTERM if needed, waits for actual child close and drains retained descendants. It performs a
process/profile census before terminating the root and repeats that exact
census through final closure, including after failed browser acquisition.
Proc-view PIDs and the child object's native PID are separately retained. The
module derives the caller's actual /proc/self namespace and NSpid depth, matches
the child by native PID, parent, executable and exact private profile, and maps
signals through the caller's namespace only after a fresh identity check. An
unrelated reused PID is never signalled. Failed file or browser closure stays
with the same owner and original guard until it completes.

No screenshot is a deliverable in this course. It retains original textual UI
observations, native documents/history, original command/receipt files and full
download bytes.

After every role has completed, the full result candidate is create-only. All
selected original files are read back before closure. BROWSER_CLOSED.json is
published below the actual attempt only after this child's original guard
duplicate has closed; it records the actual owner closure and candidate binding.
A raw descriptor close exception is retained as an uncertain close, never
retried against a potentially reused descriptor number. That invocation reports
CLOSE_UNCERTAIN with guard:false and cannot publish a completed result; the
parent retains its own original flock through the actual child exit.

If result publication fails after closure, run reuses the immutable candidate
and its actual completed closure locally. If all business steps were retained
but the final closure/publication was interrupted, it first establishes that no
prior selected browser remains, then finishes a fresh local-only closure. It
does not create another browser merely to package those completed steps.

A completed run reopened locally retains its original result/attempt and
publishes a separate current invocation closure. The original completed result
is never rewritten to appear to be a new browser observation.

## Result and parent receiving

Fixed result: risk-browser-result.json.

Schema stellar-forge.sf47-delivery-risks-browser.v1.result, status COMPLETED:
- selectionSha256: canonical sorted-key UTF-8 SELECTION.json plus one LF;
- operationId, installationId and all three original case IDs;
- firstReviewId, secondReviewId, thirdReviewId and thirdRequestId;
- original native and complete source descriptors;
- complete steps for finance, reviewer, contributor, lead and received;
- files: output-relative path/bytes/sha256 for every shareable observation and
  original download;
- exports: absolute path/bytes/sha256 for the three actual native case ZIPs;
- closure: output-relative complete BROWSER_CLOSED.json descriptor;
- attemptId: the actual accepted closure invocation.

The parent validates every files row and closure after the Node process exits.
It must run the unchanged operations_risks_walkthrough.verified_archive on every
returned ZIP, verify the complete native manifest and selected risk document,
and compare the two received editions with the original immutable second
edition. The lead ZIP must carry the thirdReviewId/thirdRequestId and retain both
earlier reviews. Browser-side SHA checks alone are not a claim that ZIP member
content has passed the native archive validator.

Keep risk-browser-journal.json, SELECTION.json credential hashes, .private/,
Chromium profiles and raw attempt stdout/stderr private with the existing
operation. Share only the declared files/result/closure through the original
case delivery, after the integrated parent completes native ZIP validation and
its actual host cold reopen. The browser module itself starts or stops no host.

Source is prepared until Engineer's original integrated execution returns the
actual outputs. Parsing and source review are not browser execution receipts.


## Retained execution correction after native memory exhaustion

Runtime and installed-source identity reads now hash the entire file in 128 KiB chunks. They still verify exact original byte length, SHA-256, permissions, device/inode and nanosecond modification/change metadata against the reopened path. JSON and other actual content consumers retain their complete bounded bytes. The Node and Chromium executables are never retained as raw buffers merely to check their identities.

The ordinary selected-source path and stable browser SELECTION.json are unchanged. A same-case correction can instead be supplied through optional input.executionContinuation={path,bytes,sha256}. Its document schema is stellar-forge.sf47-risk-execution-continuation.v1 and binds operationId, original sourceManifest/executionInput/executionSelection/executionJournal/browserSelection/browserJournal descriptors, both original/current Python and Node module descriptors plus repositoryPath, a reason, and sourcePublication provenance.

The original parent first validates and retains the exact sidecar and prior journals below the parent of outputDirectory at execution-continuations/<sidecar SHA>/. It publishes execution-continuation.json, prior-browser-journal.json, prior-execution-journal.json and finally ADOPTED.json. The adoption value is {schema:'stellar-forge.sf47-risk-execution-continuation-adopted.v1',executionContinuation:{reference,document}}. No child starts before that publication closes.

The browser validates every unchanged original repository member, the exact two corrected modules, both prior journal snapshots and the parent adoption. Only corrections.node.current may substitute for its own executing module; the original module remains byte-exact in the selected repository. The entire stable browser selection remains identical. The explicit executionContinuation record is added separately to the journal, candidate, result and each closure. A later reopen must name the same record. No host, command, request or source history is replaced, and the original inherited guard stays owned through the existing process/reader/download drain.

The original interrupted browser journal may be adopted only when it still matches the full original journal descriptor retained by the parent. Subsequent resumed journals carry the same continuation. A completed result or closure from a different continuation cannot be reused. Keep the original installed source and complete corrected source publication with the saved case's provenance; do not rewrite its original source manifest to disguise this execution correction.

### Parent execution operation and native request prefix

The explicit continuation operationId belongs to the original RISK_EXECUTION_INPUT.json. EXECUTION_SELECTION.json must remain exactly {schema:'stellar-forge.sf47-risk-execution.v1', config:<that full original input>}. The native course generates its own request prefix and uses it as its browser handover operationId; that separate original value remains bound by the unchanged native descriptor and complete browser SELECTION.json. No identity is substituted or renamed.
