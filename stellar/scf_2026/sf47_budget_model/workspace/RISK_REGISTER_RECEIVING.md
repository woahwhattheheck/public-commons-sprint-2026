## Execute the complete case

From the workspace directory, pass actual paths and the original selected plan:

    python operations_risks_walkthrough.py \
      --url "$RISK_ORIGINAL_ORIGIN" \
      --access-key-file "$RISK_ORIGINAL_ACCESS_KEY" \
      --plan "$RISK_ORIGINAL_PLAN_ID" \
      --source-manifest "$RISK_COMPLETE_SOURCE_MANIFEST" \
      --output "$RISK_ORIGINAL_OUTPUT"

These are task-specific variables; the execution owner sets them from its real
original launch and source receipt. No key is placed in a URL or printed.

The procedure clones the selected original plan into an explicitly WALKTHROUGH
case, retains a labelled exercise source and original contributor, records an
entered risk and observed issue, saves their first edition, reconciles and replays
the same accepted command, updates the linked contributor, saves the complete
successor, and checks original item/action history. It downloads the native full
ZIP, validates every manifest member, imports it through the original HTTP
importer, independently receives all immutable reviews and attachment bytes, and
exports onward from the received case.

One additional receive exercises the actual corrected ordering defect: the full
valid archive retains reviews in reverse array order, while the highest native
saved version must remain the current edition. Both original and reordered
receiving use their own retained original request identities.

Named, case-scoped lead, finance, reviewer and contributor profiles use the real
staff enrollment/login APIs. The course exercises reader previews, exact-request
reconciliation, outside-case access and the original save permission boundaries.
The browser companion uses the same enrolled lead to make an explicit third
edition through the actual UI.

## Resume and reopen

Every write body and request ID is saved atomically before dispatch. Each saved
risk command is first reconciled by the original risk-register-request API.
Creation, enrollment and receiving reuse the original provider's idempotency.
An accepted staff rotation whose one-time code was lost is reconciled from its
original request, then recovered with one new rotation at the actual current
member revision; all earlier rotation requests and results remain retained.
The two original saved risk command files are emitted with their exact receipts,
preview identity and source selection.

Run the same command again after interruption. Once it has a completed result,
the command repairs all missing final files from the same accepted journal and
performs fresh reads of the original and received cases. Browser input is first
frozen atomically in that journal, so publication recovery preserves its original
case version, source/preview identities and complete commands.

For a fresh-process verification, append --verify. For a complete cold reopen,
the execution owner stops and reopens its original managed host using that
launch's recorded PID/nonce and preserved workspace, then invokes --verify with
the same selected source, plan and output. Keep the actual host close/reopen
receipts with the resulting risk-course-reopen.json. A new Python process alone
does not establish that the server was restarted.

The original two editions remain immutable. The browser may save a later
successor in the original case. Verification allows this later head while
checking that both original editions and their original history remain intact.
The two independently received cases stay at their selected second edition.

## Browser companion contract

risk-course-browser.json contains:
- origin and installationId from the actual authenticated installed server;
- originalCaseId, receivedCaseId and reorderedReceivedCaseId;
- planId, both original review IDs, item/action/source IDs and source SHA-256;
- originalCaseVersion and the successor's asOfDate;
- originalCommands, each with full retained command, command path/hash, exact
  native receipt, previewSha256 and saved source identity;
- staff profile IDs and a relative privateStaffCodes path;
- hostContract identifying the original launch owner and close operation.

The browser verifies the actual installation/staff identity through
/api/staff/session and operates the same original case. It may use the original
private owner key supplied separately by the execution owner or the named staff
credentials in .private/risk-staff-codes.json. The independent browser exercise
opens both editions and source explanations, checks the named staff views,
records a third lead-reviewed edition through actual UI controls, downloads the
complete selected ZIP, and returns its actual source/result/download paths.
Keep the original cases and first two editions; use one successor for the edit.

The course itself starts and stops no host or browser. The execution owner
retains its original complete host lifetime and the sole integrated launch.
