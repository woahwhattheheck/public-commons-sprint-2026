# Property commissioning: Propply / RentCheck

This workflow takes the complete original customer scope into the existing Customer installations desk, retains a whole property selection, and prepares the customer's actual observations for the original Installation Return. The useful task is a selected NYC portfolio review: receive a dated source report, review a later edition, join actual property and template identities, operate an agreed inspection/report route, and reopen the complete result.

The maintained Property application owns source acquisition, inspection issuance and reconciliation, report retention, optional merchant resource publication, and the buyer's original request and receipt. This component supplies the customer workorder, structured selection, complete receiving review and operator handover around that application. The original SF47 operating case remains the native writer.

## 3. Attach the frozen selection, then read the current seed

Source attachments advance the operating case version. The selection's own file cannot be rewritten after every attachment merely to echo that new version: doing so would change the very source being attached. This workflow therefore retains two related facts:

- The selection file keeps its original complete case/plan observation and exact file digest.
- The next native action uses a freshly read seed and complete case catalogue at the same current version.

The compiler compares all stable source fields, including case, mode and pinned plan identity, and permits only a nondecreasing case version. Another case or changed plan requires a deliberate successor selection. It also checks the actual attached file metadata against the current case catalogue.

Follow this order:

1. Attach each complete supporting file through the original Sources action. Verify its actual metadata and retain its returned nativeSourceId in the editable selection.
2. Finish the complete selection, including the actual selecting operator/time. Retain the exact file that will be reviewed.
3. Attach that exact full selection JSON to the original case. Its self-reference is resolved by byte count and full SHA-256 from the actual catalogue; no circular source ID is inserted into the selection.
4. Read the current complete case and a fresh original Workshare/Installation seed at that same version.
5. Prepare the native document from those current readbacks and the unchanged selected file.

For an exact source attachment, the original typed SDK uses attach(caseId, bytes, body), with Buffer bytes and the original expectedVersion, requestId, actor, note, filename, kind, mediaType, sourceUrl and observedAt fields. Its JSON response is in .value. Preserve the original complete request and actual result; do not generate another request simply because a response was lost.

The complete case can be read through the original show command:

~~~sh
python3 workspace/cli.py operations --workspace "$SCF_WORKSPACE" \
  show --case "$SCF_CASE" \
  --output "$PRIVATE_INPUTS/current-case.json"
~~~

Use the current source IDs to read the new Workshare seed as in section 1. Then:
