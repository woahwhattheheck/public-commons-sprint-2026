# Lutra vector and QGIS commissioning

The lutra-qgis profile carries the original complete migration Workshare into the maintained Customer installations product. It joins the actual approved source, explicit mappings, native data, two QGIS projects, selected map publications, one corrected edition and independent operating handover.

The original proposal is USD 8,000 for 60 planned hours over twelve business days after the agreed source, scope, reviewers and native environment are selected. Its five commercial phases remain in the original Workshare. This seven-stage technical programme supplies the complete operating route around those phases.

## Original source and commercial programme

Select the complete original commissioning input and its matching receiving packet from the existing private Lutra customer case. Retain that case's Workshare identifier, canonical plan digest, source filename, complete-file identity and private source location together in the same case. Use those exact source and commercial bindings when continuing the Installation. The migration lead and named receiving operator use the original case's authorized source access.

| Commercial phase | Planned effort | Original delivery window | Complete result |
| --- | ---: | --- | --- |
| Source and destination agreement | 8 hours | Days 1–2 | Approved complete inventory, sample sizing, explicit mappings, target versions, two map definitions and receiving expectations |
| Baseline mappings and native vector outputs | 20 hours | Days 3–6 | Complete original records, reviewed mapping and native GeoPackage/selected Shapefile outputs with PostGIS import handover |
| Two QGIS projects and editable cartography | 16 hours | Days 5–9 | Both native projects, styles/resources, editable layouts, selected QGZ/QPT/PDF/PNG and consolidated baseline review |
| Corrected edition and independent receiving | 10 hours | Days 9–11 | One corrected-source capture, explicit successor, complete native outputs/maps/publications and independent receiving |
| Complete editable operating handover | 6 hours | Day 12 | Full source/license inventory, editable mapping and XLSX workbook, configured workspace, outputs, guides, correction history and operator sessions |

The original offer covers up to ten vector layers, two QGIS projects, one baseline and one corrected-source set, two consolidated reviews and two remote operator sessions of up to one hour each. The proposed milestones are USD 2,400 at agreed scope/start, USD 4,000 at working baseline and USD 1,600 at complete receiving/handover, payable within fourteen calendar days.

The phases overlap where the original schedule says they do. Retain their actual assigned owners and effort in the existing Workshare/Portfolio; commercial or grant funding remains assigned once per actual hour. Third-party licenses, infrastructure, travel and source-system access charges use their separately agreed terms. Additional layers, projects, source systems/editions, formats or managed operation continue the original change process.

## 1. Agree the complete original source and destination

Retain every selected source file and its original bytes/hash, source-selection inventory and actual local source root. Select the baseline and corrected-source specifications from the customer's original approved exports.

The agreed destination includes the complete layer/field inventory, feature/business keys, required values and null policy, geometry policy, observed or assigned source CRS, transformation, target CRS and supported native representations. A complete key review uses the destination representation, including cases where different original values become equal after conversion.

Select two full project definitions and their actual styles, fonts and local resources. Retain required page dimensions, orientation, resolution, layer order, map extents, attribution, legend and scale bar. The original scope is sized against the actual sample and complete data volume.

## 3. Receive source, review mapping and deliver native baseline data

Receive the complete original source-selection JSON and source root through Sources. Preserve the saved complete capture; browse all required record/issue pages using their original continuation offsets.

Draft and review the whole mapping. Keep native scalar fields, exact JSON text and retained references as explicit choices, including complete keys, null/required-value and geometry/CRS decisions. Retain the selected output formats and destination tables/schema.

Deliver the separate editable XLSX mapping workbook named in the original Workshare. It describes the same reviewed source/plan/edition and complete layer, field, key, null, geometry and CRS choices. Keep that workbook with its canonical editable mapping JSON and original review; workbook edits receive the same explicit mapping review before a native successor build.

Build the selected valid plan through the original vector engine. Reopen the actual GeoPackage and selected supported Shapefile outputs, including their full required sidecars, and retain native layer/feature/field/geometry/CRS results. The PostGIS import handover identifies the complete retained native data and agreed loading contract for the customer's selected production workflow.

## 4. Deliver both QGIS projects and their publications

Bind the native output tables into both selected projects with relative source paths and the original layer/resource decisions. Build and reopen the actual QGZ projects through the installed QGIS engine.

Save and review the complete publication specifications. Retain their QGZ, QPT, PDF, PNG, complete selected plan and native output/reopen identities. The image preview and downloaded file belong to the same retained publication.

Complete the original consolidated baseline review and first operator session. Record the exact reviewed source, plan, edition, project and publication identities in the existing operation.

## 5. Receive the corrected edition

Capture the one included corrected-source export separately. Compare complete original capture IDs and inspect affected features, fields, keys and geometries.

Draft from the retained predecessor plan, resolve real additions/removals and changed project choices, review and build the successor. Update the corresponding mapping workbook, both projects and the selected publications. Preserve baseline and corrected outputs, original issue/review decisions and the correction reason.

A source correction and a repeated use have different operational results: the correction builds a reviewed successor edition; reopening or downloading an existing result retains that original edition. The commercial fee and any separately priced Stellar resource acquisitions keep their own original records.

## 6. Receive the whole workspace independently

Export the complete original workspace at its observed revision to the external handover directory. Retain the full ZIP, byte count, SHA-256, package-manifest hash, workspace ID and revision.

The archive carries original inputs, full capture rows, mapping and issue decisions, native editions, maps/styles/resources, publications, request/event history and the selected native application source. A merchant transfer also retains migration-export.json and its complete handover.zip.

Use the original receiver and a separate selected receiving location. Its required native reopen operates the delivered projects and publications. Open that received directory in Applications → GIS migration with the receiving host's actual environments, inspect the original history and export the received workspace onward.

The maintained [receiving guide](../../../../products/gis-migration/RECEIVING.md) supplies complete commands for inspect-export, download, inspect-received, receive-local, independent reopening and onward export.
