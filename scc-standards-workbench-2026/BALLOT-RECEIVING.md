## Whole operator course

The native application performs every mutation through its existing request, revision and source contracts. The course retains each request before dispatch, and retains the full original result. A resumed native request uses those exact saved bytes and IDs.

1. Open the complete authored seed and save its original full private archive. Preserve every original source file, development event, clause, case, procedure, member, funding and planning record.
2. Open the actual empty ballot desk and its loading view. Freeze the original bilingual edition, record the expressly authored steering consultation and open a ballot on the existing source-specific PAS profile and seven-member roster.
3. Freeze each member’s own complete bilingual packet through the secretariat interface. The first packet save deliberately loses its observed response after the real application commits. Reload the same operator page and recover its complete retained original request.
4. Download and open every real member ZIP. Read the frozen public edition and original cases, enter the authored member response, save the full portable draft, close that recipient context, open a fresh one and reopen the saved draft.
5. Confirm and download the original response JSON and readable HTML. Receive the exact JSON through the secretariat’s actual file/preview/retain controls. Compare its original bytes and complete declaration, then explicitly verify and adopt it into the existing native vote.
6. Continue through all seven members: four affirmative, one justified negative, one justified abstention and one explicitly blank response. The selected original procedure calculates their meaning. The course does not replace the original calculation or change denominators.
7. Record the first negative response’s review and notification. The original member then opens the exact first return, prepares an explicit correction, saves/reopens its draft and downloads the next complete return. It keeps the same response ID, advances one revision and names the complete predecessor digest.
8. Retain and adopt that correction. Confirm the original vote ID survives, both original files and adoption snapshots remain, and the old response’s resolution and notification fields are cleared for review. An exact duplicate retains the same return and vote.
9. Review the corrected negative through the original vote editor. Use the original authority closure and independent procedural review controls, then prepare the corresponding original publication record.
10. Download the complete private decision handover, bilingual publication and full editable project. Close the producer browser context and server. Restore into a separate receiving workspace with the unchanged native CLI, open it in a fresh browser context and re-export the whole project.
11. Compare every complete project, development-history, request-ledger and retained-original member after receiving. The original seven-member vote and corrected response chain remain usable in the restored secretariat.
12. Open the actual outgoing HTML attachments at desktop and narrow widths, render every publication PDF page, and return those exact outputs to the producing owner for visual inspection and any needed product correction.

The ballot dates, names, declarations, review notices and authority entries are explicitly authored inputs in the existing authored exercise. The original public municipal rows and procedure sources keep their own factual meanings and bytes. This course does not call a sender or alter another project.

## Continue an interrupted operation

Reuse the same configuration, source, workspace and output. The progress journal stores full completed stage results. The request directory stores each original operation envelope and result, including requests whose native commit completed before the outer stage checkpoint. Reopening uses the original transaction replay; it does not create a second member, packet, vote, closure or publication.

Offline draft, original return, corrected return and readable files are create-only complete files. If a downloaded file already exists, the course reopens that exact file before continuing the recipient’s next action. Archives are fully read, checked against their original complete manifest and extracted with safe relative paths and create-only publication.

If a concrete defect requires an updated source edition after the original invocation has ended, preserve that prior edition. Keep the same source location and supply these explicit continuation fields:

The next invocation records the previous and current whole-tree identity. Previously completed native mutations and original return files remain retained. Reopen the affected exact outgoing application/attachment in the updated edition, and continue the relevant original step. The existing consultation programme retains its own operation and source history.

Each dispatched UI operation observes its actual visible validation/storage error, page crash/close and native server exit. Its default two-minute operation timeout can be selected with `operation_timeout_ms` for the actual host. A click that never sends a request returns the concrete operating error instead of holding the whole course indefinitely; an uncertain committed request retains its exact envelope and result for the original replay.

A failure record names the actual active stage and native/browser error. Resolve that concrete input, dependency or product defect on the same receiving worker. A missing runtime dependency is a host selection problem; keep the complete source, workspace and requests together when routing to the existing equipped host.
